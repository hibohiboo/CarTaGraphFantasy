ドキュメントの古い記述（例：解消済みの「解消候補」、実態と違う説明）に気づいたら、スコープ外として報告だけで止めず、その場でさっと直す。後にする理由がある場合だけ、止めて理由を伝える。

**Why:** 2026-10-03、PR #12 で architecture.md「境界」に残っていた解消済みの `components/index.ts` の記述を「今回の範囲外」として報告だけにしたところ、ユーザーから「気づいたときにさっと直そう。後にする理由も浮かばない。理由があれば止めて」と言われた。

**How to apply:** 直す前に実態を確かめる（ファイルの有無など）。作業中のブランチに含めて直し、報告では「直した」と伝える。仕様の意味が変わるもの・人間の判断が要るもの（ルールの新設、未解決論点）は従来どおり止めて聞く。[[dev-process-structure]]
