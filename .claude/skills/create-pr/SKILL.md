# create-pr（PR 本文を構造化して投稿する）

## 1. 差分と経緯を集める

- `git diff main...HEAD` で変更の全体を把握する
- 対応するプラン（`docs/plans/`）と、実装後の AI レビュー結果（P0〜P2 の整理）を読む

## 2. 本文を下書きする

次の見出しで、レビューアーが上から読めば理解できる順に書く。

- **課題**：何を解決する PR か（背景と、対応するプラン・仕様ページ・未解決論点）
- **解決策**：どう変えたか。設計判断とトレードオフを1〜2行で
- **テスト**：追加・変更したテストの内容（型検査・テスト・docsビルドは `.githooks/pre-push` とCIが自動で確認済みなので、ここで手動で再実行して結果を貼り付ける必要はない）
- **レビュー観点**：とくに見てほしい箇所、影響範囲、未対応事項、AI レビューで「要確認」に分けた点

下書きは対応するプランファイルの末尾に「PR 下書き」節として追記し、投稿前に人間の承認を得る（プランがない小さな変更はセッション内で見せて承認を得る）。

## 3. 投稿する

承認後、`gh pr create` で本文を渡して作成する。本文の末尾には `🤖 Generated with [Claude Code](https://claude.com/claude-code)` を付ける。CI（型検査・テスト・docs ビルド）の結果が出てから人間のレビューへ回す。
