# Grilling

出典: [mattpocock/skills](https://github.com/mattpocock/skills)(`skills/productivity/grilling/SKILL.md`)を
2026-09-12に移植。汎用の質問インタビュー手順であり、本プロジェクト固有の仕様には依存しない
(内容を変えるときは出典との差分を意識する)。

## 手順

ユーザーの考えを、共通理解に達するまで執拗にインタビューする。決定事項を
**デザインツリー**として捉える: 個々の決定は、それに依存する下位の決定へ枝分かれする。

ツリーは**ラウンド**単位で進める。**フロンティア**とは、前提となる決定が
すでに確定している質問群 ── まだ聞いていない答えを推測せずに**今**尋ねられる
質問のことである。フロンティア全体を1ラウンドでまとめて尋ねる: 質問に番号を振り、
それぞれに推奨回答を添える。そのうえでユーザーの回答を待ってから次のラウンドに進む。

ラウンドは次の形式で書く:

```
❓ **Q1** - **<質問タイトル>**: <質問本文。複数段落・複数の選択肢を含んでよい>

➡️ <推奨回答>

---

❓ **Q2** - **<質問タイトル>**: <質問本文。複数段落・複数の選択肢を含んでよい>

➡️ <推奨回答>
```

各ラウンドでユーザーの回答がツリーを組み替える: 確定した決定がフロンティアを
外側へ押し広げ、その決定に依存していた質問の封鎖を解く。フロンティアを再計算し、
次のラウンドを尋ねる。今ラウンドでまだ開いている別の質問に回答が依存する質問は、
今ラウンドではなく**後のラウンド**に回す。

**事実確認は自分の仕事であり、ユーザーの仕事ではない。** フロンティア上の質問が
環境の事実(ファイルシステム・ツール等)を必要とする場合、サブエージェントを使って
自分で調べる。自分で調べられることをユーザーに尋ねない。調査中でも止まらない:
実行中の調査は未確定の前提の一つに過ぎないので、その調査に依存する質問だけが
結果待ちになり、フロンティアの残りは今すぐ尋ねる。**決定そのものはユーザーのもの**
であり、各決定はユーザーに委ね、回答を待つ。

セッションが終わるのは、フロンティアが空になったとき ── デザインツリーのすべての枝を
訪れ、何も暗黙の前提として残っていない状態になったときである。ユーザーが共通理解に
達したと確認するまで、それに基づいて行動しない。

## 本プロジェクトでの位置づけ

- 適用単位は開発サイクル（`docs/process/index.md`）の「1. プラン作成」。`dev-cycle`
  スキルから呼ぶ。ユーザーが「詰めて」「grillして」と言ったときは単独でも使う
- 仕様ページ（`docs/cartagraph/` 等）に書いてあることは尋ねず自分で読む。
  未解決論点（`docs/open-questions.md`）に関わる判断だけをユーザーに委ねる
- 質問が尽きた（フロンティアが空になった）ら、回答を
  `docs/plans/<日付>-<機能>.md` の8項目（概要・背景・詳細設計・テスト影響範囲・
  新規テストケース・実装順・コミット前テスト実行・スコープ外）へ落とし込む
- 依頼文サンプルは `docs/process/prompt-sample.md`「1. プランドキュメントの作成」
