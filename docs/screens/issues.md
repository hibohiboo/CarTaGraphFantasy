# 画面ごとの課題

画面を触って気になった点（見た目・導線・言葉・足りない操作）を、画面ごとに置く。画面の一覧と導線図は [画面一覧と導線](index.md)。

## 書き方

- **1課題1行** — ID・課題・状態・要望を書く。ID は画面の略号と通し番号（`HOME-1` など）で、消さずに使い続ける（プランや PR から ID で指す）
- **状態** — 未着手／対応中／完了／見送り。完了・見送りの行も消さずに残す（見送りは理由を課題の欄に書き足す）
- **要望との役割分担** — 課題は「画面で気になった点」。直すと決めたものは、まとめて1つの [要望（バックログ）](../backlog/index.md) にし、表の「要望」に要望ファイルへのリンクを書く。どのマイルストーンで直すか・進み具合は要望の側が持つ（ここには書かない）
- **既知の問題との役割分担** — 実装の不具合・技術上の負債は [既知の問題](../architecture/known-issues.md)。画面で見える不具合でも、原因がコードにあって直し方を決めるものは既知の問題に置き、ここからはリンクだけにする
- **決めないといけないこと** — 直し方を人間が決めるものは、要望の `decisions` に書く（ダッシュボードに出る）

2026-10-10 に、M1 の進み具合を触って確かめた PO の指摘から作った。
