## 採用済み

### 2026-10-27 不安定なユースケースの E2E は、直す要望へのリンク付きでスキップにし、外し忘れを検査で止める

`retries` を足さない方針はそのままに、たまに落ちてすぐに直せないユースケースの E2E を、宣言の `test.skip('題', { tag, annotation: { type: 'backlog', description: 'docs/backlog/<名前>.md' } }, fn)` でスキップにできるようにした（[テストのルール](../rules/testing.md)「不安定なテストのスキップ」）。スキップと直す要望の起票は、落ちた機能の PR の中では入れず、別のブランチで main へ早送りで入れる。`check-usecase-tags.mjs`（`docs:build`）が、注記の無いスキップ・実在しない要望・開いていない要望・`trace.usecases` に UC の無い要望・スキップを外した後の注記と抑制コメントの消し忘れ・smoke のスキップを止める。結果のページとトレースのページでは「全スキップ」「スキップ中」と出る（[テストレポート](../../architecture/test-report.md)）。2026-10-18 の人間レビュー（`retries` を足さない）で出た要望で、2026-10-26 に `gm-session.test.ts` が1度落ちた（`docs/plans/2026-10-27-P6-不安定なE2Eのスキップ.md`）。

採らなかった案：

- `retries` を足す（不安定なテストが CI を通り、ページでも「確認済」に見える）
- Biome の `noSkippedTests` の抑制コメントだけに任せる（抑制コメント1行で通り、直す要望へのつながりも、要望を閉じたときの外し忘れも止められない）
- Biome の GritQL プラグインで注記を必須にする（要望の状態と `trace` は見られず、検査が2か所に分かれる）
