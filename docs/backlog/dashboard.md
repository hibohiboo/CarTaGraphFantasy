# トップページのダッシュボード

AI との共同開発で、進み具合や判断待ちをどんな形で見られるのがよいかを試す。これもプロダクトと同じく、使いながら形を変えていく（[体制の進化](../process/evolution.md)）。

## 1版目で決めたこと（2026-09-27）

- トップページを丸ごとダッシュボードにし、サイトの紹介は上部の小さな導入に縮める
- **情報は手で書かず、ビルド時に集める**（SSOT）。要望は `docs/backlog/` の1要望1ファイルの先頭に状態を持たせる。判断待ちは、既知の問題・未解決論点・進化ログから集める
- 過去のプランも要望として登録し、完了したものは折りたたんで見せる
- PO 向け：「決めないといけないこと」（要望の判断待ち＋未解決論点の「次に詰める候補」）を先に、その次に要望の進み具合
- 開発者向け：要望ごとのサイクルと PR、既知の問題の判断待ち、進化ログの未評価の候補
- 状態は6種類（未着手／検討中／進行中／判断待ち／完了／見送り）
- 開発サイクルを回す AI が、プランの作成時とマージ時に要望ファイルを更新する
- 試行として始め、数サイクル使ってから見直す

## 2版目で決めたこと（2026-09-28）

1版目を見た人間から「ゴールとマイルストーン、それに対する進捗が分かりづらい。あと何をしたら第一段階が完成で、次に何をやり、最終的にどうなるかが見えない」と指摘を受けた。

- ダッシュボードの一番上に、ゴール → マイルストーンと要望の完了数 → いま取り組んでいるマイルストーンの「残っている要望」を置く
- ゴールとマイルストーンの定義は [ロードマップ](../roadmap.md) に1か所で持つ。進み具合はロードマップに書かず、要望ファイルの `milestone` と状態からダッシュボードが計算する（1ファイル1責務・SSOT。当初 AI は「定義・進捗・優先順位」を1ファイルに混ぜる案を出し、人間の指摘で分けた）
- 優先順位は「今・次・いつか」の節を作らず、マイルストーンの順番とその中の状態で表す
- 役割は仕様で決着している4ロール（システム製作者・シナリオ製作者・GM・PL）。tabifuda の役割分担のイメージに合わせた
- local-flow の完成の条件を、ロールごとの流れ（システム製作者・シナリオ製作者・GM・GM が PL を兼ねる・GM 不在）で書き、足りないものを local-flow の要望として5件登録した

## 目次を足した（2026-10-10）

人間の要望で、ダッシュボードの左に目次を置いた。全体・PO 向け・開発者向けの3つに分けてアコーディオンで開閉でき、各見出しに件数を添える。広い画面では本文の横に固定し、狭い画面では本文の上に置く。
