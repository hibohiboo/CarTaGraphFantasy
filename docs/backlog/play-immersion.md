# プレイ画面に没入できるようにする

[ロードマップ](../roadmap.md#ui-polish) ui-polish の完成の条件5に当たる。課題は [画面ごとの課題「プレイページ」](../screens/issues.md#プレイページ) の PLAY-1〜7。

- いまはセッションが始まった後も、アプリのヘッダと「キャラクターシート／セッション一覧／GM の画面へ」のリンクが出続ける
- **GM の画面への導線は、テストプレイ中だけ出す**（2026-10-10、人間の判断）。local-flow で GM の画面とプレイ画面を行き来できるようにしたのは、MSW では利用者が1人なので、人間の GM のセッションを1人で通して確かめるためだった。これは GM のホームから始めるテストプレイに移し（[GM のホーム](gm-home.md)）、テストプレイ中のプレイ画面にだけ GM の操作への切り替えを出す。ふつうのセッションで GM が自分の PC で遊ぶ（GMPC）のはかまわないが、プレイ画面に GM への導線は出さない（GM の画面は別のタブで開いておく）
- パーティのキャラクターカードと、プレイマットを出す場所が無い
- 「手札から1枚選んでプレイしよう」「戦闘をはじめよう」の案内が横に並んで邪魔になる（縦に並べるなら違和感が少ないかもしれない）
- 戦闘に負けたときの案内文が戦闘のログに重なり、「戦い方を決める」が戦闘の後も出たままになる。再挑戦を選んだときだけ出す、などにする（既知の問題 [自動戦闘の設定中に、プレイ画面のレイアウトが崩れる](../architecture/known-issues.md#自動戦闘の設定中にプレイ画面のレイアウトが崩れる) と同じところ）

## 決めたこと（2026-10-27、人間の判断）

- **方向は「カードを広げた卓」** — ローグライトのカードを出す気持ちよさと、カードワースの UI までカードになっているところに寄せる。試作を2案（卓に広げる／挿絵が主役）作って比べ、卓に広げる案にした。挿絵が主役の案は、場面ごとに挿絵が要り、シナリオを作り込む手間が大きい。卓に広げる案は札と卓だけで雰囲気が出て、カード感もより強い。技術は React のまま
- **2回に分ける** — 1回目は卓の形（ヘッダを消す・卓に刷ったプレイマット・パーティの札・栞・PLAY-1〜7）。2回目は札の動き（手札から場へ飛ぶ・山札から配る など）と、山札・使った札の置き場
- **抜ける操作は「栞」にまとめる** — 卓の右上の栞から、キャラクターシート・ホームへ戻る（セッションの状態は変えない）を開く
- **GM の画面への導線は、テストプレイができるまで栞の中に置く** — GM 本人が開いたときだけ出す。テストプレイができたら、テストプレイ中だけに絞る（上の 2026-10-10 の判断のとおり）
- **プレイマットは卓に刷ったゾーン** — 場の札（PL に見えているもの）は、卓に刷った「場」のゾーンに置く
- **戦闘に負けたら、結果を札で読ませてから再挑戦** — 結果と経過は「戦闘の記録」の札で出し、手札の場所の「もう一度挑む」を選んだときだけ戦い方を開く
