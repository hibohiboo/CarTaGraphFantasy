# 仮ルールの一覧をダッシュボードに出し、決めたら消す

2026-10-10、ルールとカードプールの JSON 管理（[ルールと基本カードプールを JSON でリポジトリ管理する](rules-json.md)）の人間レビューで出た要望。別のサイクルで行う。

- いま仮ルールは、仕様ページ（[自動戦闘（仮ルール）](../cartagraph/auto-combat.md)、[GM不在のソロの進行（仮ルール）](../cartagraph/solo-village.md) など）、[未解決論点](../open-questions.md)、`rules/character-creation.json` の注記、画面の「（仮ルール）」の表示に散らばっていて、どれだけ残っているかが一目で分からない
- ダッシュボードは要望（`docs/backlog/`）からビルド時に組み立てている（`docs/.vitepress/*.data.ts`）。仮ルールの一覧も同じ仕組みで集められる
- 決めて正式なルールにしたら一覧から消える動きにして、仮ルールを減らしていく

## 決めたこと・やったこと（2026-10-10）

- **一覧の正は1仮ルール1ファイル**（人間の判断）。[仮ルール](../provisional/index.md)（`docs/provisional/`）に要望と同じ形で置き、ダッシュボードの「PO：決めないといけないこと」に、何を決めれば消せるかと一緒に出す（`docs/.vitepress/provisional.data.ts`）
- 最初の5件：自動戦闘、GM不在のソロの進行、キャラクター作成の能力値の配分と HP、ロールごとのデッキ構成、シーンの「目的」「終了条件」。このうち4件は[未解決論点](../open-questions.md)にあった項目で、二重に持たないよう移した
- 仕様ページの「仮」の印と一覧の食い違い（載せ忘れ・消し忘れ）は、`pnpm docs:build` の `scripts/check-provisional.mjs` が止める
- 軽い変更（docs とビルドの補助だけ）なので、ライトルートで行った
