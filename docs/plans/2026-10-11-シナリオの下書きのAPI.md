# シナリオの下書きの API を分ける（C1：下書きと公開版）

要望：[シナリオの下書きの API を分ける](../backlog/scenario-draft-api.md)（[ロードマップ](../roadmap.md#backend-1on1) backend-1on1 の下ごしらえ）

状態：完了（PR #24）。D1〜D8 は2026-10-11に人間と確かめた。プランの AI レビュー（設計整合性・仕様整合性・運用・テスト網羅）の P0・P1 を反映した

## 1. 概要

シナリオを「公開版」（公開の検査を通ったもの。GM・PL が使う）と「下書き」（製作者の書きかけ。形だけを見る）に分ける。製作者の保存は下書きだけを変え、「シナリオ集へ公開／公開し直す」で下書きを公開のファイルの検査に通して公開版にする。`GET /scenarios/:id` はいつも公開版を返し、下書きは `/scenarios/:id/draft` で製作者だけが読み書きする。下書きの保存は形を検査し、崩れていれば 422 にする。シナリオ集に載っていないシナリオからは、新しい募集・ソロ開始を始められない。他人のシナリオは、編集画面で公開版を読むだけにする。シナリオからセッションまでの流れを、仕様（`scenario-flow.md`）に明示する。

サイクルは3つに分ける（2026-10-11、人間が決めた）。C1（このプラン）：下書きと公開版。C2：セッションの独立（セッションは開始時のシナリオで進み、シナリオの更新と無関係にする）。C3：シナリオのコピー（他人のシナリオをコピーでき、コピーは親を辿れる）。

## 2. 背景

- [API ドキュメント](2026-10-11-APIドキュメント.md)（PR #23）で人間が出した案（D6）。下書きの保存（`PATCH /api/scenarios/:id`）は書きかけでも保存できるよう中身を検査しないので、`GET /api/scenarios/:id` がシナリオの形（業務の検査を含む）に通らないものを返すことがあり、API ドキュメントでは下書きを返しうる API を業務の検査を外した形（`ScenarioDraft`）で仮に書いた
- 既知の問題（`docs/architecture/known-issues.md`）
  - 「下書きの保存に形の崩れた本文を送ると、そのまま保存して API の一覧と違う形を返す」（API ドキュメントの D7）
  - 「シナリオを非公開にしても、募集・セッションが残り、下書きからも募集を出せる」（シナリオ公開のプランの D9）と、その「シナリオタイプとの関係」
  - 「セッションが PC とシナリオをコピーせず参照している（スナップショット未実装）」（2026-10-03。「開始後にシナリオを直すと、進行中のセッションも変わる」）。C2 で直す
  - 「画面からの公開の口に、システムのカードの参照の検査が無い」（`PATCH` を直接呼ぶとファイルに書かれる、の経路が変わる）
- 今の作り（`apps/web/src/mocks/handlers.ts`）：シナリオは `libraryStatus`（`draft`・`published`）を持つ1種類だけ（`db.scenarios`）。公開中のシナリオの保存は、公開のファイルの検査（`safeParseScenarioFile`）を通してから即座に反映し、開発サーバーでは `scenarios/<id>.json` を書き直す。進行中のセッションは、シーンを移るたびにシナリオを id で引き直す（`scenarioOf`）。募集は、出したときにシナリオの項目（題名・人数・空間モデル・推奨 CP・シナリオタイプ・前提タグ・外したシーン）を写して持つ。他人のシナリオも編集画面で読めて、保存すると 403
- `db.scenarios` を読む経路（プランレビューで grep した）：`editableScenario`（161行）・`replaceScenario`（198）・`blockedReason`（376、再挑戦不可）・`scenarioOf`（406。738・994・1077 から）・募集からの開始（531）・GM 不在の募集から遊ぶ（585）・提案の採用（943）・ソロ開始（1181）・`GET /scenarios`（1204）・`GET /scenarios/:id`（1210）・`nextFreeId`（1224）・作成（1244）・募集の作成（1285）
- 正式仕様：[用語集「シナリオ集」](../glossary.md#シナリオ集)「シナリオ製作者がシナリオを作り、シナリオ集へ公開すると、GMが選べるようになる」。[シナリオの構造とセッション開始までの流れ](../cartagraph/scenario-flow.md)は、シナリオの入手元・募集とセッション・全体フローを書くが、下書き・公開し直し・シナリオ集から外すことは書いていない。[セッションスナップショット](../cartagraph/graph.md#セッションスナップショットとマージ)は、セッションの開始時に必要な範囲を写し取る（今の実装は未実装。C2）
- テスト専用のシナリオ（`fixtures.ts` の `sc-village-always-win`・`sc-exam-*`・`sc-village-no-propose`・`sc-no-intro`。作者は `system`）は、GM の一覧に出さないために `libraryStatus: 'draft'` にしてあり、テストはそこからソロ開始・募集をしている。参照の切れたもの・導入の無いものなど、わざと公開の検査に通らない形のものもある。自分が作者の fixtures のシナリオは `sc-draft-well`（デモの下書き）と `sc-mansion-mine`（シーン編集のテスト用）

## 3. 詳細設計

### 決定事項（人間が決定。2026-10-11）

- **D1 公開版と下書きを分ける** — 製作者の保存は下書きだけを変える。公開版は「シナリオ集へ公開／公開し直す」まで変わらない。編集画面に、公開版と違う変更があることと「公開し直す」を出す
- **D2 シナリオ集に載っているシナリオからだけ、新しく始める** — 新しい募集の作成とソロ開始は、公開版があり、シナリオ集に載っているシナリオだけ（シナリオ公開のプランの D9「下書きからの募集は止めない」を改める）。GM のシナリオ詳細は公開版を読む
- **D3 シナリオ集から外しても、既にある募集・セッションは残る** — 「非公開にする」は公開版を消さず、シナリオ集の一覧から外し、新しい募集の作成とソロ開始を止める。既にある受付中の募集は残り、そこからの開始は今どおりできる（GM 不在の募集からは、外した後も新しいセッションを始められる）。進行中のセッションは続く
- **D4 セッションはシナリオの更新と無関係にする（C2）** — セッションは開始時のシナリオで進み、公開し直しても変わらない。これは仕様（`graph.md`「セッションスナップショット」）どおりで、C2 で実装する。C1 の間は、今の既知の問題（スナップショット未実装）のまま、公開し直すと進行中のセッションの次のシーンから変わる（保存のたびに変わる今より狭まる）。既にある既知の問題を書き直し、新しくは作らない
- **D5 下書きはファイルに書かない** — 開発サーバーでも、下書きはメモリだけ。ファイル（`scenarios/<id>.json`）に書くのは、シナリオ集へ公開・公開し直す・非公開にするとき。保存しただけではファイルは変わらず、リロードすると公開していない編集は消える（画面でそう知らせ続ける。G4）
- **D6 シナリオからセッションまでの流れを仕様に明示する** — `docs/cartagraph/scenario-flow.md` に、製作者の下書きと公開（公開し直すまで届かない）、シナリオ集に載ったものからだけ新しく始める、外しても既にある募集・セッションは残る、セッションは開始時のシナリオで進む（C2 で実装）を書く。理由は `docs/notes/scenario-flow.md`、用語集「シナリオ集」に1文。仕様を先に直すコミットにする
- **D7 他人のシナリオは読むだけ（コピーは C3）** — 製作者でない人がシナリオ編集・シーン編集を開くと、公開版を読み取り専用で見せる（保存・公開・非公開・カードの編集の操作を出さない）。公開版が無ければ「見つかりません」。コピー（親を辿れる）は C3
- **D8 サイクルを3つに分ける**（上の「1. 概要」）

### AI が決めた設計（プランの AI レビューを反映）

- **G1 モックのデータ** — `db.scenarios` は公開版（`Scenario`）だけにする。`libraryStatus` は公開版の「シナリオ集に載っているか」（`published`＝載っている、`draft`＝外した。ファイルの書き方（シナリオ公開の D2）と同じ）。下書きは `db.drafts`（`ScenarioDraft[]`。新しいものを先に置き、一覧の並びにそのまま使う）に置く
  - **シード**：自分（`fx.me`）が作者のシナリオのうち、`DRAFT_ONLY_SEED_IDS`（`sc-draft-well`・`sc-mansion-mine`）は下書きだけ（公開版なし）。それ以外の自分のシナリオ（公開済みの JSON など）は、公開版の深い写しを下書きにする。他人・`system` のシナリオは下書きを持たない。`resetDb` で両方を戻す
  - **下書きの `libraryStatus`**：下書きは `ScenarioDraft` の形のため `libraryStatus` を持つが、意味を持たせず、サーバーが常に `'draft'` にする。公開の状態は `ScenarioDraftView.publication` だけが持ち、画面はそれだけを見る（SSOT）
  - **`updatedAt`**：下書きの保存でサーバーが付ける。公開・公開し直すときは、公開版の `updatedAt` を下書きの値にする（中身が変わらない公開し直しで、ファイルが同じ中身になる）。非公開にするときは今どおり `nowIso()`
  - **画像**：公開版のメモリには、今どおり画像（`portraitUrl` の `data:` の URL）付きの下書きをそのまま置き、ファイルにだけ `toScenarioFile` を当てる
  - **権限の順序**（`editableScenario` を直す）：下書きにも公開版にも無ければ 404、作者（下書きか公開版の `authorId`）が自分でなければ 403
  - **キュー**：下書きの保存・公開・非公開は、今の `inScenarioQueue` に同じ id で並べる。公開の書き込みを待つ間に届いた保存は、下書きにだけ入る
  - **`nextFreeId`**：使用中の判定に `db.drafts` も含める
- **G2 テスト専用のシナリオ** — 作者が `system` のテスト専用のシナリオは、公開版を `libraryStatus: 'published'`（新しく始められる）にし、シナリオ集の一覧（`GET /scenarios`）からはモックの中だけで隠す。隠すのは「`fixtureOnlyScenarioIds`（fixtures にしか無い）にあり、公開版があるもの」で導き、新しい id の集合は作らない。これらは公開の検査を通していない（わざと壊した形がある）ので、「公開版は公開の検査を通ったもの」の例外で、テストのためのシードだけに許す（API ドキュメントの `Scenario` の説明にも「テスト用のシードを除く」）
- **G3 API**（`packages/schemas` の一覧も同じに直す。前のサイクルの G10 の仮の形をやめる）

| メソッド・パス | 振る舞い | 応答 |
|---|---|---|
| `GET /scenarios` | シナリオ集に載っている公開版（G2 で隠すものを除く） | 200 `Scenario[]` |
| `GET /scenarios/:id` | 公開版（外したものも返す。既にある募集・セッションと、他人が読むため） | 200 `Scenario`、404（公開版が無い） |
| `GET /scenario-drafts` | 自分の下書きの一覧（今の `GET /scenarios?mine=1` の代わり。シナリオ管理（製作者）が使う） | 200 `ScenarioDraftView[]` |
| `POST /scenarios` | 下書きを作る（公開版は作らない） | 201 `ScenarioDraftView`、422 |
| `GET /scenarios/:id/draft` | 下書き | 200 `ScenarioDraftView`、403、404 |
| `PATCH /scenarios/:id/draft` | 本文の項目で下書きを上書きし、上書きした結果を `scenarioDraftSchema`（業務の検査なし・知らないキーは誤り）で検査する。崩れていれば 422 で何も変えない。`id`・`authorId`・`authorName`・`libraryStatus`・`updatedAt` は本文によらずサーバーが決める。ファイルには書かない | 200 `ScenarioDraftView`、403、404、422 |
| `POST /scenarios/:id/publish` | 下書きを公開のファイルの検査に通し、公開版にして（`libraryStatus: 'published'`）ファイルに書く。公開中で変更が無くても書き直す（二度押しで失敗させない）。失敗すれば公開版・一覧・下書きは変わらない | 200 `ScenarioSaveResult`、403、404、422（検査・デモ用）、500 |
| `POST /scenarios/:id/unpublish` | 公開版を一覧から外し（`libraryStatus: 'draft'`）、公開版の中身でファイルを書き直す。下書きは変えない。公開版が無ければ 422。外したものをもう一度外しても 200 | 200 `ScenarioSaveResult`、403、404、422、500 |
| `POST /scenarios/:id/recruitments`・`POST /scenarios/:id/start-solo` | 公開版が無い・一覧から外したシナリオは 422「シナリオ集に公開されていないシナリオからは始められません」。本文の検査より後、ほかの業務の検査より前に見る | 今の応答に 422 の理由を足す |

  - `PATCH /scenarios/:id` は消す（`/draft` に替える）。`GET /scenarios?mine=1` も消す（クエリで応答の形を変えない）。これで `query` を使う API が無くなるので、`defineEndpoint` の `query` と OpenAPI の変換の `query` の処理、そのテストも消す（使う所が無いため）
  - **置き場所の例外**：`/scenario-drafts` は URL の最初の区切りが違うが、`ScenarioDraftView`（`scenarios/response.ts`）を使うので `packages/schemas/src/scenarios/endpoints.ts` に置く。`architecture.md`「packages/schemas の中の置き場所」の例外（`/scenarios/:id/start-solo` と同じ書き方の注記）に足す。タグは `scenarios` にする（`openapi.ts` の `tagOf` を、`/scenario-drafts` を `scenarios` に寄せる形にする）。`/scenarios/drafts` にしないのは `/scenarios/:id` と照合が重なるため
  - `ScenarioDraftView` ＝ `{ draft: ScenarioDraft, publication: 'none' | 'listed' | 'unlisted', changed: boolean }`。`publication` は公開版が無い／シナリオ集に載っている／外した。`changed` は下書きが公開版と違うか（`libraryStatus`・`updatedAt` を除き、キーの順によらない深い比較。公開版が無ければ false）。`packages/schemas` の `scenarios/response.ts` に置く。`ScenarioDraftSaveResult` は消す。`scenarioFileResultSchema` の `null`（下書きの保存）は使わなくなるので消す
  - 誤りの文：`PATCH /draft` の形の誤りは「下書きの形が正しくありません（<場所>）」。本文がオブジェクトでないときは今どおり「本文はオブジェクトにしてください」
- **G4 画面**
  - 状態の言葉（API の値 → 画面）：`none` → 「下書きのみ」、`listed` → 「シナリオ集に公開中」、`unlisted` → 「シナリオ集から外している」。「未公開」「非公開」は仕様の別の意味（カードの未公開情報・冒険記の公開範囲）とぶつかるので状態の表示には使わない。ボタンの「非公開にする」は今の文言のまま
  - シナリオ管理（製作者、`CreatorScenarioListPage`）：`GET /scenario-drafts` を使い、各シナリオに状態と、`changed` なら「公開版と違う変更あり」を出す
  - シナリオ編集（`CreatorScenarioEditPage`）：自分のシナリオは下書きを読み書きする（公開版は引かない。公開版の無いシナリオで 404 を出さない）。状態の表示。ボタンは「保存」（編集中だけ）、「シナリオ集へ公開」（`none`・`unlisted`）／「公開し直す」（`listed` で `changed`）、「非公開にする」（`listed`）。編集中は公開・非公開を押せない（今どおり）。`changed` のとき「保存した変更は、公開し直すまで GM・PL に届きません」。`none` か `changed` のとき、常に「公開していない編集は、リロードで消えます」を出す（D5。保存の知らせは一度きりなので、出し続ける）。公開・非公開の知らせは今の `ScenarioFileNote`（ファイルに保存した／デモのため保存されません）
  - シーン編集（`CreatorSceneEditPage`）：自分のシナリオは下書きを読み書きする（`useScenarioDraft`・`useUpdateScenarioDraft`）。シナリオ編集と同じく「公開していない編集は、リロードで消えます」と、公開はシナリオ編集から行う案内を出す。保存の知らせはファイルではなく「下書きを保存しました」
  - 他人のシナリオ（D7）：シナリオ編集・シーン編集は、`GET /scenarios/:id/draft` が 403 なら公開版を読み、読み取り専用で見せ、「製作者でないため編集できません」を出す。読み取り専用は、入力と操作の部分を `<fieldset disabled>` で包んで押せなくする（値は入力欄のまま見える）。保存・公開・非公開のボタンは出さない。シーン編集へのリンクは押せる（読み取り専用で開く）。公開版も無ければ「見つかりません」
  - GM のシナリオ詳細（`GmScenarioDetailPage`）：公開版を読む。外したシナリオは、募集を出す操作を出さず「シナリオ集から外されているため、新しい募集を出せません」。公開版が無ければ「見つかりません」（今のシナリオが無いときと同じ）
  - GM・PL のそれ以外の画面（セッションの進行管理・プレイ・セッション一覧・村はずれの一歩・GM のシナリオ一覧）は、今どおり公開版
  - 型：pages は schemas を import できないので、`ScenarioDraftView` の別名を `entities/scenario/api/types.ts` に置く（API ドキュメントの G8 と同じ形）
  - クエリキー：`keys.scenarios`（公開版の一覧。`mine` の引数をやめる）、`keys.scenario(id)`、`keys.scenarioDrafts`＝`['scenarios', 'drafts']`、`keys.scenarioDraft(id)`＝`['scenarios', 'draft', id]`（どれも `['scenarios']` の前方一致で作り直せる）。保存・公開・非公開・作成の後に `['scenarios']` を作り直す
- **G5 ファイルの書き込み** — `writeScenarioFile` は公開・非公開のときだけ呼ぶ（保存では呼ばない。D5）。公開のファイルの検査・D7（デモ用は公開できない）・D8（製作者だけ）・D10（エージェント用の開発サーバーは書かない）は今どおり
- **G6 始められるかの判定** — ハンドラの中の小さな関数（`startableScenario(id)`：公開版があり、一覧に載っているかを見て、だめなら 422 の応答）にする。domain の純粋関数にしないのは、判定がモックのデータの有無（公開版があるか、`libraryStatus`）を見るだけで、ゲームのルールの計算を持たないため（将来のバックエンドはデータの持ち方が変わるので、そちらで書く）。募集からの開始（531）・GM 不在の募集から遊ぶ（585）には挟まない（D3）
- **G7 開発サーバーで確かめるスクリプト** — `web:check:publish`（`scenario-publish.mjs`、`CARTAGRAPH_WRITE_SCENARIOS=1` の `web:dev:agent` で流す）と `web:check:authoring`（`scenario-authoring.mjs`、既定の `web:dev:agent`）を新しいボタン・文言に合わせて直す。`web:check:publish` に足す：スクリプトが作ったシナリオで、公開中に保存しただけではファイルが変わらない、公開し直すと書き直す、リロードすると公開していない編集が消え下書きが公開版から作り直される（「公開版と違う変更あり」が消える）。コミット済みのシナリオでは試さない（スクリプトが自分で作ったファイルしか消さないため）。起動と後始末は `browser-check` スキル

## 5. 新規テストケース

web（MSW）

- **T1** 保存は下書きだけを変える：公開中のシナリオの下書きを保存しても、`GET /scenarios/:id`（公開版）とファイルの保存先は変わらず、`changed` が true。公開し直すと公開版が下書きと同じになり、ファイルに1回書き、`changed` が false。公開した後に下書きを保存しても公開版が変わらない（同じオブジェクトを共有していない）
- **T2** 下書きの保存の形の検査：知らないキー（`{ foo: 1 }`、ノード・カードの中の知らないキー）・型違い（`{ title: 123 }`・`{ partySize: 'x' }`・`deck[0].cards[0].kind` の型違い）・`scenarioType: null` は 422（文の場所の部分を固定）で、下書きは変わらない。`{}` は 200 で何も変わらない。参照の切れた下書き（存在しないノードを指す選択肢）は保存できる（反対側）。`id`・`authorId`・`authorName`・`libraryStatus` を本文に書いても変わらない。`updatedAt` はサーバーが付ける
- **T3** 始められるか（D2・D3）：公開版の無いシナリオ（`sc-draft-well`）・外したシナリオからの募集の作成とソロ開始は 422（文を固定）で、募集・セッションが増えない。載っているシナリオからは今どおり始められる。外した後も、既にある受付中の募集（通常・GM 不在）から始められ、進行中のセッションは次のシーンへ進める。本文が崩れていて、かつ始められないシナリオのときは、本文の 422（順序の固定）
- **T4** 公開版の取得と一覧：公開版の無いシナリオの `GET /scenarios/:id` は 404。外したシナリオは 200。`GET /scenarios` に、外したもの・公開版の無いもの・テスト専用のもの（G2）が出ない。テスト専用のものは `GET /scenarios/:id` で `published`
- **T5** 下書きの権限：他人・`system` のシナリオの `GET`・`PATCH /scenarios/:id/draft` は 403、どちらにも無い id は 404
- **T6** シード（G1）：`GET /scenario-drafts` は自分の分だけ。`sc-galleon` は `listed`・`changed: false`、`sc-draft-well`・`sc-mansion-mine` は `none`・`changed: false`。`resetDb()` で `db.drafts` もシードに戻る
- **T7** `changed` の境界：公開版が無いと保存しても false。公開中で保存すると true。公開し直すと false。公開版と同じ中身で保存すると false（`updatedAt` だけ違う）。外しても `changed` は変わらない（`libraryStatus` だけ違う）。キーの順が違うだけなら false
- **T8** 非公開（D3）：公開版の無いシナリオを非公開にすると 422。変更のある下書きを持つシナリオを非公開にすると、ファイルに書くのは公開版の中身（下書きではない）で、下書きと `changed` は変わらない。外したシナリオを「シナリオ集へ公開」すると、一覧に戻り、公開版が下書きの中身になる。外したものをもう一度外しても 200。公開中で変更の無いものをもう一度公開しても 200 で書き直す（`updatedAt` は下書きの値なので中身は同じ）
- **T9** 公開・非公開の失敗：変更のある下書き（参照を切った・戦闘なしなのに空間モデルを持つ）は保存できる（200）が、公開し直すと 422 で、公開版・一覧・下書き・`changed` は変わらず、ファイルに書かない。保存先が失敗する（500）ときも公開版・一覧は変わらない。非公開の 500 でも一覧に載ったまま
- **T10** 公開版を使う（D2）：公開中のシナリオの導入の選択肢の名前を下書きで変えて保存しても、ソロ開始・GM 不在の募集から始めたセッションの手札は公開版の名前。公開し直すと、新しく始めたセッションは新しい名前
- **T11** キュー：公開の書き込みを待つ間に届いた保存は、下書きにだけ入る（公開版は押した時点の下書き、下書きは新しい題名、`changed` は true、書き込みは1回）

### 課題

シナリオは1種類しか無く、公開中のシナリオを製作者が保存すると、その場で GM・PL と進行中のセッションに届いていた。下書きの保存は中身を検査しないので、検査に通らない下書きから募集・ソロ開始ができ、`GET /api/scenarios/:id` が業務の検査に通らない形を返すことがあった（API ドキュメントでは仮の形で書いていた）。形の崩れた本文も保存できた。人間の案で、下書きの API を分ける。要望 `docs/backlog/scenario-draft-api.md`、プラン `docs/plans/2026-10-11-シナリオの下書きのAPI.md`。

### 解決策

- 仕様（`docs/cartagraph/scenario-flow.md`「シナリオの公開」）を先に直した：製作者の下書きは公開し直すまで届かない、新しく始められるのはシナリオ集に載っているシナリオだけ、シナリオ集から外しても既にある募集・セッションは残る、セッションは開始時にコピーした公開版で進む（実装は C2）
- モックはシナリオを公開版（`db.scenarios`）と下書き（`db.drafts`）に分けた。保存（`PATCH /scenarios/:id/draft`）は下書きだけを変え、上書きした結果の形を検査して崩れていれば 422。公開・公開し直すで下書きを公開の検査に通して公開版にし、ファイルに書く。非公開は公開版を一覧から外す
- `GET /scenarios/:id` はいつも公開版。下書きは `GET /scenarios/:id/draft`・`GET /scenario-drafts`（`ScenarioDraftView`：下書きと公開の状態・変更あり）
- 新しい募集・ソロ開始は、シナリオ集に載っている公開版だけから。既にある募集からの開始は止めない
- 画面：シナリオ管理・シナリオ編集・シーン編集に状態（下書きのみ／シナリオ集に公開中／シナリオ集から外している）と「公開版と違う変更あり」「公開し直す」を出す。公開していない編集はリロードで消えると知らせ続ける。他人のシナリオは公開版を読むだけ（自分の下書きの一覧で先に見分ける）。GM のシナリオ詳細は外したシナリオから募集を出せない
- API ドキュメント（packages/schemas の一覧・OpenAPI）を新しい API に合わせた
