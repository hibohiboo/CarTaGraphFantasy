# シナリオの下書きの API を分ける

要望：[シナリオの下書きの API を分ける](../backlog/scenario-draft-api.md)（[ロードマップ](../roadmap.md#backend-1on1) backend-1on1 の下ごしらえ）

状態：検討中。D1〜D5 は2026-10-11に人間と確かめた。プランの AI レビューはまだ

## 1. 概要

シナリオを「公開版」（検査済み。GM・PL が使う）と「下書き」（製作者の書きかけ。形だけを見る）に分ける。製作者の保存は下書きだけを変え、「公開する／公開し直す」で下書きを公開のファイルの検査に通して公開版にする。`GET /scenarios/:id` はいつも公開版（業務の検査を通った `Scenario`）を返し、下書きは `/scenarios/:id/draft` で読み書きする。下書きの保存は形を検査し、崩れていれば 422 にする。一度も公開していないシナリオと、シナリオ集から外した（非公開の）シナリオからは、新しい募集・ソロ開始を始められない。

## 2. 背景

- [API ドキュメント](2026-10-11-APIドキュメント.md)（PR #23）で人間が出した案（D6）。下書きの保存（`PATCH /api/scenarios/:id`）は書きかけでも保存できるよう中身を検査しないので、`GET /api/scenarios/:id` がシナリオの形（業務の検査を含む）に通らないものを返すことがあり、API ドキュメントでは下書きを返しうる API を業務の検査を外した形（`ScenarioDraft`）で仮に書いた
- 既知の問題（`docs/architecture/known-issues.md`）
  - 「下書きの保存に形の崩れた本文を送ると、そのまま保存して API の一覧と違う形を返す」（API ドキュメントの D7）
  - 「シナリオを非公開にしても、募集・セッションが残り、下書きからも募集を出せる」（シナリオ公開のプランの D9）と、その「シナリオタイプとの関係」（下書きの `scenarioType: null` で編集画面が落ちる。戦闘なしの下書きに自動戦闘のシーンを足して URL から募集を出せる）
- 今の作り（`apps/web/src/mocks/handlers.ts`）：シナリオは `libraryStatus`（`draft`・`published`）を持つ1種類だけ（`db.scenarios`）。公開中のシナリオの保存は、公開のファイルの検査（`safeParseScenarioFile`）を通してから即座に反映し、開発サーバーでは `scenarios/<id>.json` を書き直す。進行中のセッションは、シーンを移るたびにシナリオを id で引き直す（`scenarioOf`）ので、公開中のシナリオを保存すると、進行中のセッションの次のシーンから変わる
- 正式仕様：[用語集「シナリオ集」](../glossary.md#シナリオ集)「シナリオ製作者がシナリオを作り、シナリオ集へ公開すると、GMが選べるようになる」。下書きと公開版の扱い、非公開の扱いは仕様に書かれていない（画面の仕様は `docs/screens/index.md`「シナリオ編集」）。[セッションスナップショット](../cartagraph/graph.md#セッションスナップショットとマージ)は、セッションの開始時に正史グラフから必要な範囲を写し取る、としている（今の実装はシナリオを写し取らず id で引き直す。D4 で今どおりとし、既知の問題に記録する）
- テスト専用のシナリオ（`fixtures.ts` の `sc-village-always-win`・`sc-exam-*`・`sc-village-no-propose`・`sc-no-intro`）は、GM の一覧に出さないために `libraryStatus: 'draft'` にしてあり、テストはそこからソロ開始・募集をしている。参照の切れたもの・導入の無いものなど、わざと公開の検査に通らない形のものもある

## 3. 詳細設計

### 決定事項（人間が決定。2026-10-11）

- **D1 公開版と下書きを分ける** — 製作者の保存は下書きだけを変える。公開版は「公開する／公開し直す」まで変わらない。編集画面に、公開版と違う変更があることと「公開し直す」を出す
- **D2 公開版があるシナリオだけから始める** — 募集の作成・ソロ開始・GM のシナリオ詳細は公開版を使う。一度も公開していないシナリオからは始められない（シナリオ公開のプランの D9「下書きからの募集は止めない」を改める）
- **D3 非公開は、一覧から外して新しく始めるのを止めるだけ** — 公開版は消さない。進行中のセッションはその版で続き、受付中の募集も残る（既にある募集からの開始は今どおりできる）。新しい募集の作成とソロ開始は 422
- **D4 公開し直すと、進行中のセッションも新しい公開版に切り替わる** — 今どおり、セッションはシナリオを id で引き直す（次のシーンから変わる）。版を持ち分ける（セッションに写しを持たせる）のはスコープ外にし、既知の問題に記録する
- **D5 下書きはファイルに書かない** — 開発サーバーでも、下書きはメモリだけ（今の未公開の下書きと同じ）。ファイル（`scenarios/<id>.json`）に書くのは、公開する・公開し直す・非公開にするとき。保存しただけではファイルは変わらず、リロードすると公開していない編集は消える（画面でそう知らせる）

### AI が決めた設計

- **G1 モックのデータ** — `db.scenarios` は公開版（`Scenario`）だけにする。`libraryStatus` は公開版の「シナリオ集に載っているか」（`published`＝載っている、`draft`＝外した。ファイルの書き方（シナリオ公開の D2）と同じ）。下書きは `db.drafts`（`Map<id, ScenarioDraft>`）に置く。シード：自分（`fx.me`）が作者のシナリオは、公開版の写しを下書きにする。公開版の無い下書き（デモの `sc-draft-well`）は下書きだけ。他人・`system` のシナリオは下書きを持たない（編集できない。今の D8 どおり 403）。`resetDb` で両方を戻す
- **G2 テスト専用のシナリオ** — `fixtures.ts` のテスト専用のシナリオは、公開版を `libraryStatus: 'published'`（新しく始められる）にし、シナリオ集の一覧（`GET /scenarios`）からはモックの中だけで隠す（`fixtureOnlyScenarioIds` と同じ置き方で、`hiddenFromLibrary` の id の集合を `handlers.ts` に置く。domain・スキーマは変えない）。これで、テストは今どおり始められ、GM の一覧にも出ない
- **G3 API**（`packages/schemas` の一覧も同じに直す。前のサイクルの G10 の仮の形をやめる）

| メソッド・パス | 振る舞い | 応答 |
|---|---|---|
| `GET /scenarios` | シナリオ集に載っている公開版（隠すテスト用を除く） | 200 `Scenario[]` |
| `GET /scenarios/:id` | 公開版（載っていない＝非公開も返す。進行中のセッションと既にある募集が使う） | 200 `Scenario`、404（公開版が無い） |
| `GET /scenario-drafts` | 自分の下書きの一覧（今の `GET /scenarios?mine=1` の代わり。製作者のシナリオ管理が使う） | 200 `ScenarioDraftView[]` |
| `POST /scenarios` | 下書きを作る（公開版は作らない） | 201 `ScenarioDraftView`、422 |
| `GET /scenarios/:id/draft` | 下書き | 200 `ScenarioDraftView`、403（製作者でない）、404 |
| `PATCH /scenarios/:id/draft` | 本文の項目で下書きを上書きし、上書きした結果を形（`scenarioDraftSchema`。業務の検査なし・知らないキーは誤り）で検査する。崩れていれば 422 で何も変えない。`id`・`authorId`・`authorName`・`libraryStatus` は本文によらず保つ。ファイルには書かない | 200 `ScenarioDraftView`、403、404、422 |
| `POST /scenarios/:id/publish` | 下書きを公開のファイルの検査に通し、公開版にして（`libraryStatus: 'published'`）ファイルに書く。公開中で変更が無くても書き直す（二度押しで失敗させない） | 200 `ScenarioSaveResult`、403、404、422（検査・デモ用）、500 |
| `POST /scenarios/:id/unpublish` | 公開版を一覧から外し（`libraryStatus: 'draft'`）ファイルを書き直す。下書きは変えない。公開版が無ければ 422 | 200 `ScenarioSaveResult`、403、404、422、500 |
| `POST /scenarios/:id/recruitments`・`POST /scenarios/:id/start-solo` | 公開版が無い・一覧から外したシナリオは 422「シナリオ集に公開されていないシナリオからは始められません」 | 今の応答に 422 の理由を足す |

  - `PATCH /scenarios/:id` は消す（`/draft` に替える）。`GET /scenarios?mine=1` も消す（`/scenario-drafts` に替える。クエリで応答の形を変えない）。`/scenario-drafts` を `/scenarios/drafts` にしないのは、`/scenarios/:id` と照合が重なるため（API ドキュメントの実装レビュー（異常系）P2-7）
  - `ScenarioDraftView` ＝ `{ draft: ScenarioDraft, publication: 'none' | 'published' | 'unlisted', changed: boolean }`。`publication` は公開版の有無と一覧に載っているか、`changed` は下書きが公開版と違うか（`libraryStatus`・`updatedAt` を除いて比べる。公開版が無ければ false）。`packages/schemas` の `scenarios/response.ts` に置く
  - 本文のスキーマ：`PATCH /scenarios/:id/draft` は今の `updateScenarioBody`（オブジェクトなら何でも）のまま受け取り、上書きした結果を `scenarioDraftSchema` で検査する（本文の項目だけでなく、上書きの結果の形を見る。本文のスキーマを `scenarioDraftSchema.partial()` にすると、`{}` の深いところの崩れは見られるが、上書き後の整合は見られないため、結果を見る）。誤りの文は「下書きの形が正しくありません（<場所>）」
- **G4 画面**
  - シナリオ管理（製作者、`CreatorScenarioListPage`）：`GET /scenario-drafts` を使い、各シナリオに「下書き（未公開）」「シナリオ集に公開中」「非公開」と、公開中で変更があれば「公開版と違う変更あり」を出す
  - シナリオ編集（`CreatorScenarioEditPage`）：下書きを読み書きする。状態の表示（上と同じ）。ボタンは「保存」（今どおり編集中だけ）、「シナリオ集へ公開」（公開版が無い・非公開のとき）／「公開し直す」（公開中で変更があるとき）、「非公開にする」（公開中のとき）。編集中（`dirty`）は公開・非公開を押せない（今どおり）。公開中で変更があるとき「保存した変更は、公開し直すまで GM・PL に届きません」。保存したときの知らせは「下書きを保存しました（公開していない編集はリロードで消えます）」（D5）
  - シーン編集（`CreatorSceneEditPage`）：下書きを読み書きする（`useScenarioDraft`・`useUpdateScenarioDraft`）
  - GM のシナリオ詳細（`GmScenarioDetailPage`）：公開版を読む。一覧から外したシナリオは、募集を出す操作を出さず「シナリオ集に公開されていないため、募集を出せません」
  - GM・PL のそれ以外の画面（セッションの進行管理・プレイ・セッション一覧・村はずれの一歩）は、今どおり `useScenario`（公開版）
  - クエリキー：下書きは `keys.scenarioDraft(id)`・`keys.scenarioDrafts`。公開・非公開・保存の後に、下書き・公開版・一覧を作り直す
- **G5 ファイルの書き込み** — `writeScenarioFile` は公開と非公開のときだけ呼ぶ（保存では呼ばない。D5）。公開のファイルの検査・D7（デモ用は公開できない）・D8（製作者だけ）・D10（エージェント用の開発サーバーは書かない）は今どおり
- **G6 domain** — 変えない（`scenarioSchema`・`scenarioDraftSchema` はそのまま）。「始められるか」の判定は、ハンドラの中の小さな関数（`startableScenario(id)`：公開版があり、一覧に載っている、を見て、だめなら 422 の応答）にする
- **G7 開発サーバーで確かめるスクリプト** — `web:check:publish`（`apps/web/e2e/dev/scenario-publish.mjs`）と `web:check:authoring`（`scenario-authoring.mjs`）を新しいボタン・文言に合わせて直す。公開中のシナリオを保存しただけではファイルが変わらないこと、公開し直すと書き直すことを、`web:check:publish` に足す

## 5. 新規テストケース

web（MSW と画面）

- **T1** 保存は下書きだけを変える：公開中のシナリオの下書きを保存しても、`GET /scenarios/:id`（公開版）は変わらず、ファイルの保存先にも書かない。`changed` が true になる。公開し直すと公開版が下書きと同じになり、ファイルに書き、`changed` が false
- **T2** 下書きの保存の形の検査：知らないキー（`{ foo: 1 }`）・型違い（`{ title: 123 }`・`{ partySize: 'x' }`）・`scenarioType: null` は 422 で、下書きは変わらない。参照の切れた下書き（存在しないノードを指す選択肢）は保存できる（反対側）。`id`・`authorId`・`libraryStatus` を本文に書いても変わらない
- **T3** 始められるか：公開版の無いシナリオ（`sc-draft-well`）・非公開にしたシナリオからの募集の作成とソロ開始は 422（文を固定）で、募集・セッションが増えない。公開中のシナリオからは今どおり始められる（反対側）。非公開にしても、既にある受付中の募集から始められ、進行中のセッションは次のシーンへ進める（D3）
- **T4** 公開版の取得：公開版の無いシナリオの `GET /scenarios/:id` は 404。非公開のシナリオは 200（進行中のセッションのため）。`GET /scenarios` に非公開・公開版の無いもの・テスト専用のものが出ない
- **T5** 下書きの取得・保存の権限：他人のシナリオの `GET`・`PATCH /scenarios/:id/draft` は 403、無い id は 404
- **T6** 非公開：公開版の無いシナリオを非公開にすると 422。非公開は下書きを変えない
- **T7** 公開し直しの切り替え（D4）：進行中のセッションがあるシナリオを公開し直すと、次のシーンから新しい公開版を引く（今どおりであることの固定）
- **T8** 画面（シナリオ編集）：状態の表示（下書き（未公開）・公開中・非公開）、変更があるときの「公開し直す」と知らせ、編集中は公開・非公開を押せない、保存の知らせ。シナリオ管理の一覧の状態の表示。GM のシナリオ詳細で、非公開のシナリオは募集を出す操作が出ない
- **T9** 画面から最後まで：製作者がシナリオを作り（下書き）、編集して保存し、公開し、GM の一覧に出て、GM 不在の募集を出して PL が結末まで遊ぶ（`web:check:authoring` と同じ流れを Vitest で。今ある通しのテストを新しい流れに直す）。続けて、下書きを直して保存しても、進行中・新しく始めたセッションは公開版のまま、公開し直すと変わる

schemas

- **T10** 一覧（`endpoints.ts`）の新しい API と、`ScenarioDraftView` の形（`publication` の列挙、`changed`）。OpenAPI に `ScenarioDraftView` が出て、`ScenarioDraftSaveResult` が無くなる

骨抜き禁止（`node scripts/mutate-check.mjs`）：T1（保存で公開版も変える）、T2（形の検査を外す）、T3（始められるかの検査を外す・非公開を見ない）、T4（`GET /scenarios` の絞り込みを外す）で落ちることを確かめる。

## 8. スコープ外

- セッションが始めたときの公開版で最後まで遊ぶ（版を持ち分ける。D4。既知の問題に記録）
- 下書きをファイルに書いてリロードで残す（D5）
- 非公開にしたときに受付中の募集を締め切る（D3）
- 公開版と下書きの差分を項目ごとに見せる（「変更あり」だけ出す）
- 公開版を消す・シナリオを消す
- ログインと権限（バックエンドで）
