# 不安定な E2E を、直す要望へのリンク付きでスキップにする

要望：[不安定な E2E は、いったんスキップにして直す要望を起票する](../backlog/e2e-flaky-skip.md)

状態：プラン作成中（2026-10-27）。D1〜D8 は2026-10-27に人間と確かめた（質問2ラウンド）。D9〜D14 は AI が決めた案（人間に確かめること。プランの AI レビューの後に確かめる）。次は手順2〜3（プランの AI レビュー。別セッション、等級：強い）。

## 1. 概要

ユースケースの E2E（`apps/web/e2e/usecases/`）で、たまに落ちるテストを、直す要望（`docs/backlog/…`）へのリンクを添えてテスト単位でスキップにできるようにする。リンクの無いスキップ・実在しない要望・閉じた要望（完了・見送り）へのリンクは検査で止める。ユースケースの結果のページとトレースのページでは、スキップしたテストの UC を「全スキップ」と出し、テストの一覧に「スキップ中」と直す要望へのリンクを出す。

`retries` は足さない方針（[テストのルール](../process/rules/testing.md)「ユースケースの E2E」）を保ったまま、不安定なテストで PR の CI が止まり続けないようにする。

## 2. 背景

- 2026-10-18、[ユースケースと E2E の結果を紐づける](../backlog/usecase-e2e-report.md)の人間レビュー（D9：`retries` を足さない）で出た要望。2026-10-26、P5 の実装中に `gm-session.test.ts` が `Failed to load resource: net::ERR_FAILED` で1度落ちた（単独で流すと通る）
- 2026-10-27、P5 の人間レビューで「スキップだけの UC が『落ちた』と出る。『全スキップ』と出るようにしたい」。ユースケースの結果のページとトレースのページの両方で同じ状態にする
- 正式仕様・ルール：[テストのルール](../process/rules/testing.md)「ユースケースの E2E」（変える：スキップの書き方と検査）、[テストレポート](../architecture/test-report.md)「ユースケースとの対応の見方」「トレースの見方」（変える：状態の表）、[デザイナーノート](../notes/architecture/test-report.md)（決めた理由を足す）、[要望の書き方](../backlog/index.md)（変えない）。ゲームの仕様（`docs/cartagraph/`）は変えない
- 今の作り（読んで確かめた）
  - `scripts/usecases.mjs` の `parseTestFile` が `test.skip`・`test.fixme`・`test.step.skip` などを `forbidden` に拾い、`scripts/check-usecase-tags.mjs` が `e2e/usecases/` でだけ止める。`testCount` と `readTags` の持ち主の判定は `test(` と `test.describe(` だけを見る（`test.skip(` は数えない）
  - Biome の `noSkippedTests`（`biome.json`。e2e も対象）が `.skip` をコミット前に止める。意図的に残すときは抑制コメントを書く（テストのルール「骨抜き禁止」）
  - `scripts/build-usecase-report.mjs`：`runStates` は結果の `status` が `skipped` のとき「手前で止まった」のままにする（serial の手前の失敗などで走らなかったテスト）。UC の状態は 落ちた ＞ 手前で止まった ＞ 通った の強い順
  - `scripts/build-trace-report.mjs`：UC の状態は usecase-report の状態を写し、手前で止まったを落ちたにする。状態の悪い順は `STATE_ORDER`（落ちた ＞ 結果なし ＞ 未実装 ＞ テストなし ＞ 確認済）。smoke の spec は全部スキップならテストなし、Vitest のスキップのみもテストなし
  - Playwright は 1.63。`test.skip(title, details, body)` でスキップを宣言でき、`details.annotation` は HTML・JSON のレポートに載る

| D7 | ラベル：UC・トレースの要素の状態は「全スキップ」、テストの一覧の各テストは「スキップ中」（直す要望へのリンク付き） | 人間 |

| D9 | スキップはテスト単位で、宣言の形に限る：`test.skip('題', { tag: [...], annotation: { type: 'backlog', description: 'docs/backlog/<名前>.md' } }, async (...) => { ... })`。ステップ単位（`test.step.skip`）は不可（後のステップが前のステップの画面の状態に頼る通しなので、途中だけ飛ばせない）。本文の中の条件付きの `test.skip(cond)`・`test.fixme`・`test.fail`・`test.slow`・`expect.soft`・`test.only` は今どおり止める（スキップの書き方を1つにし、静的に読めるようにする） | AI |
| D10 | `annotation` は1つのオブジェクトか配列。`type: 'backlog'` の注記はスキップしたテストにちょうど1つ。スキップしていないテストに `backlog` の注記があれば止める（直した後の消し忘れ）。注記の `type`・`description` は文字列の直書き | AI |

| D12 | 結果のページで「全スキップ」にするのは、結果の `status` が `skipped` で、`backlog` の注記があるテストだけ。注記の無い `skipped`（serial の手前の失敗など）は今どおり「手前で止まった」。注記は JSON の `tests[].annotations` と `results[].annotations` の両方から読む（版で置き場所が違うため。実物の JSON で確かめる：T6） | AI |
| D13 | 「スキップ中」のリンクは `../backlog/<名前>.html`、文字は要望の `title`（ページを作るときに `docs/backlog/` から読む。読めなければファイル名） | AI |
| D14 | 直す要望の `trace` には、スキップしたテストのタグの UC を書くことを、テストのルールに書く（検査はしない）。トレースで、その要望が「全スキップ」になり、直すまで届いていないと分かる | AI |

### 書き方（テストのルール「ユースケースの E2E」に置く）

```ts
// biome-ignore lint/suspicious/noSkippedTests: 不安定なため。直す要望は annotation
test.skip('GM が描写を書いて…', {
  tag: ['@PL-1', '@PL-2'],
  annotation: { type: 'backlog', description: 'docs/backlog/gm-session-flaky.md' },
}, async ({ page }) => { /* 本文は消さずに残す */ });
```

- 本文は消さない（直したら `test.skip` を `test` に戻し、注記を消すだけにする）
- スキップする PR で、直す要望を起こす（状態は未着手でよい）

### 検査：`scripts/usecases.mjs`・`scripts/check-usecase-tags.mjs`

- `parseTestFile` に足す：`skips`（最初の引数が文字列の直書きの `test.skip(` の数）、`backlogs`（`type: 'backlog'` の注記の `description` の配列）。`test.skip(` の宣言は `testCount` に数え、`readTags` の持ち主にも入れる。`forbidden` からは宣言の `test.skip(` だけを外す（最初の引数が文字列でない `test.skip(` は残す）
- 既存のツールで書けないか：Biome の `noSkippedTests` はスキップの有無だけを見て、注記の中身やリンク先の要望の状態は見られない（抑制コメントの理由も検査できない）。Playwright の設定にも、注記を必須にする仕組みは無い。今の `check-usecase-tags.mjs` が既にテストのファイルを静的に読んでいるので、そこに足す
- `findUsecaseTagProblems` に要望の状態の一覧（`Map<ファイル名, 状態>`）を渡す。CLI は `docs/backlog/*.md` の frontmatter の `status` を読む。`e2e/usecases/` で止めるもの：スキップに `backlog` の注記が無い・2つ以上ある、注記の要望が実在しない・完了か見送り、スキップしていないテストの `backlog` の注記、`description` が `docs/backlog/<名前>.md` の形でない

### ページ：`scripts/build-usecase-report.mjs`

- `collectSpecs` が spec ごとに `backlog`（注記の `description`。無ければ null）を持つ
- `runStates`：結果が `skipped` で `backlog` があれば、タグの ID をすべて `skipped`。それ以外は今どおり
- 強さ：落ちた ＞ 手前で止まった ＞ 確認済 ＞ 全スキップ（`skipped` をいちばん弱くする。D5）。テストが無いときの none とは別
- `LABELS` に `skipped: '全スキップ'`。テストの一覧の各テストは、`skipped` なら「（スキップ中：<a href="../backlog/<名前>.html">要望の title</a>）」。CLI の件数の出力に全スキップを足す

### ページ：`scripts/build-trace-report.mjs`

- `STATE_ORDER` を `['failed', 'skipped', 'noresult', 'planned', 'none', 'passed']`、`STATE_LABELS.skipped = '全スキップ'`。UC の `skipped` はそのまま写す（`fromUseCaseState` は手前で止まっただけを落ちたにする）。要素の色（ライト・ダーク）を足す
- smoke・Vitest のスキップはテストなしのまま（D2。Vitest はスコープ外）

### docs の修正

- `docs/process/rules/testing.md`「ユースケースの E2E」：`retries` の項に「直せないときは、直す要望を起こしてスキップにする」、上の書き方、検査が止めるものの一覧を直す（`test.skip` を条件付きに限る）
- `docs/architecture/test-report.md`：「ユースケースとの対応の見方」の表に全スキップ、強さの順。「トレースの見方」の表と悪い順
- `docs/notes/architecture/test-report.md`：D2・D5・D6・D9・D12 の理由
- `docs/backlog/e2e-flaky-skip.md`：状態・プラン
- 体制の進化ログ（`docs/process/evolution/2026-10.md`）：テストのルールの変更

## 4. テスト影響範囲

- `scripts/usecases.test.mjs`・`check-usecase-tags.test.mjs`：`test.skip` を止める既存のテストは、条件付きの形に直して残す
- `scripts/build-usecase-report.test.mjs`：T12（skipped は手前で止まった）は注記の無い場合として残す
- `scripts/build-trace-report.test.mjs`：状態の悪い順のテストに全スキップが入る
- `docs:build`：`check-usecase-tags.mjs` が要望の一覧を読むようになる
- アプリ（`apps/`・`packages/`）のコードと、今の E2E のテストは変えない
