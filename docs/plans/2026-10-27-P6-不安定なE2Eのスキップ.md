# 不安定な E2E を、直す要望へのリンク付きでスキップにする

要望：[不安定な E2E は、いったんスキップにして直す要望を起票する](../backlog/e2e-flaky-skip.md)

状態：プランの AI レビュー済み（2026-10-27。設計整合・運用・テスト網羅の3観点。P0 3件を直した）。D1〜D8 は2026-10-27に人間と確かめた（質問2ラウンド）。AI レビューで D2 の前提（smoke は Biome が止める）が実物では守られないと分かり、人間と確かめ直した（検査で止める）。D9〜D13 は人間が案どおりと確かめ、D14 は「機械で止める」、D15 は「別のライトのブランチ」と人間が決めた（2026-10-27）。D16〜D20 はレビューの指摘から AI が決めた案で、2026-10-27 に人間が承認した（実装順0）。実装順1〜8（実装・テスト・T8 の骨抜きの確かめ12件・T9 のブラウザでの確かめ・docs の修正）は2026-10-27に済んだ。実装順9（実装の AI レビュー）も済み（9章）。次は手順7（人間レビュー）。

## 1. 概要

ユースケースの E2E（`apps/web/e2e/usecases/`）で、たまに落ちるテストを、直す要望（`docs/backlog/…`）へのリンクを添えてテスト単位でスキップにできるようにする。リンクの無いスキップ・実在しない要望・開いていない要望（完了・見送りなど）へのリンク・要望の `trace` にスキップしたテストの UC が無いものは検査で止める。`e2e/usecases/` の外（smoke）のスキップは、抑制コメントがあっても検査で止める。

ユースケースの結果のページとトレースのページでは、UC を確かめるテストが全部スキップのときだけ UC を「全スキップ」と出し（一部だけスキップなら、スキップでないテストの状態で出す）、テストの一覧に各テストの「スキップ中」と直す要望へのリンクを出す。

`retries` は足さない方針（[テストのルール](../process/rules/testing.md)「ユースケースの E2E」）を保ったまま、不安定なテストで PR の CI が止まり続けないようにする。

## 2. 背景

- 2026-10-18、[ユースケースと E2E の結果を紐づける](../backlog/usecase-e2e-report.md)の人間レビュー（D9：`retries` を足さない）で出た要望。2026-10-26、P5 の実装中に `gm-session.test.ts` が `Failed to load resource: net::ERR_FAILED` で1度落ちた（単独で流すと通る）
- 2026-10-27、P5 の人間レビューで「スキップだけの UC が『落ちた』と出る。『全スキップ』と出るようにしたい」。ユースケースの結果のページとトレースのページの両方で同じ状態にする
- 正式仕様・ルール：[テストのルール](../process/rules/testing.md)「ユースケースの E2E」「骨抜き禁止」（変える：スキップの書き方・入れ方と検査）、[アーキテクチャのルール](../process/rules/architecture.md)「依存の向き」（変える：scripts から docs/backlog への向き）、[テストレポート](../architecture/test-report.md)「ユースケースとの対応の見方」「トレースの見方」（変える：状態の表）、[デザイナーノート](../notes/architecture/test-report.md)（決めた理由を足す）、[要望の書き方](../backlog/index.md)（変えない）。ゲームの仕様（`docs/cartagraph/`）は変えない
- 今の作り（読んで確かめた。プランの AI レビューで Playwright 1.63.0 の実装も読んだ）
  - `scripts/usecases.mjs` の `parseTestFile` が `test.skip`・`test.fixme`・`test.step.skip` などを `forbidden` に拾い、`scripts/check-usecase-tags.mjs` が `e2e/usecases/` でだけ止める（全 E2E に当たる `commonProblems` はスキップを見ない）。`testCount` と `readTags` の持ち主の判定、題の中のタグ（`titleTagged`）は `test(` と `test.describe(` だけを見る（`test.skip(` は数えない）
  - Biome の `noSkippedTests`（`biome.json`。e2e も対象）が `.skip` をコミット前に止めるが、抑制コメント1行で通る（テストのルール「骨抜き禁止」は抑制を認めている）。今の `apps/web/e2e/` にスキップは0件
  - `scripts/build-usecase-report.mjs`：`runStates` は結果の `status` が `skipped` のとき「手前で止まった」のままにする（serial の手前の失敗などで走らなかったテスト）。`results` が空のときも手前で止まった。UC の状態は 落ちた ＞ 手前で止まった ＞ 通った の強い順。CLI は入力・出力のパスが固定で、テストから呼べない
  - `scripts/build-trace-report.mjs`：UC の状態は usecase-report の状態を写し（`fromUseCaseState`）、手前で止まったを落ちたにする。状態の悪い順は `STATE_ORDER`（落ちた ＞ 結果なし ＞ 未実装 ＞ テストなし ＞ 確認済）。完了の要望で確認済でなければ未達（`unreached`）を付ける。smoke の spec は全部スキップならテストなし（`specState`）、Vitest のスキップのみもテストなし。CLI は `--e2e`・`--out` を受け取る
  - 要望の frontmatter の読み手 `frontmatterValue`・`readBacklog` は `build-trace-report.mjs` にあり、`branch-id.mjs` が動的 import で使う。`build-trace-report.mjs` は `build-usecase-report.mjs` を import するので、逆向きに import すると循環になる（`biome.json` の `noImportCycles`）。`readBacklog` は `trace` の無い要望で例外を投げる
  - `scripts/report-html.mjs` の `.badge.skipped` は手前で止まったと同じ色
  - Playwright 1.63.0：`test.skip(title, details, body)` で宣言でき、`details.annotation` は1つのオブジェクトか配列。宣言のスキップでは Playwright が `{ type: 'skip' }` の注記を自動で後ろに足す。JSON のレポートでは、注記は `tests[].annotations` と `results[].annotations` の両方に載り、宣言のスキップでも `results` は空にならず `status: "skipped"` の結果が1件ある。タグは `specs[].tags`（`@` を外す）。注記の `location` は絶対パス
  - `@PL-2` は `gm-session.test.ts` と `scenario-authoring.test.ts` の両方に付いている。`gm-session.test.ts` だけをスキップすると、PL-1 は全スキップ、PL-2 は確認済になる（D5）

### 書き方（テストのルール「ユースケースの E2E」に置く）

```ts
// biome-ignore lint/suspicious/noSkippedTests: 不安定なため。直す要望は annotation
test.skip('GM が描写を書いて…', {
  tag: ['@PL-1', '@PL-2'],
  annotation: { type: 'backlog', description: 'docs/backlog/<直す要望>.md' },
}, async ({ page }) => { /* 本文は消さずに残す */ });
```

- 本文は消さない（直したら `test.skip` を `test` に戻し、注記と抑制コメントを消すだけにする）
- スキップは別のブランチで入れ、同じブランチで直す要望を起こす（状態は未着手でよい。`trace.usecases` にスキップしたテストのタグの UC を書く）（D15）
- 直す要望を完了・見送りにするときは、先にスキップを外す（見送りでテストを直さないなら、テストを消す）。外し忘れは `docs:build` が止める

### 検査：`scripts/usecases.mjs`・`scripts/check-usecase-tags.mjs`

- `parseTestFile` に足す：`skips`（宣言の `test.skip(` の数）、`backlogs`（`type: 'backlog'` の注記の `description` の配列と、それがスキップしたテストのものか）、`unreadableAnnotations`（直書きでない `annotation`・`type`・`description`）、`danglingSkipSuppressions`（D19）。宣言の `test.skip(` は `testCount` に数え、`readTags` の持ち主と `titleTagged` にも入れる。`forbidden` からは種類が `test.skip` で最初の引数が直書きの文字列のものだけを外す（`test.describe.skip('題', …)`・`test.fixme('題', …)`・`test.step.skip('…')`・最初の引数が文字列でない `test.skip(` は残す）。複数行にまたがる details・Biome の整形で題が次の行に回る形も読む
- 既存のツールで書けないか：Biome の `noSkippedTests` はスキップの有無だけを見る。Biome の GritQL プラグイン（`scripts/biome/*.grit`）なら「`test.skip` に `type: 'backlog'` の注記が要る」という構文の形は書けるが、リンク先の要望の状態と `trace` は見られず、どのみち自前の検査が要る。検査を2か所に分けないため、既にテストのファイルを静的に読んでいる `check-usecase-tags.mjs` に足す。Playwright の設定にも、注記を必須にする仕組みは無い
- `findUsecaseTagProblems` に要望の一覧（`readBacklog` の `{ name, status, trace }`）を渡す（渡さないときは要望を読まず、`backlog` の注記があれば「要望の一覧が無い」で止める）。`e2e/usecases/` で止めるもの：スキップに `backlog` の注記が無い・2つ以上ある、注記の要望が実在しない・開いていない（D16）、要望の `trace.usecases` にスキップしたテストのタグの UC が無い（D14）、スキップしていないテストの `backlog` の注記、`description` が `docs/backlog/<名前>.md`（`<名前>` は `/`・`\` を含まず、`index` でない）の形でない、直書きでない注記（D10）、抑制コメントの消し忘れ（D19）。全 E2E（`commonProblems`）で止めるもの：`e2e/usecases/` の外の `test.skip`・`test.fixme`・`test.describe.skip`・`backlog` の注記（D2）
- 要望を閉じて止まったときの誤りの文に、スキップを外す（`test.skip` → `test`、注記と抑制コメントを消す）かテストを消すことと、そのテストのファイルを出す（閉じるのはドキュメントだけのコミットを書く人なので、テストのルールまで辿らずに分かるように）
- 成功のメッセージに「スキップ中 n 件」（D18）

### ページ：`scripts/build-usecase-report.mjs`

- `collectSpecs` が spec ごとに `backlog`（`type: 'backlog'` の注記の `description`。`tests[]` と `results[]` の両方から探す。無ければ null）を持つ
- `runStates`：結果の `status` が `skipped` で `backlog` があれば、タグの ID をすべて `skipped`。それ以外は今どおり（D12）
- 強さ：落ちた ＞ 手前で止まった ＞ 確認済 ＞ 全スキップ（`skipped` をいちばん弱くする。D5）。テストが無いときの none とは別。並びの順に依らない
- `LABELS` に `skipped: '全スキップ'`。テストの一覧の各テストは、`skipped` なら「スキップ中（<a href="../backlog/<名前>.html">要望の title</a>）」（`LABELS` をそのまま使わない。D7）。要望の title は D13
- `report-html.mjs` の `.badge.skipped` の色を手前で止まったと分ける（ライト・ダーク）
- 先頭の案内にスキップ中のテストの数と直す要望へのリンク、CLI の件数に全スキップ（D18）。`main({ e2eFile, out })` と `--e2e`・`--out`（D20）

### ページ：`scripts/build-trace-report.mjs`

- `STATE_ORDER` を `['failed', 'skipped', 'noresult', 'planned', 'none', 'passed']`、`STATE_LABELS.skipped = '全スキップ'`。UC の `skipped` はそのまま写す（`fromUseCaseState` は手前で止まっただけを落ちたにする）。要素の色（ライト・ダーク）を足す。テストのファイルの要素も UC から写すので全スキップになる
- 先頭の案内（`noticeHtml`）にスキップ中のテストの数と直す要望へのリンク（D18）
- smoke・Vitest のスキップはテストなしのまま（D2 で smoke のスキップは検査が止める。Vitest はスコープ外）
- `frontmatterValue`・`readBacklog` は `trace.mjs` から import する（D17）

## 10. PR 下書き

### 課題

`retries` を足さない方針（不安定なテストが CI を通り、ページでも「確認済」に見えるため）のもとでは、たまに落ちる E2E があると PR の CI がそのたびに止まる。2026-10-26 には `gm-session.test.ts` が `ERR_FAILED` で1度落ちた。また、スキップだけの UC がユースケースの結果のページとトレースのページで「落ちた」と出ていた（P5 の人間レビュー）。要望：[不安定な E2E は、いったんスキップにして直す要望を起票する](../backlog/e2e-flaky-skip.md)。

### 解決策

- ユースケースの E2E（`apps/web/e2e/usecases/`）に限って、直す要望へのリンクを付けた宣言の形のスキップを通す：`test.skip('題', { tag, annotation: { type: 'backlog', description: 'docs/backlog/<名前>.md' } }, fn)`。書き方と入れ方（落ちた機能の PR には入れず、別のブランチで main へ早送りで入れる）は[テストのルール](../process/rules/testing.md)「不安定なテストのスキップ」
- `check-usecase-tags.mjs`（`docs:build`）が次を止める：リンクの無いスキップ、実在しない要望・開いていない要望（未着手・検討中・進行中・判断待ちでない）へのリンク、要望の `trace.usecases` にスキップしたテストの UC が無いもの、スキップを外した後の注記と抑制コメントの消し忘れ、smoke のスキップ（抑制コメントがあっても止める）
- ユースケースの結果のページは、UC を確かめるテストが全部スキップのときだけ「全スキップ」（一部だけならスキップでないテストの状態）、テストの一覧に「スキップ中」と直す要望へのリンク、先頭にスキップ中の数を出す。トレースのページでは全スキップを「落ちた」の次に悪い状態にする（完了の要望なら未達）
- 要望の frontmatter の読み手を `scripts/trace.mjs` に1つにまとめた（循環を避けるため）。アプリ（`apps/`・`packages/`）と今の E2E のテストは変えていない
