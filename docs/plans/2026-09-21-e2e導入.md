# プラン：E2E（Playwright）の導入とGitHub Pagesでのレポート公開

書式は `docs/process/index.md` の「プランドキュメントの8項目」。

## 1. 概要

Playwright を `apps/web` に導入し、`routes.ts`（サイトマップの唯一の情報源）を巡回して全20ルートを実ブラウザで開き、フルページスクリーンショット付きのHTMLレポートを生成する。レポートはGitHub Pages（`docs/.vitepress/dist/e2e-report/`）に公開し、ローカルでアプリを動かさなくても `https://hibohiboo.github.io/CarTaGraphFantasy/e2e-report/` から見た目を確認できるようにする。

## 2. 背景

- `docs/plans/2026-09-16-dev-process-foundation.md` のスコープ外だったE2E導入を、決定事項5（2026-09-21）で前倒しした。理由はスクリーンショットをGitHub Pagesから確認できるようにしたいという要望
- 既存の `apps/web/src/test/pages.test.tsx` はMSWのnodeサーバー上で「描画できる」ことだけを検証しており（`docs/process/rules/review.md`にも明記の限界）、実ブラウザでの見た目・崩れは確認できていない。E2Eはこのギャップを埋める
- GitHub Pagesは `actions/deploy-pages` で運用しており、**1サイト1アーティファクト**という制約がある（`scripts/copy-web-to-pages.mjs` のコメント参照）。E2Eレポートも独立したデプロイ先を持てず、既存の `docs/.vitepress/dist/` 配下にコピーしてから同じアーティファクトとして公開する必要がある
- 関連する未解決論点はない（UI試作の見た目そのものは仕様ではなく実装の確認事項のため）

## 3. 詳細設計

### スコープと巡回方式

- `apps/web/src/app/routes.ts` の `routes` 配列を1件ずつ巡回する。動的ルート（`:sessionId` 等を含む）は `route.example` を使い、静的ルートは `route.path` をそのまま使う。20ルート全件に `example` または `path` が揃っていることを確認済み
- HashRouterのため、実際のナビゲーションは `/#${path}` の形になる
- 各ルートについて：(1) 該当URLへ遷移し、(2) フルページスクリーンショットを撮り、(3) 下記の合否判定を行う

### 合否判定（アサーション）

汎用の3点チェックを全ルート共通で行う（`route.title` と実際の見出しの一致は見ない。動的ページはタイトルが`route.title`と一致しない場合があり、壊れやすいチェックになるため）。

1. ページ遷移が例外なく完了する
2. 画面内にエラー表示（`ErrorNote` が出す `role="alert"`）が無い
3. ブラウザの `console.error`・ページエラー（`pageerror`）が発生していない

### 実行対象サーバー

- `vite preview`（本番ビルド相当）に対して実行する。GitHub Pagesの実際の成果物に近い状態で確認し、base path起因の崩れも検出できるため
- **E2E用のビルドは `WEB_BASE` を設定しない**（base=`/`のデフォルトビルド）。GitHub Pages用のビルド（`WEB_BASE=/CarTaGraphFantasy/app/`）とは別に、E2E専用のビルドを作る。これにより、CIとdeployで同じコマンド・同じbase pathでE2Eを実行でき、base path起因の分岐を避けられる
- `playwright.config.ts` の `webServer` に `pnpm build && pnpm preview` を指定し、`playwright test` 単体でビルド・起動・後片付けまで完結させる（`reuseExistingServer: !process.env.CI`）。**CI・deploy側では明示的な `pnpm web:build` ステップを別途追加しない**（`webServer` が自己完結してビルドするため、二重ビルドを避ける）。既存の `pnpm run build:pages`（Pages公開用、`WEB_BASE`あり）とはステップが別なので、env指定を分ければ競合しない

### ブラウザ

- Chromiumのみ。CI時間を優先する。複数ブラウザが要る場面が出たら候補として追加する

### ファイル配置

- `apps/web/playwright.config.ts`（monorepoの他パッケージ同様、`apps/web/`に閉じる）。設定項目は最低限次を明示する：
  - `testDir: './e2e'`、`testMatch: '**/*.test.ts'`（既定の`testDir`は`./tests`、既定の`testMatch`は`*.spec.ts`系なので、どちらも明示しないと `apps/web/e2e/smoke.test.ts` が発見されない）
  - `use: { screenshot: { mode: 'on', fullPage: true } }`（既定は`'off'`。これを明示しないと成功したルートのスクリーンショットがレポートに載らず、概要の目的を達成できない）
  - `reporter: [['html', { outputFolder: 'playwright-report', open: 'never' }]]`
  - `webServer: { command: 'pnpm build && pnpm preview', url: 'http://localhost:4173', reuseExistingServer: !process.env.CI }`
- `apps/web/e2e/smoke.test.ts`（`routes.ts` を巡回する1ファイル。ルートごとにファイルを分けない）
- `apps/web/package.json` に `"e2e": "playwright test"` を追加。ルートの `package.json` に `"web:e2e": "pnpm --filter @cartagraph/web e2e"` を追加
- `apps/web/vite.config.ts` のVitest設定に `exclude: [...configDefaults.exclude, '**/e2e/**']` を追加する。Vitestのデフォルトincludeパターン（`**/*.{test,spec}.?(c|m)[jt]s?(x)`）は `.test.ts`・`.spec.ts` のどちらも拾うため、拡張子をどちらにしてもこの除外設定は必須。ファイル名は `.test.ts` に揃える（プロジェクトで馴染みがあるため）
- `@playwright/test` を `apps/web` の `devDependencies` に追加し、`playwright install --with-deps chromium` をCI・deployの両方に追加する
- `.gitignore` に `apps/web/playwright-report/`・`apps/web/test-results/` を追加する（Playwrightが既定で生成し、コミット対象ではない）

### CI・deployへの組み込み（非対称構成）

既存のC1決定（「型検査・テストはCIでゲート、デプロイはテストの成否を待たずに走る」）と同じ非対称構成に揃える。ビルドは `webServer` に任せ、CI・deployのどちらにも明示的な `pnpm web:build` ステップは追加しない（二重ビルドを避けるため）。

- **`ci.yml`（PRをブロックする）** — `playwright install --with-deps chromium` → `pnpm web:e2e` を追加。失敗したらCIが赤くなり、C6のPRフローでマージがブロックされる。レポートの公開は行わない
- **`deploy.yml`（レポートを公開する。mainへのpush時のみ）** — 既存の `pnpm run build:pages`（Pages公開用ビルド、`WEB_BASE`あり）のステップとは別に、`playwright install --with-deps chromium` → `pnpm web:e2e` を実行し、**失敗してもデプロイを止めない**（このステップにのみ `continue-on-error: true`。失敗した実行の方がむしろレポートで原因を確認したいため）。生成された `apps/web/playwright-report/` を新しいスクリプト `scripts/copy-e2e-report-to-pages.mjs` で `docs/.vitepress/dist/e2e-report/` へコピーしてから、既存の `upload-pages-artifact` へ渡す。コピー処理は `if: always()` でE2Eの成否に関わらず実行する。ただし `copy-web-to-pages.mjs`（ソース無しなら`process.exit(1)`）とは違い、**ソース（`apps/web/playwright-report/`）が存在しない場合は警告を出して正常終了（exit 0）する**——`webServer`の起動自体が失敗してレポートが1つも生成されないケースで、`if: always()`のこのコピーステップがジョブ全体を落とさないようにするため

## 4. テスト影響範囲

- 既存のVitestテスト（64件）・型検査・lint・docsビルドへの影響なし。Vitestのexclude追加により、`apps/web/e2e/` 配下がVitestの対象から外れることを確認する

## 5. 新規テストケース

- `apps/web/e2e/smoke.test.ts`：`routes.ts` の20ルート全件について、遷移成功・`role="alert"`が無いこと・console error/pageerrorが発生しないことを検証する（正常系のみ。異常系はMSWのモックデータ自体が固定のため対象外）
- 境界値・異常系はスコープ外（8.参照）

## 6. 実装順

1. `apps/web` に `@playwright/test` を追加し、`playwright.config.ts` を書く（`testDir`・`testMatch`・`use.screenshot`・`reporter`・`webServer` を明示。詳細設計3.参照）
2. `apps/web/vite.config.ts` のVitest設定に `exclude` を追加し、`pnpm web:test` がE2Eファイルを拾わないことを確認する
3. `.gitignore` に `apps/web/playwright-report/`・`apps/web/test-results/` を追加する
4. `apps/web/e2e/smoke.test.ts` を書く。`routes.ts` を巡回するループ＋3点アサーション
5. ローカルで `pnpm web:e2e` を実行し、20ルート全件が green になることを確認する（既存の20ルートは `pages.test.tsx` で描画確認済みのため、基本的に green になるはず）。`playwright-report/index.html` を開き、各ルートのスクリーンショットが添付されていることを確認する
6. `scripts/copy-e2e-report-to-pages.mjs` を書く（ソース不在時は警告して正常終了する点が `copy-web-to-pages.mjs` との違い。詳細設計参照）
7. `ci.yml` に `playwright install --with-deps chromium` → `web:e2e` を追加
8. `deploy.yml` に同様のステップ（`continue-on-error: true`）とレポートのコピーステップ（`if: always()`）を追加
9. `docs/process/rules/testing.md` のE2E行（「未導入│─│─│バックエンド着手時にPlaywrightを検討」）を、今回導入した内容（対象・実行タイミング・レポート公開先）に更新する。このファイルは `apps/**/*.test.*` に適用されるルールであり、`apps/web/e2e/smoke.test.ts` はこのパターンに合致するため、実装後も「未導入」のままだとSSOTと実装が矛盾する
10. `docs/architecture/web-app.md` の「コマンド」節に `web:e2e` を追加し、公開先一覧に `https://hibohiboo.github.io/CarTaGraphFantasy/e2e-report/` を追加する
11. `docs/process/evolution.md` にE2E導入の候補一覧の行を `[x]` にし、採用済みへ記録する
12. ブランチ→PRで実施（C6）。レポート公開は人間がマージ後にGitHub Pagesで実際に確認する

全タスクは軽いモデルでも実行できる定型作業（既存パターンの横展開）。

## 7. コミット前テスト実行

```sh
pnpm web:typecheck && pnpm web:test && pnpm docs:build
```

E2E（`pnpm web:e2e`）はブラウザの起動を伴い重いため、`.githooks/pre-push` には追加せず、CIのみで実行する（詳細設計「CI・deployへの組み込み」参照）。手元で確認したい場合は `pnpm web:e2e` を個別に実行する。

## 8. スコープ外

- Chromium以外のブラウザ（Firefox・WebKit）
- 深いインタラクションシナリオ（提案の裁定、カード追加等）のE2E化。既存の `pages.test.tsx`（MSW nodeサーバー）に任せる
- ビジュアルリグレッション（スクリーンショットの差分比較）。今回はレポートを人間が目視確認する用途に留める
- モバイルビューポートでの確認
- `route.title` と実際の画面の見出しの一致チェック（動的ページでは意味を持たないため見送り。3.参照）
