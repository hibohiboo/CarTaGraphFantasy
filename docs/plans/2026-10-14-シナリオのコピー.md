# シナリオの下書きの API を分ける（C3：シナリオのコピー）

要望：[シナリオの下書きの API を分ける](../backlog/scenario-draft-api.md)（[ロードマップ](../roadmap.md#backend-1on1) backend-1on1 の下ごしらえ）。前のサイクル：[C1 下書きと公開版](2026-10-11-シナリオの下書きのAPI.md)（PR #24）、[C2 セッションの独立](2026-10-14-セッションの独立.md)（PR #25）

## 1. 概要

他人のシナリオ（と自分の公開済みのシナリオ）の最新の公開版を、自分の下書きとしてコピーできるようにする。コピーは新しい id・自分が作者・公開版なしの下書きで、題名は「〇〇のコピー」。どの版から作ったかを `copiedFrom`（親のシナリオ id と版番号）に覚えさせ、シナリオ編集・GM のシナリオ詳細に「〇〇（作者：△△）のコピー」と親への導線を出す。他人のシナリオは読むだけ、という C1 の決め（D7）に、直したいときの道を足す。

## 2. 背景

- 正式仕様：[シナリオの構造とセッション開始までの流れ](../cartagraph/scenario-flow.md)「シナリオの公開」。「読めるのは公開した版」の項はあるが、コピーは書いていない
- 未解決論点：[正史グラフ・比較体験の「原型」と、シナリオの版・コピーの対応](../open-questions.md)。このサイクルは親を記録するだけで、コピーが親と同じ原型か別の原型かは決めない（論点のまま残す）
- 今の作り
  - 他人のシナリオを開くと、`useEditableScenario`（`entities/scenario/api/queries.ts`）が公開版を読み取り専用で見せる（`CreatorScenarioEditPage.tsx:78` の読み取り専用の分岐、90行目の「製作者でないため編集できません」）。シーン編集も同じ
  - シナリオの作成は `POST /scenarios`（題名だけ。`handlers.ts`）。下書きは `db.drafts`、公開版は `db.scenarios`、版の履歴は `db.versions`（C2）。サーバーが決める項目は `id`・`authorId`・`authorName`・`libraryStatus`・`updatedAt`（`PATCH /scenarios/:id/draft`）
  - `Scenario`（`packages/domain/src/scenario/model.ts`）が JSON ファイルの形で、下書きの形 `scenarioDraftSchema`（`packages/schemas/src/scenarios/response.ts`）はそれを緩めたもの

## 3. 詳細設計

### 決定事項（人間が決定）

- **D1 コピー元は、公開版のあるシナリオの最新の公開版**（2026-10-14） — 他人のシナリオも自分のシナリオもコピーできる。シナリオ集から外したシナリオも含む。公開版の無い下書きと、古い版はコピーできない
- **D2 入口はシナリオ編集の「コピーして編集」** — 押すとコピーを作り、そのコピーのシナリオ編集へ移る。GM の画面（シナリオ一覧・詳細）には置かない
- **D3 コピーは別のシナリオで、題名以外は写す** — 新しい id・作者は自分・公開版なしの下書き・題名は「〇〇のコピー」。結末タグ・前提タグ・再挑戦不可・初期装備もそのまま写す。ゲーム上の混線（コピーを遊ぶと本物と同じ結末タグを得る）を防ぐ仕組みは入れない。直すのは製作者
- **D4 親は `copiedFrom: { scenarioId, version }` で持つ** — `Scenario` に任意の項目として足し、JSON ファイルにも書く。直接の親だけを持つ（孫は親を辿って得る）。親が外されても、公開し直されても、記録は変わらない
- **D5 親への導線を出す** — シナリオ編集の見出しの近くに1行「〇〇（作者：△△）のコピー」と親への導線を出す。親が読めないときは名前を出さず導線も出さない。子を辿る一覧は作らない
- **D6 原型・正史グラフとの対応は決めない**（未解決論点のまま）

- **G3 API（`packages/schemas/src/scenarios/endpoints.ts`）**

| メソッド・パス | 振る舞い | 応答 |
|---|---|---|
| `POST /scenarios/:id/copy` | 公開版のあるシナリオの最新の公開版を、自分の下書きにコピーする。本文なし。誰でもコピーできる（外したシナリオも） | 201 `ScenarioDraftView`、404（公開版が無い）、422（デモ・テスト専用のシナリオ） |

## 5. 新規テストケース

domain

- **T1d スキーマ**：`copiedFrom` は省ける。`{ scenarioId, version: 1 }` で通る。`version` が 0・-1・1.5・文字列、`scenarioId` が空文字、知らないキーは誤り。`null` は誤り
- **T2d ファイル**：`toScenarioFile` と `safeParseScenarioFile` の往復で `copiedFrom` が残る。`findScenarioRefErrors` は、存在しないシナリオを指す `copiedFrom` を誤りにしない（`refs.test.ts`）

mocks の単体（`mocks/scenarioCopy.test.ts`）

- **T3m `copyOf`**：元のオブジェクトを書き換えない。題名は「…のコピー」（元が既に「…のコピー」なら「…のコピーのコピー」）。元の `libraryStatus` が published・draft のどちらでも draft。元が `copiedFrom` を持っていても、元の `scenarioId`・`version` に差し替える。`$comment` はそのまま写る。2回コピーしたものを片方に足してももう片方は変わらない（深い複製）。画像（`portraitUrl`）は残る

web（MSW）

- **T1 他人のシナリオのコピー**：灰色館（他人の公開版）をコピーすると 201。新しい id・作者は自分・題名「〇〇のコピー」・`publication: 'none'`・`changed: false`・`copiedFrom: { scenarioId: 'sc-gray-mansion', version: 1 }`。中身（deck・endings・結末タグ・前提タグ・再挑戦不可・`soloStarter`）は元と `toEqual`。`$comment` は無い。元の公開版・版の履歴は変わらない
- **T2 コピーは独立**：コピーの下書きを保存しても元は変わらない。コピーを公開するとシナリオ集に載り（`GET /scenarios`）、公開版に `copiedFrom` が写り、版1の `copiedFrom` も同じ。コピーは `GET /scenario-drafts` に出る。元の `GET /scenarios` の一覧は1件のまま
- **T3 コピーできる元**：自分の公開版（`sc-galleon`）はコピーできる。シナリオ集から外した公開版も、外した後でコピーできる（コピー元の `libraryStatus` はコピーに引き継がない＝コピーは下書きのみ）。最新の公開版をコピーする（元を公開し直して版2にした後は `copiedFrom.version` が 2 で、中身は版2。版1の値ではない）。元の下書きに未公開の変更があっても、コピーに写るのは公開版（下書きの変更は写らず、`copiedFrom.version` は公開版の版）。画像を持つ公開版は、コピーにも画像が残る
- **T4 コピーできない元**：公開版の無い下書き（`sc-draft-well`）・どこにも無い id は 404。デモ・テスト専用のシナリオ（`sc-village-always-win`）は 422。どれも何も増えない（`GET /scenario-drafts` の数）。公開版のない（未公開の）コピーのコピーは 404
- **T4b 親の記録は変わらない（D4）**：コピーを作った後、親を公開し直して版2にしても、シナリオ集から外しても、コピーの `copiedFrom` は `{ version: 1 }` のまま。親を外した後も、親の版1は読める
- **T5 孫**：コピーを公開し、そのコピーをコピーすると、`copiedFrom` は直接の親（最初のコピー）で、祖先は持たない
- **T6 サーバーが決める**：`PATCH /draft` で `copiedFrom` に別の親・`null`・不正な形（`{ version: 0 }`）を書いても、キーを送らなくても、200 で変わらない（422 にならない）。親のない下書き（`POST /scenarios` で作ったもの）に `copiedFrom` を付けようとしても付かない。公開すると `copiedFrom` が公開版・版1・保存先に渡るシナリオ（偽の保存先 `written`）に写る
- **T7 id**：続けて2回コピーしても別の id。使用中の id（下書きだけの id・公開版だけの id）は飛ばす（`POST /scenarios` の既存の衝突のテストの組み立て〔`nextFreeId`〕を流用する）

画面

- **T8 他人のシナリオからのコピー**：灰色館を開き（読み取り専用）「コピーして編集」を押すと、コピーのシナリオ編集へ移る。題名が「…のコピー」で、編集できる状態（保存ボタンがある）、状態は「下書きのみ」。見出しの近くに「灰色館の一夜（作者：琴音）のコピー」とリンクが出て、リンクを押すと元の読み取り専用画面へ戻る（移り先にしか無い要素〔製作者でない案内文〕を待つ）。シナリオ管理の一覧にコピーが出る。移った後のコンソールに誤りが出ない
- **T8b コピーの失敗と二重押し**：`server.use` で `POST /scenarios/:id/copy` を 404 にすると、誤りが出て移らず、ボタンがまた押せる。遅い応答で2回押しても呼ばれるのは1回で、コピーは1件だけ増える。未保存の編集があっても押せて、コピーに写るのは公開版
- **T9 自分のシナリオ**：公開版のある自分のシナリオ（`sc-galleon`）の編集画面にも「コピーして編集」が出る。自分で外した後（`unpublish`）も出る。公開版が無い自分の下書き（`sc-draft-well`）には出ない
- **T9b 置かない所（D2）**：GM のシナリオ一覧・シナリオのカスタマイズと募集（親のあるコピーでも）・他人のシーン編集・自分のシーン編集に「コピーして編集」が無い
- **T10 GM のシナリオ詳細（カスタマイズと募集）**：コピーを公開した後の画面に、親の1行が出る。親のあるシナリオだけ。親の題名は、親を改題して公開し直しても、コピーした版（版1）の題名のまま
- **T11 親が読めない**：親の版が読めない（404・`HttpResponse.error()`）ときと、読み込み中は、親の1行を出さず、画面は壊れない（親の題名が取れないのに「…のコピー」だけは出さない）。組み立ては、モックの `server.use` で `GET /scenarios/:id/versions/:version` を差し替える。親を外した後は1行が出る
