# アイデアから実装までをたどるトレースのページ

要望：[アイデアから実装までをたどれるようにする](../backlog/trace-report.md)

状態：実装済み（2026-10-26）。D1〜D8 は2026-10-26に人間と確かめた（質問2ラウンド）。D9〜D28 は2026-10-26に人間が「この決定でよい」と確かめた。手順2〜3（プランの AI レビュー）は2026-10-26に済み、P0・P1 を反映した（9章。P0 の直し方は人間が了承）。手順4〜6（実装・テスト・T16・T17・実装の AI レビュー）は2026-10-26に済んだ（10章）。次は手順7（人間レビュー）。

## 1. 概要

RDRA の層（アクター → 要望 → ユースケース → 画面・ルールの節 → テスト）と DDD の集約・イベントを、左から右へ層ごとの列に並べた1枚の図のページを作る。要素をクリックすると、そこから上流（なぜ作るか）と下流（どこで確かめているか、最新の結果はどうか）へたどれる要素と線だけが濃くなる。要望ごとに「届き具合」（つなぐ先の状態のうち、いちばん悪いもの）を色で出し、アイデアが実装・テストまで届いているかを見られるようにする。

つながりは書き写さない。要望の先頭（frontmatter）に新しく `trace` を書くほかは、既にある文書（[中核のユースケース](../architecture/use-cases.md)・[画面一覧と導線](../screens/index.md)・[集約とドメインイベント](../architecture/aggregates.md)・ルールのページ）・ルート定義・テストの結果から、デプロイ時に組み立てる。ページは GitHub Pages の `/CarTaGraphFantasy/trace-report/` に載せる（[テストレポート](../architecture/test-report.md)の仲間）。

### 書き方（D9〜D11）

```yaml
trace:
  usecases: [SC-6, SC-7]
  screens: [/creator/scenarios/:scenarioId, GM のホーム]
  rules: [scenario-flow/シナリオの公開]
```

```yaml
trace:
  none: 開発の基盤（E2E の導入）
```

- 3つのリストは、それぞれ省略してよいが、全部が無い・全部が空は不可
- リストはフロー形式（`[a, b]`）に限る。`none` とリストは一緒に書けない
- `#` と引用符は書けない。`none` の理由は空にできない（D28）

### 検査（D22）：`scripts/check-trace.mjs`

### ページの組み立て：`scripts/build-trace-report.mjs`

- 入力：要望（`docs/backlog/`）、`use-cases.md`、`screens/index.md`、`routes.ts`、`aggregates.md`、ルールのページと対象外の一覧、Playwright の JSON、各パッケージの Vitest の JSON、ビルド結果の HTML（アンカー。無ければページへのリンク）

### 図（D5・D13・D17）

- 列ごとに縦に要素を並べる。並びは、要望は状態の悪い順→名前、UC は表の順、画面は `routes.ts` の順（まだ無い画面は最後）、節はルールのページの順、テストはファイル名順、集約・イベントは表の順
- 線は列のあいだの曲線（SVG の path）。列を飛ばす線（UC → 集約）もそのまま引く
- 色：要素の塗りが状態（D15）、枠がコンテキスト（UC の業務領域・集約のコンテキスト）。色だけに頼らず、状態の文字（「落ちた」など）も要素に出す
- 幅の狭い画面では、図を横にスクロールさせる（パネルは図の下に回す）
- `reportPage` の本文の幅の上限（`max-width:1000px`）は、このページだけ `extraCss` で広げる（7列の図が窮屈になるため）

## 11. PR 下書き

### 課題

アイデア（要望）が実装・テストまで届いているかを見る手段が無かった。ユースケース・ルールの節ごとの結果のページはあるが、要望から先をたどれず、要望・ユースケース・画面のつながりはどこにも書かれていなかった。要望：[アイデアから実装までをたどれるようにする](../backlog/trace-report.md)。

### 解決策

- 要望の先頭（frontmatter）に `trace`（つなぐ先のユースケース・画面・ルールの節。無ければ `none: <理由>`）を全件必須で書く。ユースケースの表（中核の2表）に「画面」の列を足す。書き忘れ・実在しないつなぎ先・列の欠けは `pnpm docs:build` が止める（`scripts/check-trace.mjs`）
- 要望・ユースケース・画面・ルールの節・テスト・集約・イベントを層ごとの列に並べた図のページを、デプロイ時に作って Pages の `/trace-report/` に載せる（`scripts/build-trace-report.mjs`）。押した要素の上流・下流だけが濃くなる。要望ごとの届き具合（つなぎ先のうちいちばん悪い状態）と、完了なのに確認済でない「未達」を出す
- 状態の計算は usecase-report・rule-test-report の関数を共用する。自前の SVG と素の JS で描き、ライブラリは足さない。アプリ（`apps/`・`packages/`）は変えていない
