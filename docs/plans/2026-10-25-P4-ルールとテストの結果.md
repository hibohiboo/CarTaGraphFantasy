# ルールのページとテストの結果を紐づけるページ

要望：[ルールのページとテストの結果を紐づける](../backlog/rule-test-report.md)

状態：プラン作成済み（2026-10-25）。D1〜D5 は2026-10-25に人間と確かめた（質問2ラウンド）。D6〜D14 は AI が決めた（プランのレビューと人間レビューで確かめる）。次は手順2〜3（プランの AI レビュー）、等級は強い。

## 1. 概要

ルールのページ（`docs/cartagraph/`）の節（`##`・`###`）ごとに、それを確かめる Vitest のテストと最新の結果（確認済・落ちた・スキップのみ・テストなし・対象外・結果なし）を一覧にするページを作る。紐づけは Vitest 4.1 のテストのタグ（`{ tags: ['rule:check/判定の基本メカニズム'] }`）でテストの側に書き、タグの一覧は仕様のページの見出しから組み立てて Vitest の設定に渡す（見出しに無いタグを付けたテストは Vitest が実行時に落とす）。デプロイが Vitest の後に HTML を組み立て、GitHub Pages の `/rule-test-report/` に載せる。あわせて、`packages/domain` のテストに一通りタグを付ける。

## 2. 背景

- 2026-10-19、人間の要望。[ユースケースと E2E の結果](2026-10-18-P2-ユースケースとE2Eの結果.md)に続けて、ルールのどこがテストで守られているかを見たい
- 正式仕様：ルールのページ（`docs/cartagraph/*.md`）、[テストレポート](../architecture/test-report.md)、[テストルール](../process/rules/testing.md)、[docs の1ファイル1責務](../process/rules/doc-responsibility.md)（`cartagraph/auto-combat-simulation.md` は生成ページで対象外）。ルールのページの中身は変えない
- 今の作り
  - テストから仕様の節への参照は、コメントに `docs/cartagraph/xxx.md「節」` と書いたものが20件ほど（書式はそろっていない）。機械では読まない
  - Vitest は domain・schemas・web の3パッケージ（4.1.11）。domain・schemas には `vitest.config` が無く既定で動く。web は `apps/web/vite.config.ts` の `test`
  - `test:report` は各パッケージで `--reporter=default --reporter=html` を流し `vitest-report/` に書く。デプロイ（`.github/workflows/deploy.yml`）は `build:pages` → E2E → `test:report` → `build-usecase-report.mjs` → `copy-test-reports-to-pages.mjs` の順（テストの段は `continue-on-error`、後の段は `if: always()`）
  - `docs/cartagraph/` は17ページ。`##` は約100、`###` は約30。同じページの中に同じ見出しは無い（ページをまたぐと「この章の設計原則」が重なる）。見出しに空白は無い。コードブロック（```）の中に `#` で始まる行があるページがある
  - 見出しのアンカー（id）は VitePress が作る（例：`初期装備（仮ルール）` → `#初期装備仮ルール`）。`check-doc-anchors.mjs` はビルド結果の HTML の id を読んでいる
- Vitest 4.1.11 のタグの挙動（`node_modules/.pnpm/@vitest+runner@4.1.11/.../chunk-artifact.js`、`vitest/dist/chunks/index.*.js` を読んで確かめた）
  - テスト・describe に `{ tags: [...] }` で付ける。describe のタグは中のテストに引き継がれる（`unique([...parentTags, ...tags])`）
  - 設定の `test.tags`（`{ name, description }` の配列）に無いタグを付けると、収集の時点で例外になる（`The tag "…" is not defined in the configuration`）。設定にタグが1つも無いときも例外
  - JSON レポーター（`--reporter=json`）の `assertionResults[]` に `tags`・`status`（passed・failed・skipped・pending・todo）・`ancestorTitles`・`title`・`fullName` が出る

### 紐づけの書き方（D6）

```ts
describe('判定', { tags: ['rule:check/判定の基本メカニズム'] }, () => {
  it('能力値＋カードの修正が目標値以上なら成功', () => { … });
  it('HP を払って振り直せる', { tags: ['rule:check/失敗時の扱い'] }, () => { … });
});
```

- タグは文字列の直書き（D8 の静的な検査と、検索で引けるように）
- 付けるのは、そのテストが節に書いたルールを実際に確かめているときだけ。モジュール単位で機械的に付けない（「確認済」が水増しになる）
- 既存のコメントの `docs/cartagraph/xxx.md「節」` は、タグに置き換えられるものは置き換え、出典の説明として要るものは残す

### タグの一覧の組み立て（D6・D7）：`scripts/rule-sections.mjs`

- `readRuleSections(dir = 'docs/cartagraph')` → `[{ tag, page, pageTitle, heading, level, parent, provisional }]`
  - `*.md` のうち `auto-combat-simulation.md` を除く。コードブロックの中の行は読まない
  - 同じページに同じ見出しが2つあれば例外。1件も読めなければ例外
- `vitestTags()` → `[{ name: tag, description: '<ページの題>「<見出し>」' }]`。3パッケージの設定から呼ぶ
  - `packages/domain/vitest.config.ts`・`packages/schemas/vitest.config.ts` を新しく置く（今の既定の設定を変えない）。`apps/web/vite.config.ts` の `test` に `tags` を足す
  - 設定から `scripts/` の .mjs を相対パスで読む。biome の層ごとの import の禁止に当たれば、設定ファイルを例外にする方法を手順1で確かめる（当たらなければ何もしない）

### 対象外の一覧（D3・D8）：`docs/architecture/rule-test-exclusions.md`

- 表の列は「ページ」「節」「理由」。節を空にするとページ全体が対象外
- 初めの中身：`index.md`（構想の概観）、各ページの「この章の設計原則」、相場観（`balance.md`）のように数値の目安で判定の無いもの。どれを入れるかは手順4でルールのページを読んで決め、理由を1行ずつ書く。迷うものは入れない（「テストなし」のまま出す）
- `scripts/check-rule-test-exclusions.mjs`：`readRuleSections` と表を突き合わせ、D8 の3つを止める。テストのファイルは `apps/web/src/**`・`packages/*/src/**` の `*.test.*`

### ページの組み立て（D9〜D14）：`scripts/build-rule-test-report.mjs`

- 入力：`packages/domain`・`packages/schemas`・`apps/web` の `vitest-results/results.json`、`readRuleSections`、対象外の一覧、ビルド結果の HTML（アンカー）。出力：`rule-test-report/index.html`（リポジトリの直下。.gitignore に足す）
- ページの並び：ルールのページの順（`docs/cartagraph/` のファイル名順ではなく、サイドバーの順が引ければそれ。引けなければファイル名順）→ 節は見出しの順、`###` は親の下
- どの節にも当たらないタグ（設定が古いなど。Vitest が止めるので通常は出ない）は、ページの末尾に「当たらないタグ」として出す
- 見た目は `build-usecase-report.mjs` に合わせる（状態の色・表）。テストの題は HTML にエスケープする
- コマンド：`pnpm rule:report`（`pnpm test:report; pnpm rule:report` と流す）。`copy-test-reports-to-pages.mjs` の表に `['rule-test-report', 'rule-test-report']` を足す。deploy.yml の「Build use case report」の後に同じ形（`if: always()`・`continue-on-error`）で足す

### docs の修正

- `docs/architecture/test-report.md`：表に「ルールとの対応」の行、「ルールとの対応の見方」の節（状態の意味・「確認済」の範囲）
- `docs/architecture/rule-test-exclusions.md`：新しく置く。サイドバー（`docs/.vitepress/config`）にも足す
- `docs/process/rules/testing.md`：「ルールのテストのタグ」の節（書き方・付ける基準・止めるもの）
- `AGENTS.md`：コマンドの表に `pnpm rule:report`、`docs:build` の説明に対象外の一覧の検査
- 要望ファイル：状態をサイクルに合わせて直す

## 4. テスト影響範囲

- `packages/domain` の既存のテスト：タグを足すだけで中身は変えない。タグの打ち間違いは Vitest が落とす
- `apps/web`・`packages/schemas`：設定に `tags` が増えるだけ（タグを付けたテストは無い）
- `scripts/` の新しい3本と、それぞれの `*.test.mjs`（`pnpm tools:test`）
- `pnpm docs:build`：検査が1本増える

## 8. スコープ外

- `rules/cards.json` のカードごとの紐づけ（D2）
- web・schemas のテストへのタグ付け（D5。仕組みは入れる）
- E2E（Playwright）のテストをこのページに出すこと（D4）
- 節に書いたルールをどこまで確かめたか（網羅の度合い）の表示。「確認済」はタグを付けたテストが通ったという意味だけ（D9）
- ルールのページの中身の変更
- タグの名前の型（`TestTags` の宣言）による補完。打ち間違いは Vitest の実行時に止まるので今回は足さない
