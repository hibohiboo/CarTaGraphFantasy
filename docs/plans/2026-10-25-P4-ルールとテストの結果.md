## 1. 概要

ルールのページ（`docs/cartagraph/`）の節（`##`・`###`）ごとに、それを確かめる Vitest のテストと最新の結果（確認済・落ちた・スキップのみ・テストなし・対象外）を一覧にするページを作る。紐づけは Vitest 4.1 のテストのタグ（`{ tags: ['rule:check/判定の基本メカニズム'] }`）でテストの側に書き、タグの一覧は仕様のページの見出しから組み立てて Vitest の設定に渡す（見出しに無いタグ・対象外の節のタグを付けたテストは Vitest が実行時に落とす）。デプロイが Vitest の後に HTML を組み立て、GitHub Pages の `/CarTaGraphFantasy/rule-test-report/` に載せる。あわせて、`packages/domain` のテストに一通りタグを付ける。

### 紐づけの書き方（D6）

```ts
describe('判定', { tags: ['rule:check/判定の基本メカニズム'] }, () => {
  it('能力値＋カードの修正が目標値以上なら成功', () => { … });
  it('HP を払って振り直せる', { tags: ['rule:check/失敗時の扱い'] }, () => { … });
});
```

- タグは文字列の直書き（検索で引けるように）
- 付けるのは、そのテストが節に書いたルールを実際に確かめているときだけ。モジュール単位で機械的に付けない（「確認済」が水増しになる）
- 既存のコメントの `docs/cartagraph/xxx.md「節」` は、タグに置き換えられるものは置き換え、出典の説明として要るものは残す

### タグの一覧の組み立て（D6・D7・D16〜D18）：`scripts/rule-sections.mjs`

- `readRuleSections(dir = <リポジトリの直下>/docs/cartagraph)` → `[{ tag, page, pageTitle, heading, level, parent, provisional, pageProvisional }]`
  - `*.md` のうち `auto-combat-simulation.md` を除く（`check-provisional.mjs` の `NOT_SPEC` を export して使う）。` ``` `・`~~~` のフェンス（開いたのと同じ種類・同じ長さ以上で閉じる）の中の行は読まない。`##`・`###` だけを読む
  - 同じページに同じ見出しが2つあれば例外。D17 の例外。1件も読めなければ例外
- `readExclusions(file = <リポジトリの直下>/docs/architecture/rule-test-exclusions.md)` → `[{ page, heading | null, reason }]`
- `vitestTags()` → 対象外を除いた節の `[{ name: tag, description: '<ページの題>「<見出し>」' }]`。3パッケージの設定から呼ぶ
  - `packages/domain/vitest.config.ts`・`packages/schemas/vitest.config.ts` を新しく置く（`test.tags` のほかは既定のまま。手順1で、置いても収集されるテストの数が変わらないことを確かめる）。`apps/web/vite.config.ts` の `test` に `tags` を足す
  - 設定からは `import { vitestTags } from '../../scripts/rule-sections.mjs'` と静的に書く

### 対象外の一覧（D3・D8）：`docs/architecture/rule-test-exclusions.md`

- 表の列は「ページ」「節」「理由」。節を空にするとページ全体が対象外。節は見出しの文字そのまま（リンクにしない）
- 初めの中身：`index.md`（構想の概観）、各ページの「この章の設計原則」、相場観（`balance.md`）のように数値の目安で判定の無いもの。どれを入れるかは手順4でルールのページを読んで決め、理由を1行ずつ書く。迷うものは入れない（「テストなし」のまま出す）
- `scripts/check-rule-test-exclusions.mjs`：`readRuleSections`・`readExclusions` を突き合わせ、D8 の検査を行う。`readRuleSections` の例外（D17 など）もここで docs:build を止める（pre-push で Vitest より後になるが、docs だけを直す人が `pnpm docs:build` で気づける）

### ページの組み立て（D9〜D15・D19・D20）：`scripts/build-rule-test-report.mjs`

- 入力：`packages/domain`・`packages/schemas`・`apps/web` の `vitest-results/results.json`、`readRuleSections`、`readExclusions`、ビルド結果の HTML（アンカー・サイドバー）。出力：`rule-test-report/index.html`（リポジトリの直下）
- 関数（テストする単位）と CLI の入口を分ける（入口は子プロセスで1本だけ流して確かめる）
- 先頭に出すもの：結果なしのパッケージ（D11）、収集で落ちたファイル（D15）、生成の時刻とコミット
- どの節にも当たらない `rule:` のタグ（設定が古いなど。Vitest が止めるので通常は出ない）は、ページの末尾に「当たらないタグ」として出す。`rule:` で始まらないタグは無視する
- テストの題・見出し・ファイル名・パッケージ名・理由は HTML にエスケープする
- コマンド：`pnpm rule:report`（`node scripts/build-rule-test-report.mjs`）。手元では `pnpm docs:build` の後に `pnpm test:report; pnpm rule:report` と流す（docs:build が無いとアンカー・並びが引けず、ページへのリンク・ファイル名順になる）
- デプロイ：deploy.yml の「Build use case report」の後、「Copy test reports」の前に「Build rule test report」を同じ形（`if: always()`・`continue-on-error`）で足す。`copy-test-reports-to-pages.mjs` の表に `['rule-test-report', 'rule-test-report']` を足す
- `.gitignore` に `*/*/vitest-results/` と `/rule-test-report/` を足す（biome は `useIgnoreFile` なので、足さないと lint が JSON を読む）

### 課題

ルールのページ（`docs/cartagraph/`）のどこがテストで守られているかを、見て分かるようにしたい（要望 [ルールのページとテストの結果を紐づける](../backlog/rule-test-report.md)。[ユースケースと E2E の結果](2026-10-18-P2-ユースケースとE2Eの結果.md)の続き）。いまはテストのコメントに出典が20件ほど書いてあるだけで、書式がそろっておらず機械では読めない。

### 解決策

- ルールのページの節（`##`・`###`）ごとに、それを確かめる Vitest のテストと最新の結果（確認済・落ちた・スキップのみ・テストなし・対象外）を一覧にするページを作った。デプロイが Vitest の後に組み立て、Pages の `/rule-test-report/` に載せる（`scripts/build-rule-test-report.mjs`）

- テストで確かめる性質でない節は `docs/architecture/rule-test-exclusions.md` に1か所で宣言する（検査は `scripts/check-rule-test-exclusions.mjs`、`docs:build`）。仕様のページの中身は変えていない
- `packages/domain` のテスト42件に、確かめている節のタグを付けた（ルールでない確かめ・仕様と食い違う振る舞いには付けていない）。web・schemas は仕組みだけ
- トレードオフ：タグ名を見出しの文字そのままにしたので、テストから見出しを検索で引ける代わりに、見出しを直すとそのタグのテストが落ちる（直し方は AGENTS.md・testing.md・spec-writing.md）
