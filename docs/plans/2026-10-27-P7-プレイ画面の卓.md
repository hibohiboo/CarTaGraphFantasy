# プレイ画面を、カードを広げた卓にする（1回目：卓の形）

要望：[プレイ画面に没入できるようにする](../backlog/play-immersion.md)

状態：プランを書いた（2026-10-27）。D1〜D5 は2026-10-27に人間と確かめた（試作 A「卓に広げる」を選んだこと、質問1ラウンド4問）。D6〜D12 は AI の案で、実装順0で人間に確かめる。次はプランの AI レビュー（手順2・3。設計整合・テスト網羅。仕様整合は D10 があるので回す）で、新しいセッション、等級は強い。

## 1. 概要

プレイ画面（`/pl/sessions/:sessionId/play`）を、ヘッダもリンクも無い「カードを広げた卓」にする。卓そのものをプレイマットにして、場所の札・語りの札・場のゾーン・パーティの札・扇形の手札を置き、画面から抜ける操作は右上の「栞」にまとめる。あわせて、PLAY-1〜7（[画面ごとの課題「プレイページ」](../screens/issues.md#プレイページ)）を直す。

これは2回に分けたうちの1回目（卓の形）。札が場へ飛ぶ・山札から配られる・挿絵の札がめくれる、といった動きは2回目のプランで行う（8章）。

- 技術は React のままにする（人間に説明して了承済み）。試作は素の HTML・CSS・Web Animations API で、React からもそのまま使える。動きのライブラリ（Motion）を入れるかは2回目のプランで決める

  - ホームは `/home`（`HomePage`）

## 8. スコープ外

- 札の動き（手札から場へ飛ぶ・着地の揺れ・山札から配る・挿絵の札がめくれる・能力値が上がる光り）。2回目のプランで行い、Motion を入れるかもそこで決める
- 山札と「使った札」の置き場。試作にはあったが、いまのセッションには PL に見える山札が無く、使った札はセッションのログ（`feed`）の文から拾うしかない（提案の採用で場に足した札も `cardName` を持つ）。動きと一緒に2回目で、データをどう持つかから決める
- 持ち物の置き場（試作の「持ち物」）。いまは手札の区切り線の後ろに出ている札がそれに当たる
- 挿絵（試作 B）。場面ごとの絵を持つ仕組みは無い
- パーティの札を押してシートを開くこと、PC の画像（[キャラクターの容姿・設定](../backlog/character-profile.md)）
- テストプレイと、「GMの画面へ」をテストプレイ中だけに絞ること（[GM のホーム](../backlog/gm-home.md)、D2）
- GM の画面・チュートリアル・村スタートの見た目

### 正式仕様との突き合わせ（2026-10-27）

- D4 と [場のゾーン構造](../cartagraph/card-face-back.md#場のゾーン構造)・[GM不在のソロの進行](../cartagraph/solo-village.md)：PL可視ゾーンだけを出し、裏の札の中身と GM専用ゾーンを出さないので、食い違いは無い
- D5 と [自動戦闘「PLの敗北」](../cartagraph/auto-combat.md)：仕様は「ナレーションを挟み、優先順位リストの設定に戻る」。状態は今どおり設定に戻り（`awaiting-priority`）、画面で結果を読んでから設定を開く見せ方なので、遷移は変えない。仕様の文は変えない（人間に報告する）
- D2・D3 と [要望「プレイ画面に没入できるようにする」](../backlog/play-immersion.md)：GM の画面への導線は「テストプレイ中だけ出す」とある。テストプレイがまだ無いので、それまでは GM 本人の栞にだけ出す（人間が決めた。要望の本文にも書く）
- 用語：`docs/cartagraph/`・`docs/glossary.md` を「プレイ画面」「栞」「中断」「山札」で grep した。「栞」は画面の部品の名前で、ゲームの用語ではないので用語集には足さない。「中断」は状態の名前なので栞の中では使わない（D3）
