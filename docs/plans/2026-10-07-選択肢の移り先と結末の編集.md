# 選択肢の移り先と結末の編集（C2）

要望：[シナリオ製作者がシナリオを作って公開する](../backlog/scenario-publish.md)（2サイクルのうち C2。C1 は [シナリオの公開で JSON に書き込む](2026-10-06-シナリオ公開のJSON書き込み.md)）

## 1. 概要

シナリオ製作者が画面だけで、GM 不在でも結末まで遊べるシナリオを作れるようにする。

- シーン編集で、選択肢カードの移り先（別のシーン・結末のノード）を選べる
- 導入・結末のノードも、シーン編集の画面で開ける
- シナリオ編集の「結末を追加」で、結末と、それを指す結末ノードを対で作る。「削除」で対で消す
- 移り先になっているノードは消せず、理由を出す

最後に「画面だけで作る→公開→GM 不在で募集→PL が始めて結末まで→結末タグを得る」を画面から通す。

## 2. 背景

- [ロードマップ](../roadmap.md) M1 の完成の条件2（シナリオ製作者が作って公開でき、遊べるシナリオになる）。C1 は公開と JSON への書き込みまでだった。画面で作ったシナリオは、GM が移り先付きの選択肢を配らない限り先へ進めなかった
- 関わる仕様
  - [遊びと場の仕様](../cartagraph/play-and-field.md)
    - 「基本操作セット」の8「次のシーンへ進む（シナリオデッキの**別の**ノードへ移る）」
    - 「次のシーンへ進む」：選択肢カードの効果として移り先のノードを指定する。GM 不在のセッションでは、結末のノードへ進んだ時点で終わる。GM 不在でないセッションは、GM が終了を宣言するまで終わらない
  - [GM不在のソロ（仮ルール）](../cartagraph/solo-village.md)「結末タグ」：結末のノードは、シナリオが定義した**結末**の1つを指せる。指す結末に結末タグがあれば、ドライバーのキャラクターへ即時に付ける
  - [シナリオの構造とセッション開始までの流れ](../cartagraph/scenario-flow.md)「シナリオの基本構造」「連作・キャンペーンの表現：結末タグ」：入れ子構造（導入→シーン→結末）。結末は任意の数で、結末ごとに結末タグを配れる（配らなければ単発）
- 用語（型との対応）
  - **結末**：`EndingDef`（`name` が結末の名前）
  - **結末タグ**：`EndingDef.grantsTag`
  - **結末のノード**：`kind: 'ending'` の `DeckNode`（`endingId` で結末を指す）
  - **移り先**：`CardDef.nextNodeId`（GM の画面と同じ語）
- 仕様のルールは変えない。画面で編集できる範囲を広げるだけ。未解決論点（シーンの「目的」「終了条件」）は今の仮ルールの扱いのまま
- C1 で既知の問題に記録した「公開中のシナリオで保存が検査に落ちると、編集を手で戻すしかない」は、移り先になっているノードを消せなくする（D1・D2）ことで、画面の操作からはたどり着かなくなる。既知の問題から消す
- **用語の揺れを直す（最重要ルール3。プランレビューで見つかった）**
  - 画面のシナリオ編集で、結末の一覧の題が「結末タグ」、結末タグ（`grantsTag`）の欄が「配る前提タグ」になっている（入れ替わっている）
  - `scenario-flow.md` の「任意の数の結末タグを定義してよい」は、結末と結末タグを取り違えている。同じ節の「結末タグを配る結末にだけ付けられる」と食い違う
  - `model.ts` の `EndingDef` の説明が「結末タグの定義」になっている
  - 用語集に「結末」の項目が無い
  - 「行き先」（C1 の要望の名前、既知の問題、テスト名の一部）は、仕様と GM の画面の「移り先」にそろえる

### その他の設計判断（AI が決めたもの）

- **D4 で結末にカードの枠を出さない理由**：C2 の目的は GM 不在で結末まで遊べることで、GM 不在では結末のノードへ進むと終わる。GM 不在でないセッションでは結末のノードでも選択肢を配れるが（`planTransition`）、その編集は C2 のスコープ外にする（8.）。既にあるカードは、結末の編集で保存しても消さない（名前と `endingId` だけを書き換える）
- **導入を移り先に出さない理由**：D5 は人間が決めた。GM の画面（`narrationTargets`）は導入も移り先にできる（GM の裁量）。製作者の画面は、入れ子構造の順（導入→シーン→結末）を前に進む移り先だけを出す。二つの候補の定義は目的が違うので、共通にしない。違いはコードのコメントに書く
- **編集の純粋関数は `packages/domain/src/scenario/edit.ts` に置く**
  - React に依存しないデッキの変換なので domain に置く（`docs/process/rules/architecture.md`「構造」の1）
  - デッキをたどる処理は `deadEnd.ts` の `walk` と同じく scenario の中で持つ（`session/transition.ts` の `findDeckNode` は、domain の中の向き scenario ← session のため使えない）
  - `walk` は `scenario/deck.ts`（新規）に移し、`deadEnd.ts` と `edit.ts` の両方が使う（書き写さない）
- `edit.ts` の関数
  - `moveTargets(deck, fromNodeId)`：移り先に選べるノード（D5）。`{ node, label }[]` で、デッキの並びの順。`label` は「シーン：〈名前〉」「結末：〈名前〉」。入れ子は GM の画面と同じく「〈親〉 › 〈子〉」を添える
  - `choiceReferrers(deck, nodeIds)`：`nodeIds` のどれかを `nextNodeId` に持つ選択肢カードと、そのカードがあるノード（`{ node, card }[]`）。消すノード（とその子孫）の中のカードは数えない
  - `removeNode(deck, nodeId)`：ノードとその子孫を消す。指されていれば消さずに `{ ok: false, referrers }`、消せれば `{ ok: true, deck }`
  - `addEnding(scenario, name, ids)`：結末と、それを指す結末ノードを足す（D6。ノードの名前は結末の名前、デッキの最後に置く）
  - `removeEnding(scenario, endingId)`：結末と、それを指す結末ノード（最上位・`children` とも、複数あれば全部）を消す（D2）。指されていれば何も消さずに `{ ok: false, referrers }`。無い id なら何も変えずに `{ ok: true }`
  - `unusedId(base, isTaken)`：`base` が使われていればハイフンと数字を付けて、使われていない id を返す（同じミリ秒に2回押しても、`d-<時刻>`・`e-<時刻>` が重ならないように。時刻は呼び出し側が渡す）
  - `referrerMessage(referrers)`：「『桟橋へ』（港の酒場）から指されているので削除できません」（複数なら「、」でつなぐ）
  - どの操作の結果も参照を壊さない（`findScenarioRefErrors` が空のまま）
- **新規作成（`POST /api/scenarios`、`handlers.ts`）**：D3 のとおり `addEnding` で結末「結末」と結末ノードを作る
- **シナリオ編集（`CreatorScenarioEditPage.tsx`）**
  - シーンの「削除」は `removeNode` を使う。止められたら理由を `role="alert"` でデッキの枠の中に出す。下書きの中だけで止める（保存しない）。判定は下書きのデッキを見る（先に指している側を消せば、指されていた側も消せる）
  - 「シーンを追加」「結末を追加」の id は `unusedId` で作る
  - 結末の枠：題を「結末」にし、行に「削除」を足す（`removeEnding`、止められたら理由を出す）。結末タグの欄のラベルを「結末タグ（空なら単発）」にする（`aria-label` も「結末タグ」）
  - デッキの構造で、導入・結末のノードにも「編集」のリンクを出す（シーンと同じ URL）。「削除」「濃密に」はシーンだけ（導入・結末には出さない）
  - 結末の名前を変えても、結末ノードの名前は変えない（ノードの名前は製作者が付ける。初期値だけ結末の名前）
- **シーン編集（`CreatorSceneEditPage.tsx`）**
  - 開けるノードを、`kind` が `scene`・`intro`・`ending` の最上位のノードに広げる（プール用は今までどおり「シーンが見つかりません」）
  - 見出し（h1）は今までどおりノードの名前。左の枠の題を「シーン情報」「導入の情報」「結末の情報」に、名前の欄のラベルを「シーン名」「導入の名前」「結末の名前」にする
  - 導入：シーンと同じ画面から、目的・終了条件（仮）の欄と注記を除く
  - 結末：名前と「指す結末」（`select`。シナリオの結末の名前と「指さない」）だけ。ロケーションとカードの枠は出さない
  - 選択肢カードの行に「移り先」の `select`（`aria-label="移り先"`）を出す。選択肢は「移り先なし」と `moveTargets`。「移り先なし」を選ぶと `nextNodeId` のキーごと消す（空文字を残さない）
  - いまの移り先が候補に無いとき
    - デッキに無い（壊れたデータ）なら「（見つからない：〈id〉）」を選択肢として出す
    - デッキにはあるが候補外（導入・自分自身など。JSON で書いたもの）なら「（候補外：〈名前〉）」を出す
    - どちらも、選び直さずに保存したら値をそのまま残す（黙って消さない）
- **`packages/domain` の型は変えない**（`DeckNode.endingId`・`CardDef.nextNodeId` は既にある）。`EndingDef` の説明（JSDoc）だけ「結末の定義」に直す

## 5. 新規テストケース

最初から通る回帰テストは `node scripts/mutate-check.mjs` で、守る条件を外して落ちることを確かめる。消えたことは `not.toHaveProperty` で確かめる（空文字が残る実装を通さない）。

### `packages/domain/src/scenario/edit.test.ts`

テストの中で小さなデッキを組み立てる（`scenarios/*.json` には `children` が無く、domain から JSON を読む向きも無いため。`deck.test.ts` と同じ）。デッキは、導入・シーン（中に `children` のシーンと結末）・NPC と情報と敵のプール・最上位の結末を含める。

- `moveTargets`：別のシーンと結末（最上位・`children` の2段目）が並び順で入る。導入・プール用・指定したノード自身は入らない。入れ子のラベルに親の名前が付く
- `choiceReferrers`：指している選択肢と、そのノードを返す（別のノード・`children` の中のカードも）。指されていなければ空。消すノードの中から自分を指す選択肢は数えない。外から指していれば数える（境界の両側）
- `removeNode`：指されていなければ、ノードと子孫を消した `deck` を返し、引数は変えない。指されていれば `ok: false` と referrers で、`deck` は変えない
- `addEnding`：結末と、それを指す結末ノードがデッキの最後に1つずつ増える。ノードの名前は結末の名前。`grantsTag` は付かない
- `removeEnding`：結末と、それを指す結末ノード（最上位・`children` の中、複数あれば全部）が消える。ほかの結末・結末ノード、どの結末も指さないノードは残る。同じ結末を指す結末ノードが2つあり、片方だけが移り先なら何も消えない（部分的に消さない）。結末ノードを持たない結末は消せる。無い結末 id なら何も変えない
- `addEnding` → `removeEnding` で元に戻る（往復）
- `unusedId`：空いていればそのまま。使われていれば `-2`・`-3` と進める
- `referrerMessage`：1件・複数件の文。括弧の中はノードの名前
- 上の操作の結果は、どれも `findScenarioRefErrors` が空
- `deadEnd.ts` の既存テストが、`walk` を `deck.ts` へ移したあとも通る

### 画面（新規 `apps/web/src/test/scenarioAuthoringScreens.test.tsx`）

シーン編集

- 選択肢カードに「移り先」の選択がある。選択肢は「移り先なし」と、別のシーン・結末のノードだけ（導入・プール用・そのシーン自身は無い）。前置き「シーン：」「結末：」と並び順。追加したばかりの選択肢の初期値は「移り先なし」
- 移り先を選んで保存すると、再取得した `nextNodeId` がその id になる。「移り先なし」で保存すると、キーごと消え（`not.toHaveProperty`）、そのシナリオは公開できる（空文字で 422 にならない）
- 選択肢でないカード（NPC など）には「移り先」が出ない
- デッキに無い移り先（`sc-village-always-win` の `vw-lost`→`vw-nowhere`）は、その行の値が `vw-nowhere` で「（見つからない：vw-nowhere）」と出る。ほかのカードの行には出ない。製作者が system で保存できないので、選び直すところまで確かめる
- 選び直さずにほかの欄だけ変えて保存しても、候補外の移り先は残る（`sc-mansion-mine` の選択肢を、テストの中で導入を指すように直したもので確かめる。製作者が自分の下書きなので保存できる）
- `dealWhen`・`soloEffect` を持つ選択肢の移り先だけを変えて保存しても、それらは残る（編集しない項目を失わない）
- 導入を開ける。カードと選択肢（移り先）を置け、保存すると再取得に反映される。目的・終了条件（仮）の欄と注記 `/未決の仮ルール/` は出ない。左の枠の題は「導入の情報」
- 結末を開くと、名前と「指す結末」だけが出る（「＋カードを追加」「ロケーション」「目的（仮）」が無い）。名前を変えて保存すると反映される。指す結末を選んで保存すると `endingId` が変わり、「指さない」で `endingId` がキーごと消える
- 既存の、どの結末も指さない結末ノード（`sc-mansion-mine` の `d-end`）を開くと、指す結末の選択肢が結末3つの名前と「指さない」で、選んで保存できる
- 既にカードがある結末ノード（テストの中で足す）を名前だけ変えて保存しても、カードは消えない
- プール用のノード（`d-npc`）は今までどおり開けない（既存テスト）

シナリオ編集

- デッキの構造で、導入・結末にも「編集」のリンクがあり、プール用には無い。導入・結末の行に「削除」「濃密に」は無い
- 移り先になっているシーンの「削除」は止まり、「『〈選択肢〉』（〈ノード名〉）から指されているので削除できません」が出て、デッキから消えない。指されていないシーンは消える（境界の両側）
- 下書きの中で、指している側のシーンを先に消すと、指されていたシーンも消せる（判定が下書きを見ている）
- 「結末を追加」で結末と結末ノードが1つずつ増える。続けて2回押しても、同じ時刻（`Date.now` を固定）で「シーンを追加」しても、id が重ならず、保存して公開できる
- 結末の「削除」で、結末と結末ノードの両方が消え、保存して再取得しても参照の誤りが無い。移り先になっている結末ノードの結末は消せず、理由が出る
- 結末の名前を変えて保存しても、結末ノードの名前は変わらない
- 結末の枠の題が「結末」、結末タグの欄のラベルが「結末タグ（空なら単発）」

**通し（M1 の完成の条件2。画面の操作だけで進め、API を直接呼ばない）**

1. 偽の保存先を差し込む
2. シナリオ製作者が新規作成する
3. 「シーンを追加」→ 保存（保存しないとシーン編集から新しいシーンが見えない）
4. 導入の行の「編集」→ 選択肢「村へ」（移り先：シーン）を足して保存
5. シーンの行の「編集」→ 選択肢「帰る」（移り先：結末）を足して保存
6. シナリオ編集で、結末の結末タグに「村を見た」を入れて保存 → シナリオ集へ公開
7. 保存先に書かれたシナリオで、導入の選択肢の `nextNodeId` が新しいシーン、シーンの選択肢が結末ノード、結末ノードの `endingId` が結末、結末の `grantsTag` が「村を見た」で、`safeParseScenarioFile(toScenarioFile(…))` を通る
8. GM がシナリオ詳細で「GM 不在」「提案不可」を選ぶ。先へ進む選択肢の無いシーンの注意が出ない。募集を出す
9. PL がセッション選択で「GM 不在の募集だけ」に絞り、自分の PC で始める。プレイ画面に「新たな選択肢を提案」が無い
10. 「村へ」を押すと「村へ」が消えて「帰る」が出る（配り直し）。「帰る」を押すと「このセッションは終了しています。」・見出し「結末「結末」」・描写の「結末タグ『村を見た』を得た。」が出る
11. 「キャラクターシート」へ移ると、結末タグ「村を見た」が出る

## PR 下書き

**タイトル**：シナリオ製作者が選択肢の移り先と結末を画面で編集し、作ったシナリオを GM 不在で結末まで遊べるようにする

### 課題

[ロードマップ](../roadmap.md) M1 の完成の条件2（シナリオ製作者が作って公開でき、遊べるシナリオになる）の残り。要望は [シナリオ製作者がシナリオを作って公開する](../backlog/scenario-publish.md) の C2、プランはこのファイル。C1（PR #17）で公開と JSON への書き込みはできたが、画面では選択肢カードの移り先も結末のノードも決められず、画面で作ったシナリオは GM が移り先付きの選択肢を配らない限り先へ進めなかった。

### 解決策

- シーン編集：選択肢カードに「移り先」（移り先なし／別のシーン・結末のノード）を足した。導入・結末のノードも同じ画面で開ける（結末は名前と「指す結末」だけ）。候補に無い移り先・結末は「見つからない」「候補外」と出し、選び直さずに保存しても黙って消さない
- シナリオ編集：移り先になっているシーンは削除を止めて理由を出す。「結末を追加」「削除」で結末と結末のノードを対で増減する。新しいシナリオは結末1つと結末のノードを対で持つ（結末タグは付けない）。保存していないノードには「編集」を出さない
- 編集の操作は `packages/domain/src/scenario/edit.ts` の純粋関数（`moveTargets`・`removeNode`・`addEnding`・`removeEnding`・`unusedId` など）。デッキをたどる `walk` は `scenario/deck.ts` に移した
- 移り先から、そのノード自身を除いた（基本操作8「別のノードへ移る」。C1 のときの決定を人間の判断で取り消した）。導入も出さない（D5）。GM の画面の移り先（`narrationTargets`）とは目的が違うので共通にしない
- 用語の揺れを直した（最重要ルール3）：画面の「結末タグ」の枠→「結末」、「配る前提タグ」→「結末タグ」。scenario-flow.md の「任意の数の結末タグ」→「任意の数の結末」。用語集に「結末」。「行き先」→「移り先」、「結末ノード」→「結末のノード」

### テスト

- `edit.test.ts`：移り先の候補（入れ子・自分自身・導入・プール用）、指している選択肢の数え方（消すノードの中は数えない）、削除を止める・部分的に消さない、結末の追加と削除の往復、id が重ならない、操作のあとも参照を壊さない
- `scenarioAuthoringScreens.test.tsx`：シーン編集（移り先の候補・保存・キーごと消える・候補外と見つからない・編集しない項目を失わない）、導入と結末の編集、シナリオ編集（削除を止める・下書きの順序・結末の追加と削除・同じ時刻でも id が重ならない・保存前は「編集」が出ない）、**通し**（画面だけで作る→公開して JSON の中身を確認→GM 不在・提案不可で募集→PL が始めて結末→キャラクターシートに結末タグ）
- 既存テストの書き換え：C1 の「指されているシーンを消して保存すると 422」は、削除そのものが止まる形に（422 の経路は API のテストが守る）
- 守る条件は `node scripts/mutate-check.mjs` で外して落ちることを確かめた（16件）
- ブラウザ：エージェント用の開発サーバーで、作る→移り先を付ける→削除が止まる→結末の編集→公開→GM 不在で募集→PL で結末まで。コンソールのエラーなし
