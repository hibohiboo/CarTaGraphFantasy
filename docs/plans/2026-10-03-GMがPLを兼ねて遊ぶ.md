# GM が PL を兼ねて結末まで遊ぶ

要望：[GM が PL を兼ねて結末まで遊ぶ](../backlog/gm-play-as-pl.md)（[ロードマップ](../roadmap.md) M1 の完成の条件4）

## 1. 概要

人間 GM のセッションで、GM が「描写を書く」「選択肢カードをその場で作って配る（移り先も指定できる）」「配った選択肢を取り下げる」を1つのフォームでまとめて送れるようにする。GM が自分のキャラクターでドライバーも務めるときは、GM の画面とプレイの画面をリンクで行き来できるようにする。これで、移り先を持つ選択肢カードの無いシナリオ（灰色館の一夜など）も、GM が移り先付きのカードを配ることで導入から結末まで進められる。結末に着いたら GM が結末の描写を書き、既存の「セッションを終了する」で終える。

## 2. 背景

- 正式仕様：[場・手札・プレイ](../cartagraph/play-and-field.md)
  - 「選択肢カードとGMの生成」「PLはカードをプレイすることでセッションに干渉する」（イベントで GM が選択肢カードを生成し、一時的な選択肢カードとして PL に渡す。GM がフォームから直接配る根拠はここ。基本操作6はカードがプレイされたときの効果なので根拠にしない）
  - 「次のシーンへ進む」：導入→シーン→結末のノード間を移る操作。移り先は選択肢カードの効果として指定する。移ると手札の選択肢カードは移り先のもので配り直される。**人間GMのセッションでは、結末のノードへ進んでも GM が終了を宣言するまで終わらない**。8は選択肢カードの効果による遷移だけを扱う。基本操作8は「シナリオデッキの別のノードへ移る」
  - 「提案の裁定待ちの間の状態遷移」（裁定待ちの間もセッションは止めない）
  - 「GMレスセッションでの選択肢の描写」の最後（人間GMのセッションでは、選択肢を選ぶと GM の描写を待つ）
- 正式仕様：[カード・デッキの考え方](../cartagraph/card-and-deck.md)「カードは『プレイによって生まれる』こともある」（GM が生成したカードは通常のカードと同じ構造）
- 正式仕様：[シナリオの構造とセッション開始までの流れ](../cartagraph/scenario-flow.md)「GMのカスタマイズ」（外したシーンへは進めない）
- 正式仕様：[自動戦闘（仮ルール）](../cartagraph/auto-combat.md)（GM 不在のソロ限定。人間 GM のセッションでは自動戦闘のシーンへ進めない）
- デザイナーノート：[場・手札・プレイ](../notes/play-and-field.md)（人間 GM のセッションでは、GM がその結果を描写し、次の選択肢を配る）
- 用語集「手札」：GM から**一時的に**渡される選択肢カードを含む
- ロードマップの「役割」：「GM が PL を兼ねる」とは、GM が自分のキャラクターでドライバーも務めること
- いまのコード
  - GM の進行管理画面（`/gm/sessions/:id`、`GmSessionManagePage.tsx`）でできるのは、提案の裁定・モードの切り替え・終了の宣言だけ。描写を書く・選択肢を配る操作は無い
  - 人間 GM のセッションで、移り先の無い選択肢カードを選ぶと、手札の選択肢が全部消え「GMの描写を待っている」になる。そこから先へ進める操作が無い
  - 人間 GM 向けのシナリオ（`sc-gray-mansion`・`sc-galleon`・`sc-corridor-after`）は、移り先を持つ選択肢カードがほぼ無い。灰色館の導入には選択肢カードが無く、募集から始めた直後の手札は空になる（募集から始めたセッションの手札は導入の選択肢だけで、PC のカードは入らない）
  - GM の画面からプレイ画面へのリンク、プレイ画面から GM の画面へのリンクが無い
  - プレイ画面は、終了したセッションで `currentScene.nodeId` があれば、ノードの種類を見ずに「結末『〈シーン名〉』」と出す
  - 提案の採用（`/proposals/:pid/approve`）は GM が誰かを確かめていない（このプランでは直さない。スコープ外）

## 3. 詳細設計

### 決定事項（grilling の結果）

1. **シーンの進め方** — GM が移り先を指定した選択肢カードを配り、ドライバーがそれをプレイして進む（仕様の「8は選択肢カードの効果による遷移だけ」のまま）。GM が PL を兼ねるときは、GM の画面で配り、プレイ画面でプレイする2手になる。GM の画面から直接ノードを移す操作は作らない
2. **配れる選択肢カード** — GM がその場で作るカードだけ。名前（必須）・説明文（任意）・移り先（任意）を入力する。シナリオの各ノードに用意された選択肢カードから選んで配る操作は作らない。手札にある選択肢カードの取り下げもできる。ノードに入ったときの自動配布（移り先のノードの選択肢を配り直す）はいまのまま
3. **操作の単位** — 「描写」「取り下げる選択肢」「配る選択肢（0枚以上）」を1つのフォームにまとめ、1回で送る（非同期で GM が1回応答する形）
4. **結末タグ** — スコープ外。結末に着いたら GM が結末の描写を書き、既存の「セッションを終了する」で終える。人間 GM のセッションで結末タグが付かないのは、既知の問題「人間GMのセッションで、結末タグが PC に反映されない」のまま

### その他の設計判断（AI が決めたもの。プランレビューの指摘を反映）

- **描写** — 卓上の描写（`Session.flavor`）を GM が書いた文で置き換える。前後の空白を取り除き、空なら今の描写を残す（取り下げ・配るだけを送れるように）
- **何も変えない送信は断る** — 描写が空で、取り下げも配るカードも無ければエラー（「描写を書くか、選択肢を配るか取り下げてください」）
- **送れるのは進行中のセッションだけ** — `status` が `playing` でなければエラー（終了・中断のどちらも）。画面の枠も `playing` のときだけ出す。中断中に GM が描写してよいかは仕様に無いので、今回は送れない側に揃える
- **取り下げられるカード** — 手札の選択肢カード（`kind: 'choice'`）だけ。能力・アイテムなど PC のカードは取り下げられない。手札に無い ID・選択肢でないカードの ID・同じ ID の重複はエラー
- **取り下げの仕様上の扱い** — 仕様には「取り下げ」の操作が無い。決定事項2で決めた操作なので、[場・手札・プレイ](../cartagraph/play-and-field.md)「選択肢カードとGMの生成」に「GM は、配った一時的な選択肢カードを、プレイされる前に手札から取り下げられる」を1行足す（用語集「手札」の「一時的に渡される」の範囲。理由はデザイナーノートに書く）
- **作るカードの形** — `{ id, kind: 'choice', name, description?, nextNodeId?, tags: ['GM生成'] }`。提案の採用で作るカードと同じく `GM生成` のタグを付ける。名前・説明文は前後の空白を取り除き、空の説明文は持たせない。ID はサーバー（MSW）が振る。手札の中では、残った選択肢カードの後ろ（PC のカードの前）に、送った順で入れる（提案の採用と同じ位置）
- **移り先として選べるノード** — そのセッションのデッキ（外したシーンを除いた `sessionDeck`）にある、種類が導入・シーン・結末（`intro`/`scene`/`ending`）のノード。入れ子のノードも選べる。次は選べない
  - NPC・情報・エネミー・場所などのノード（「次のシーンへ進む」は導入→シーン→結末のノード間の操作）
  - 自動戦闘のノード（人間 GM のセッションでは進めない。`planTransition` と同じ理由）
  - いま居るノード（基本操作8は「別のノードへ移る」）
- **検査と組み立ての純粋関数** — `packages/domain/src/session/narrate.ts` に置く。画面（フォームのボタンの可否・エラーの表示・移り先のセレクト・結末の案内）とサーバー（MSW）の両方が使う（判定を画面に書き写さない）
  - `narrationTargets(deck, currentNodeId)`：移り先にできるノードの `{ id, label }[]`。デッキの順に並べ、入れ子のノードは祖先の名前を添えた `label`（`〈親〉 › 〈子〉`）にする
  - `checkNarration(session, deck, input)`：エラーか OK を返す。判定はこの順で、最初の1つを返す：セッションが進行中でない／何も変えない／取り下げる ID が重複／取り下げる ID が手札の選択肢カードに無い／配るカードの名前が空／移り先が `narrationTargets` に無い。移り先の判定は `narrationTargets` を使う
  - `narrateHand(hand, withdrawCardIds, dealt)`：取り下げたカードを除き、配るカードを残った選択肢カードの後ろに入れた手札を返す（元の手札は書き換えない）
  - `isAtEnding(deck, currentNodeId)`：いま居るノードが結末か（GM の画面の案内とプレイ画面の結末の見出しに使う）
  - `deck` は呼び出し側が `sessionDeck` を通して渡す
- **API** — `POST /api/sessions/:id/narrate`（本文：`{ flavor?, withdrawCardIds?, choices?: [{ name, description?, nextNodeId? }] }`）。成功で 200 と `Session`
  - セッションが無ければ 404、セッションの GM が自分でなければ 403（GM 不在のソロ＝`SYSTEM_GM_ID` のセッションもこれで断る）、`checkNarration` のエラーは 422
  - 本文の形：`flavor` は省略可・文字列。`withdrawCardIds`・`choices` は省略すると空の配列。形の崩れたもの（本文が null・`flavor` が文字列でない・配列でない・要素の `name`/`description`/`nextNodeId` が文字列でない）は 422（既存の開始 API と同じく、黙って丸めず断る）
  - どのエラーでもセッションは変えない（描写だけ正しく移り先が不正、でも何も書き込まない）
  - 書き込み：描写（空でなければ）、手札（`narrateHand`）、ログ（下記）、`lastActivityAt`
  - ログ（新しい順に積むので、上から読んで「描写→取り下げ→配る」の順になるように積む）：描写したら「〈GM名〉が描写した」、取り下げたら「〈GM名〉が選択肢「〈名前〉」を取り下げた」、配ったら「〈GM名〉が選択肢「〈名前〉」を配った」（`cardName` 付き。移り先があれば「（→〈ノードの label〉）」を添える）。括弧は「」にする（GM の画面のログはカード名を「」ごと外してチップで出すため）
  - 裁定待ちの提案はそのまま（描写や配る操作で「今回は使われなかった」にしない。それはドライバーが選択肢をプレイしたときだけ）
- **GM の画面の「描写と選択肢」の枠** — `pages/gm/session-manage/ui/NarrationPanel.tsx` に切り出す（`AutoCombatPanel.tsx` と同じく、ページの大きな区画を別ファイルに）。見出しは「描写と選択肢を配る」（「進行中のシーン」「最近の進行」と紛れない名前）。ページの一番上（提案の裁定の前）に置く。セッションが進行中で、GM が自分（`useMe`）のときだけ出す
  - いまの描写を見せ、その下に描写の入力欄（複数行）
  - 手札の選択肢カードの一覧に、それぞれ「取り下げる」のチェック
  - 配る選択肢の行（名前・説明文・移り先のセレクト「このシーンに留まる（移り先なし）」＋`narrationTargets` の一覧）。「選択肢を足す」で行を増やし、行ごとに消せる。初期は0行。行には足したときに振る id を持たせ、React の key にする（途中の行を消しても入力がずれないように）
  - 「送る」ボタンは、シナリオを読み込み終え、`checkNarration` が OK のときだけ押せる。エラーはボタンの近くに出す（入力が空の初期状態では「何も変えない」を出さず、ボタンを押せないだけにする）。サーバーの 422 も出す。成功したら描写・取り下げのチェック・配る行を空に戻す
  - 結末のノードにいるときは、枠の上に「結末「〈名前〉」に着いた。結末の描写を書いて、セッションを終了できる」を出す（`isAtEnding`）
- **画面の行き来**
  - GM の画面：セッションの GM が自分で、かつ自分がドライバーの行があれば（GM が PL を兼ねるとき）、ページの見出しの近くに「ドライバーとしてプレイ画面へ」（`/pl/sessions/:id/play`）を出す
  - プレイ画面：セッションの GM が自分なら、HUD のリンク（`PlayPage.tsx` から渡す `links`）に「GMの画面へ」（`/gm/sessions/:id`）を足す。`widgets/play-screen/ui/play.tsx` は変えない
- **プレイ画面の結末の見出し** — 終了したセッションで「結末「〈シーン名〉」」を出すのを、いま居るノードが結末のとき（`isAtEnding`）だけにする。GM が結末以外のノードで終了を宣言すると、いまはそのシーン名が結末として出てしまい、この機能でその状態に入りやすくなるため。そのためにプレイ画面は、終了したセッションならシナリオを読む（いまは GM 不在のソロの終了時だけ読んでいる）
- **変更のフック** — `entities/session/api/mutations.ts` に `useNarrate`（`useSessionMutation` で作る）
- **プレイ画面のほかの振る舞いは変えない** — 移り先の無い選択肢を選ぶと「GMの描写を待っている」になるのも、移り先のある選択肢で遷移するのもいまのまま（GM が作ったカードもシナリオのカードと同じ経路で遷移する）
- **ルートの説明** — `shared/routes/routes.ts` の `/gm/sessions/:sessionId` の説明に「描写・選択肢を配る」を足す

### 実装後の AI レビューで足したもの

- **仕様の食い違いの裁定（人間）** — `party-and-session.md`「非同期セッションの進行」の「提案が出たときだけ、GMが選択肢を追加する」が、GM が描写のたびに配れることと食い違っていた。人間の裁定で仕様を「GMは描写のたびに選択肢カードを配ってよい。提案が出たときは、それに応えて追加する」に直した（経緯はノート）
- **取り下げの範囲（人間）** — GM の側から一時的に渡したもの全部（ノードに入ったときに配られたもの・GM がその場で作ったもの）。仕様の1行をそう明記した。実装は手札の `kind: 'choice'` のカード（いま PC 由来の選択肢カードは無い）
- **移り先付きのカードを GM が作れること** — ノートにしか書いていなかったので、仕様の「次のシーンへ進む」に1行足した
- **ドメイン** — `buildDealtCard`（作るカードの形）と `isEmptyNarration`（何も変えない入力か。画面が初期状態でエラーを出さない判定にも使う）を `narrate.ts` に足した。移り先のエラーはノード名で出す
- **フォームが古くなる場合** — 開いたあとで手札かシーンが変わったら、手札に無くなった取り下げのチェックと、選べなくなった移り先を state から捨てる（同じ ID のカードが配り直されてもチェックが戻らないように）。移り先を外した行には「シーンが変わったため、選べなくなった移り先を外した。」と出す。送信中は入力も止める。セッションが変わったら枠を作り直す（`key`）
- **結末の案内** — 枠の中の先頭に出す

### 実装後の AI レビューで見送ったもの

- GM が見ていたシーンと送ったときのシーンが違うときに断る（本文に「どのシーンを見て書いたか」を持たせる）— 非同期の同時編集の扱いはバックエンドのとき
- `/api/me` の読み込み失敗・プレイ画面のシナリオ読み込み失敗の表示 — 既存の画面と同じく黙って枠・見出しを出さない
- 描写・選択肢の名前の長さ、配る枚数の上限 — 仕様に無い
- 422 のあと入力を直しても、次に送るまで前回のエラーが出たまま
- 外したシーンを API に直接送ったときのエラーはノード名でなく ID で出る（画面からは選べない）
- 同じ ID のカードが配り直されたときにチェックが戻らないことの画面テスト（シードに、同じ手札へ戻る経路が無い）

## 5. 新規テストケース

テストの間で MSW の状態は `resetDb()` で戻る。ID の採番（`seq`）は戻らないので、生成された ID（`ss-…`・`ch-…`）はテストに直書きせず、返ってきた値から取る。

### `packages/domain/src/session/narrate.test.ts`

デッキは小さな手作りのもの：導入・シーン・入れ子のシーン（親の子）・NPC のノード・自動戦闘のシーン・結末。

`narrationTargets`
- 導入・シーン・入れ子のシーン・結末が、デッキの順で出る。入れ子のシーンの `label` は「〈親〉 › 〈子〉」
- NPC のノード・自動戦闘のノード・いま居るノードは出ない（いま居るノードを変えると、出なかったノードが出る）
- いま居るノードが無い（`currentNodeId` が undefined）と、除くのは種類と自動戦闘だけ

`checkNarration`

- 元の手札を書き換えない

`isAtEnding`
- 結末のノード（入れ子でも）なら true、シーンのノード・デッキに無い ID・undefined なら false

### 課題

### 解決策

- **仕様**：

  - 自分が GM のセッションでだけ受け付け、それ以外は 403
