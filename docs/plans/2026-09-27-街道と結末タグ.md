# プラン：街道と結末タグ（村スタート冒険者キャンペーン C4）

書式は `docs/process/index.md` の「プランドキュメントの8項目」。親プラン [村スタート冒険者キャンペーン](2026-09-23-村スタート冒険者キャンペーン.md) の C4 の詳細設計を、C2・C3 と同じ扱いで個別プランに切り出したもの。C4 の決定で親プランの記述を上書きした箇所は、親プラン側にも反映する（実装順タスク1）。

## 1. 概要

GM不在のソロシナリオ `sc-village-start` の村の広場と冒険者試験のあいだに「街道」のシーンを挟む。結末に至ったら、結末タグ「冒険者になった」をキャラクターへ即時に付ける。あわせて、シーンに入ったときの描写が「〇〇へ進んだ。」だけになる問題（C3 で既知の問題に記録）を、次のシーンへ進むカードの説明文を描写に使う形で直す。シナリオ名から「（仮）」を外す。旧チュートリアル「旅立ちの酒場」は撤去せず残し、どちらを入口にするかは**人間の判断待ち**とする（C4-1）。

**solo-village.md に足す仮ルール**：

1. **シーンに入ったときの描写** — GM不在のセッションでは、次のシーンへ進むカードに説明文があれば、それを移った先の描写にする。成長の効果を持つカードは、C3 どおり説明文＋効果の文。説明文が無ければ従来どおりシーン名だけ（「〇〇へ進んだ。」）。自動戦闘のシーンへ進むときは、説明文のあとに相手の登場の文を続ける
2. **結末タグ** — GM不在のセッションで結末のノードへ進んでセッションが終わったとき、そのノードが指す結末に結末タグがあれば、ドライバーのキャラクターへ即時に付ける。すでに持っていれば重ねない。描写とセッションのログに「結末タグ『〇〇』を得た」と出す

### 3-2. ドメイン型（`packages/domain/src/index.ts`）

```ts
DeckNode に追加:
  /** 結末のノードが指す結末（Scenario.endings の id）。kind === 'ending' のときだけ意味を持つ */
  endingId?: string;
```

### 3-3. シーン遷移（`packages/domain/src/sceneTransition.ts`）

- `planTransition` の引数 `scenario` を `Pick<Scenario, 'deck' | 'endings'>` にする
- `ended: true` のとき、ノードの `endingId` が指す結末の `grantsTag` を `endingTag` として返す
- 次のどれかなら `endingTag` は返さない
  - `endingId` が無い
  - 指す結末がシナリオに無い
  - 結末に `grantsTag` が無い
- 人間GMのセッションでは `ended` が false なので、`endingTag` も返らない

### 3-4. API（`apps/web/src/mocks/handlers.ts` の `/play`）

GM不在のセッションでだけ、次を行う。

- **描写**
  - 成長の効果が無く、説明文を持つカードで遷移したら、その説明文を `applyTransition` に描写として渡す
  - `applyTransition` は、自動戦闘のシーンでは渡された描写のあとに相手の登場の文を続ける
- **結末タグ**
  - `plan.endingTag` があれば、ドライバーのキャラクターの `endingTags` に足す（重複しない）
  - feed に「〇〇は結末タグ『冒険者になった』を得た」を記録する
  - 描写の末尾に「結末タグ『冒険者になった』を得た。」を足す
- 書き込みは C3 と同じく、遷移の検証がすべて通ってから行う

### 3-5. シナリオ（`apps/web/src/mocks/fixtures.ts`）

`villageScenario()` を次のように直す（`sc-village-start` と `sc-village-always-win` の両方に効く）。

- **シナリオ**
  - 名前を「村はずれの一歩」にする（`sc-village-always-win` はテスト用の名前のまま）
  - `endings: [{ id: '${p}-e-adventurer', name: '冒険者として旅立つ', grantsTag: '冒険者になった' }]` を持たせる
  - 結末のノードに `endingId` を付ける
- **広場の「街の冒険者ギルドへ向かう」**
  - 移り先を試験から街道（`${p}-road`）へ変える
  - 使える条件（`攻撃`）はそのまま
  - 説明文（村を発つ場面）を足す
- **街道（scene、`${p}-road`）**
  - 「辺りを眺める」：説明文だけ。GM不在の選択肢の描写で、その場に留まる
  - 「街の門をくぐる」：説明文あり、移り先は試験
  - 村へ戻る選択肢は置かない（C4-2）
- **説明文を足すカード**
  - 依頼へ行くカード3枚（依頼人の困りごと）
  - 「お店へ行く」「お店を出る」「村の広場へ向かう」
  - 「広場へ戻る」（依頼から引き返すカード）には足さない。説明文の無い遷移カードでは従来の描写になることの確認に使う
  - 「合格の証を受け取る」：結末の場面。試験・結末のノードは `examScenario()` のものなので、`villageScenario()` の側でこのカードに説明文を足す
- 文面は実装タスクで書く

## 決定事項（C4、2026-09-27、grilling による人間の判断）

1. **旧チュートリアル「旅立ちの酒場」は撤去せず残す。** 村スタートと酒場スタートのどちらを入口にするかは決めかねているため、人間の判断待ちとする。親プランの C4 の「旧チュートリアル置き換え」はこのサイクルでは行わない
2. **広場と試験のあいだに「街道」のシーンを挟む。** 選択肢は「辺りを眺める」と「街の門をくぐる」。村へ戻る選択肢は置かない
3. **GM不在のセッションでは、次のシーンへ進むカードの説明文を、移った先の描写にする**（solo-village.md の仮ルールを広げる）。シーンに導入文を持たせる案は、未解決論点に近づくので採らない
4. **結末タグは、GM不在のセッションでは結末に至った時点でキャラクターへ即時に付ける**（「所有者が選んで反映する」の例外。ソロでは所有者＝ドライバー）。所有者が選ぶ画面は作らない
5. **結末のノードに `endingId` を持たせ、`Scenario.endings` と結び付ける**（名前の一致では結び付けない）
6. **シナリオ名は「村はずれの一歩」（「（仮）」を外す）。** ルート `/pl/village-start` はそのまま。ホームの導線は「村はずれの一歩から始める」

### 描写の組み立て（3-4 を上書き。設計 P1-2、仕様 P2-2）

GM不在のソロで遷移したときの卓上の描写は、次の順で組み立てる。

1. 本文：成長の効果の描写（C3）＞ カードの説明文 ＞「〇〇へ進んだ。」。この3つのうち、最初に当てはまる1つを使う
2. 移った先が自動戦闘のシーンなら、本文のあとに相手の登場の文を続ける。成長の効果の描写も、これまでは上書きされていたが、続ける形に変える。説明文が無ければ、従来どおり登場の文だけにする（「〇〇へ進んだ。」は付けない）
3. 結末タグを得たら、最後に「結末タグ『〇〇』を得た。」を続ける

- 人間GMのセッションでは、従来どおり「〇〇へ進んだ。」または登場の文だけ
- 組み立ては `applyTransition` の中で行う
- feed の並び（新しい順）は、上から次のとおり
  - 結末タグを得た
  - 結末に至りセッションが終了した
  - 「〇〇」へ進んだ
  - プレイ
- 自動戦闘の登場のふるまいは auto-combat.md に1行足す

### 結末タグ（3-2・3-3・3-4 を補足。仕様 P1-1、設計 P2-4、テスト P1-3）

- **働く範囲**：「GM不在のソロ」とする。GM不在のセッションは、いまはソロ開始（start-solo）でしか作れない
- **即時反映の根拠**：「ソロでは所有者＝ドライバー」。称号タグには及ばない（solo-village.md に一言書く）
- **型**：`TransitionPlan` に `endingTag?: string` を足す
- **付与の関数**：`packages/domain/src/soloVillage.ts` に `grantEndingTag(character, tag)` を足す。重複させずに足した新しいキャラクターを返す純粋関数で、両側を単体テストにする
- **書き込み先**：成長の効果を適用した後のキャラクター（`actor`）
- **結末タグの持ち方**：実装は `Character.endingTags: string[]` で、仕様上の「カードの一種」ではない。この既存のずれは known-issues に記録する

### 画面の「仮」（3-6 を補足。設計 P1-4）

- GM不在のソロの結末で結末タグを得ているとき、完了表示に「結末タグの即時付与は仮ルール」と出す
- 判定は、feed に結末タグの記録があるかではなく、セッションが GM不在で終了していて、キャラクターの `endingTags` にそのシナリオの結末タグがあること
