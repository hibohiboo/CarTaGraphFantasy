# パーティー編成と非同期セッション参加

PCは複数のPLが持ち、自分または友人のPCを借りてパーティーを組み、非同期のセッションに参加する。

## ドライバーとナビゲーター

- **ドライバー** — パーティー全体の行動を代表して決定し、[カードをプレイする](play-and-field.md#plはカードをプレイすることでセッションに干渉する)担当者。**1パーティーにつき1人**。
- **ナビゲーター** — 会話・提案でドライバーを助言する参加者。**複数人**参加できる。カードを選んでプレイする権限は持たない（それはドライバーのみが行える）。

「PCごとに担当者がつく」のではなく「パーティー全体に対してドライバー1人」とする。

## PCの貸し借りとフィードバック

- PLは複数のPCを持ち、自分または友人のPCを借りてパーティーを組める。
- PCの所有者は、貸したPCについて**ナビゲーターとして参加するかどうかを任意で選べる**（参加しなくてもよい）。
- セッションに参加するPCのデータは**コピーされて**セッションに持ち込まれる（[セッションスナップショット](graph.md#セッションスナップショットとマージ)の構造を、グラフに限らずPCデータ全般に適用する）。
- セッション終了後、そのセッションの結果を**PCデータへフィードバックするかどうかは、PCの所有者が選べる**。ドライバー（借りた側）ではなく、所有者が最終判断者になる。
- フィードバックしないと決めた場合でも、[一次情報としてのセッションログ](../concept/index.md#セッションログの方針)は消えずに残る。PCデータという「正式な状態」への反映だけがスキップされる。
- 例外：GM不在のセッションの仮ルール（[自動戦闘](auto-combat.md#勝敗の扱い)で敗れたときに付く「再挑戦の記憶」、[村の成長](solo-village.md#即時反映例外)の能力値・カードの増減と結末タグ）は、所有者とドライバーが同じ人のため、セッション中に即時反映する（GM不在の募集から始めるときも、所有者が自分のPCだけを使う）。

## 非同期セッションの進行

- GMがあらかじめ選択肢カード・NPC会話カードなどを用意しておき、ドライバーはカードを選ぶだけで自動的にセッションを進行できる。
- GMは描写のたびに選択肢カードを配ってよい。新しい提案（[「新たな選択肢を提案」カード](play-and-field.md#新たな選択肢を提案カード)）が出たときは、それに応えて選択肢を追加する。それ以外は参加者それぞれが自由なタイミングで反応してよい。提案から裁定までの間の状態遷移は [提案の裁定待ちの間の状態遷移](play-and-field.md#提案の裁定待ちの間の状態遷移) を参照。
- **GM不在のセッションのGM** — [GM不在のセッション](solo-village.md#適用範囲)（システムが進行するセッション）では、GMは描写・選択肢を配る・取り下げることはしない。[ソロ開始](solo-village.md#適用範囲)のセッションには裁定するGMがいない（GMの欄は表示のためのダミー）。[GM不在の募集](scenario-flow.md#募集とセッション)から始めたセッションのGMは募集を出したGMで、提案の裁定とセッションの終了の宣言だけを行う。
- **ドライバーの離脱・交代** — ドライバーが応答しなくなった場合、元ナビゲーターやPCの所有者がドライバー役を引き継げる。
- **セッションの終了条件** — 次の組み合わせで判定する。
  - GMが用意したシナリオの内容を使い切ったとき
  - GMが任意のタイミングで「終了」を宣言したとき
  - GM不在のセッションでは、[「次のシーンへ進む」](play-and-field.md#基本操作セット)で結末のノードへ進んだとき（GM不在でないセッションでは、結末へ進んでもGMが終了を宣言するまで終わらない）
- **中断** — セッションを終わらせずに一時停止する。反応が無い期間で自動的に中断することはしない。理由は次の2つ。
  - ドライバーかGMが任意で中断したとき
  - [GM不在の募集](scenario-flow.md#募集とセッション)から始めたセッションで、提案の裁定を待つとき（[提案の裁定待ちの間の状態遷移](play-and-field.md#停止の粒度)の例外）
- **再開** — 中断したセッションは、ドライバーもGMもいつでも再開できる。ただし提案の裁定待ちは、GMが裁定するまで解けない（裁定待ちの状態を変えられるのはGMだけ）。GMは、自分のセッションのうち中断中のものに絞って確かめられる

## 軽量モードと濃密モード

通常のカード選択による自動進行を**軽量モード**、しっかり戦闘したい・NPCと細やかにやり取りしたい場面を**濃密モード**と呼ぶ。

切り替えは次の2通りを組み合わせる。

- GM／シナリオ製作者が、設計時に「このシーンは濃密モード」とあらかじめ指定しておく
- 戦闘イベントカードなど、特定のカード種別が濃密モードを自動的に要求する

その場のリクエストによる切り替え（PLが「もっと詳しくやりたい」と提案する）は、「新たな選択肢を提案」カードで行う。特別なルールは持たない。

例外として、GM不在のソロプレイの[自動戦闘（仮ルール）](auto-combat.md)は、PLが戦闘中に関与しないため濃密モードにせず、軽量モードのまま戦闘を決着させる。

濃密モードの戦闘のルールは[戦闘ルール](combat.md)、判定は[判定ルール](check.md)を参照。
