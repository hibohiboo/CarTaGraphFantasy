# 段階的な開示・習熟によるアンロック

プレイヤーの習熟・既読状況に応じて、扱えるコンテンツ（シナリオ制作・セッション参加など）が段階的に解放される。次の2つの軸があり、判定する対象が違うので同じ仕組みにはしない。

- **制作側の学習的アンロック** — 現実のプレイヤー（人間）の知識・理解度に基づくゲート
- **プレイ参加側のゲーム内アンロック** — キャラクター（フィクション内の存在）の能力に基づくゲート

## 制作側の学習的アンロック

ルールを読むと、そのルールを使うシナリオを作れる・運営できるようになる（例：戦闘ルールを読むと、戦闘を含むシナリオを作れる）。

- **対象** — シナリオを作る人と、既存のシナリオを選んで運営する GM。そのルールを使う行為（作る・運営する）をしようとしている人全般
- **判定** — 「読んだ」ボタンによる既読フラグの自己申告
- **既読状態の保存単位** — 未定（アカウント単位かローカル保存かは、実装のときに決める）

## プレイ参加側のゲーム内アンロック

戦闘に使えるスキルを取得すると、そのキャラクターで戦闘シナリオのセッションに参加できるようになる。

- **判定** — PL のキャラクターが、対応するスキルカードを[キャラクターデッキ](card-and-deck.md#キャラクターデッキ例)に持っているか。新しいデータは持たず、キャラクターデッキの中身を使う
- **シナリオ側の書き方** — シナリオ（またはシーン）カードに「推奨スキル／前提スキル」の[タグ](../glossary.md#タグ)を持たせ、キャラクターの保有スキルと突き合わせて表示する

## 強制力

制作側・プレイ参加側のどちらも、システムが機械的に「使えなくする／参加できなくする」**ハードロックにはしない**。「まだ読んでいません」「このスキルは未取得です」と表示・推奨するだけの**ソフトガイド**で、実際に使うか・参加させるかは人間（GM／PL）が判断する。

例外は次の2つ。

- [GM不在のソロの進行（仮ルール）](solo-village.md#配る条件使える条件)では、「使える条件」を満たさない選択肢カードを選べなくする。
- シナリオの結末に[再挑戦不可](scenario-flow.md#連作キャンペーンの表現結末タグ)が付いていれば、その結末の結末タグを持つPCは、同じシナリオに参加できない。人間GMのセッションでも止める（正式な例外）。
