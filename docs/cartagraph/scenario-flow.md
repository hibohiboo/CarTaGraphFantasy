# シナリオの構造とセッション開始までの流れ

シナリオが持つ構造・メタデータと、GMがシナリオを選んでセッションを開始するまでの流れを整理する。

## シナリオの基本構造

シナリオは、[カード・デッキの考え方](card-and-deck.md#シナリオデッキ例)にある「シナリオデッキ」の構成（NPCカード／情報カード／エネミーカード／シーンカード／ロケーションカード／イベントカード）と、入れ子構造（導入→シーンデッキA/B/C→結末）を持つ。

入れ子構造のノード間は、選択肢カードの効果[「次のシーンへ進む」](play-and-field.md#次のシーンへ進む)で移る。

## シナリオのメタデータ

GMがシナリオを選ぶ際の判断材料として、シナリオは次の属性を持つ。

- **シナリオタイプ** — [シナリオタイプ](scenario-type.md)の「戦闘なし」「判定なし」の宣言（宣言がなければ冒険、両方なら読み物）
- **前提スキル／推奨知識のタグ** — [段階的な開示・習熟によるアンロック](unlock.md#プレイ参加側のゲーム内アンロック)の、参加前提の目安。前作の[結末タグ](#連作キャンペーンの表現結末タグ)もこの前提タグの一種として扱う
- **想定人数** — パーティー人数（PCの数）の目安。ナビゲーターの人数には制限を設けない。下限に届かなくても、上限を超えても、セッションは始められる（画面に注意を出すだけ）
- **空間モデル** — [戦闘ルール](combat.md#空間モデル)の1次元／2次元の別（戦闘がある場合）。空間を持たない[自動戦闘（仮ルール）](auto-combat.md)だけを使うシナリオと、シナリオタイプが「戦闘なし」のシナリオでは指定しない
- **提案の扱い方** — [GMレスセッションでの提案の扱い](play-and-field.md#gmレスセッションでの提案の扱い)の「GM必須（デフォルト）／提案不可／自動解決」のいずれか。[GM不在の募集](#募集とセッション)では、募集でGMが選んだ値を使う
- **推奨CP** — [シナリオ難易度とCPの紐付け](character-growth.md#シナリオ難易度とcpの紐付け)の目安

## GMのカスタマイズ

「シナリオを選び、カスタマイズしたうえでセッション募集をする」の「カスタマイズ」は、主に**シナリオデッキの中から、今回使うカード・シーンを選ぶ／外す**ことを指す。難易度・数値パラメーターの調整や、世界設定の一部差し替えも、GMの裁量として許容する。

外したシーンは、その子孫のシーンも含めて、そのセッションに含めない。外したシーンへ進む選択肢カードは配らず、そこへは進めない。導入と結末のシーンは（外すシーンの子孫として巻き込まれる場合も含めて）外せない。外した結果、先へ進む選択肢が残らないシーンができても止めない（GMの裁量）。

## シナリオの入手元

GMはシナリオ集からシナリオを選ぶ。加えて、「シナリオ製作者」という別ロール（[グラフの役割](graph.md#グラフの利用者とロール別の見え方)）が新規シナリオを作成できる。「GM＝シナリオを選んで運営する人」「シナリオ製作者＝シナリオを作る人」という役割分担を基本としつつ、兼任は妨げない。

## シナリオの公開

シナリオ製作者は、シナリオを**下書き**として作り、直す。下書きは書きかけでもよい。

- **シナリオ集へ公開** — 製作者が下書きを公開すると、検査（シーンのつながり・シナリオタイプと中身の食い違いなど）を通ったものが**版**になり、シナリオ集に載る。検査に通らなければ公開できない。**公開版**は、シナリオ集で新しく始めるときに使う、いちばん新しい版。
- **公開し直す** — 公開した後も、製作者は下書きを直せる。直した下書きは、公開し直すまでGM・PLに届かない。公開し直すと、下書きの中身で新しい版ができ、それが公開版になる。版の中身は後から変わらない。前の版は、それで出した募集・始めたセッションのために残り、読める。
- **シナリオ集から外す** — 製作者は公開版をシナリオ集から外せる。外すと、そのシナリオから新しい募集を出すこと・ソロ開始はできなくなる。既にある募集とセッションは残り、既にある募集からは始められる（[GM不在の募集](#募集とセッション)からは、外した後も新しいセッションを始められる）。外したシナリオは、もう一度公開すればシナリオ集に戻る。外しても、公開版は読めるし、コピーもできる（外すのは新しく始めることを止めるためで、読むこと・コピーすることは止めない）。
- **新しく始められるシナリオ** — GMが募集を出せるのも、PLがソロ開始できるのも、シナリオ集に載っているシナリオだけ。一度も公開していない下書きからは始められない。ソロ開始は、始めたときの公開版で進む。
- **読めるのは公開した版** — 下書きを読み書きできるのは製作者だけ。製作者でない人は、公開した版（公開版と前の版）を読める。直したいときは、コピーする。
- **シナリオのコピー** — 公開版のあるシナリオなら、製作者でなくても、いちばん新しい公開版を自分の下書きとしてコピーできる（他人のシナリオも、シナリオ集から外したものも。デモ・テスト専用のシナリオを除く）。コピーは別のシナリオで、作者は自分、公開版のない下書きになり、題名は「〇〇のコピー」になる。題名以外は、結末タグ・前提タグ・再挑戦不可・初期装備も含めてそのまま写す。どのシナリオのどの版から作ったか（直接の親）を覚え、シナリオ編集と、シナリオのカスタマイズと募集の画面に「〇〇（作者：△△）のコピー」と親への導線を出す。親が外されても、公開し直されても、覚えた親は変わらない。[セッションスナップショット](graph.md#セッションスナップショットとマージ)のPCのコピーとは別のもの。

## 連作・キャンペーンの表現：結末タグ

セッション終了時、シナリオの結末を表す**結末タグ**（成功／失敗など）を、既存のカード種別（情報カード・特徴カードなど。新しいカード種別は増やさない）の一種として、PCへ配ることができる。GM不在のソロプレイでは例外として、結末に至った時点でキャラクターへ即時に付ける（[GM不在のソロの仮ルール](solo-village.md#結末タグ)）。

- シナリオの結末は「成功／失敗」の2値に限らず、**任意の数の結末**を定義してよい（結末ごとに結末タグを配れる）（例：「英雄的勝利」のような追加の結末）。
- 結末タグのカードは、どのシナリオのどの結末で得たかと、再挑戦不可かを、得たときの版のまま持つ。
- 結末ごとに**再挑戦不可**を付けられる。再挑戦不可の結末で得た結末タグのカードを持つPCは、同じシナリオをもう一度遊べない。通常の募集への応募・GMによる開始・[GM不在の募集](#募集とセッション)からの開始の、どの始め方でも止める（[アンロックの強制力](unlock.md#強制力)の例外）。製作者が後から再挑戦不可を付け外ししても、既にカードを持つPCには及ばない。失敗の結末に付けなければ、失敗したPCは再挑戦できる。結末タグを配る結末にだけ付けられる。
- 後続シナリオの前提条件は、この結末タグと[前提スキルのタグ](unlock.md#プレイ参加側のゲーム内アンロック)を、まったく同じタグ突き合わせの仕組みで判定する。カードそのもの（特定の1枚）を直接指定する形は取らない。

## セッション開始までの全体フロー

1. GMがシナリオ集からシナリオを選ぶ。
2. GMがシナリオデッキの中から使うカードを取捨選択してカスタマイズする（必要なら難易度・設定も調整）。
3. GMが募集を出す（想定人数、前提タグ、シナリオタイプ、空間モデルなどを明示）。募集は、出したときの公開版で進む。
4. PL（ドライバー候補）が、条件を満たす自分／借りたPCで応募する。
5. GMが応募の中から参加させるPCを選び、そのうち1つをドライバーのPCにする。ドライバーのPCを応募した人がドライバー、ほかのPCを応募した人がナビゲーターとして加わる。
6. 参加PCのデータがコピーされ（[セッションスナップショット](graph.md#セッションスナップショットとマージ)）、セッション開始。セッションは募集を出したときの版で最後まで進み、後から製作者が公開し直しても変わらない。
7. セッション終了後、結末タグを含む結果が、参加したすべてのPCへ反映される（[PCの貸し借りとフィードバック](party-and-session.md#pcの貸し借りとフィードバック)）。

[GM不在の募集](#募集とセッション)では、3〜7の代わりに次のように進む。

1. GMがGM不在で募集を出す（提案の扱いを選ぶ）。
2. PLが自分のPCを選んで始める。そのPLだけのセッションができる（PCのデータをコピーし、募集を出したときの版で最後まで進む。上の6と同じ）。
3. システムが進行する（[GM不在のソロの進行（仮ルール）](solo-village.md)）。提案が来たときだけ、GMが裁定する。
4. 結末に至ると終わり、結果はその場でPCに反映される（[即時反映](solo-village.md#即時反映例外)）。

## 募集とセッション

募集は、セッションを始めるための、セッションとは別のもの。GMがシナリオから募集を出す。募集には通常の募集とGM不在の募集がある。

- **通常の募集** — PL（ドライバー候補）がPCを指定して応募し、GMが応募の中から選んでセッションを始める。始めると開始済みになり、一覧から消える（募集1つからセッション1つ）。
- **GM不在の募集** — 応募は無く、PLが自分のPC（所有者が自分のPCだけ。借りたPCは使えない）を選んで、すぐに始める。始めるたびに、そのPLだけのセッションができ、募集したGMの管理するセッションに加わる。募集は受付中のまま残り続ける（募集1つからセッションが複数）。同じPLが何度でも始められる。
  - 提案の扱いは、募集ごとにGMが「GMが後から裁定」か「提案不可」を選ぶ（[GMレスセッションでの提案の扱い](play-and-field.md#gmレスセッションでの提案の扱い)）。シナリオが提案不可なら提案不可。
  - 先へ進む選択肢の無いシーンがあっても、募集は止めない（画面に注意を出す）。「GMが後から裁定」なら、提案をGMが移り先付きで採用することで抜けられる。

## 前提条件チェックの扱い

シナリオの前提タグを満たさないPCの応募は、システムがブロックする**ハードロックにはしない**。応募自体は自由に行え、最終的な参加可否はGMが判断する**ソフトガイド**とする（[アンロックの強制力](unlock.md#強制力)と同じ）。

[再挑戦不可](#連作キャンペーンの表現結末タグ)は、前提タグのソフトガイドとは別の仕組みで、システムが止める（ハードロック）。
