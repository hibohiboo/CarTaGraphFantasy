# キャラクターの成長とキャラメイク（CP制）

セッションを通じたキャラクターの成長と、CP（キャラクターポイント）によるキャラメイクの仕組みを整理する。

## 成長の基本メカニズム

セッションクリア時、PCは次の2つのルートでカード・成長を得る。

- **報酬カード** — シナリオがあらかじめ用意した特定のカード（例：「このシナリオを終えると"炎の剣"を手に入れる」）を無償で獲得する。物語に密着した成長。GM不在のソロプレイで依頼の解決ごとに受け取りお店で手放す[引換カード](solo-village.md#引換カードとお店)（仮ルール）は、報酬カードとは別物である。
- **CP（キャラクターポイント）** — 汎用的なポイントとして獲得し、既存のカードプールから好きなカードと交換できる。

## CP予算はハードな制約

CP制によるキャラメイクは、合計CPを超えるカード選択を機械的に禁止する**ハードな予算制約**とする。ただし、GMがシナリオ上の理由で例外的にカードを与えること（「NPCから特別に譲り受けた」等）は妨げない。

## 解放済みカードプール

2人目以降のPCを作るとき、既に獲得したカードを選択肢に含められる。

- **プールは「選択肢の解放」であり、無償配布ではない** — プールに入ったカードも、新規PC作成時にはCPを払って選ぶ。新規PCも1人目と同じCP予算でキャラメイクする。
- **プールの保存単位はプレイヤー単位** — 概念としてはプレイヤー単位（アカウントに紐づく）で持つ。具体的な保存方法（アカウントに紐づけるかローカル保存か）は未定（アカウントシステムの設計時に決める）。
- **プールへの追加タイミング** — PCがカードを獲得した時点でプールに追加される実績として扱う。PCの生死・現在の所持状況とは切り離し、PCが引退・死亡してもプールは失われない。

## CPで選べるカードの範囲

新規PC作成時にCPで選べるのは、「基本カードプール（誰でも最初から選べるシステム標準のカード）」＋「プレイヤー固有の解放済みプール（前節）」の合計とする。共有設定全体を無条件に選べるわけではない。

## シナリオ難易度とCPの紐付け

[シナリオのメタデータ](scenario-flow.md#シナリオのメタデータ)に「推奨CP」を持たせる。前提スキル・想定人数などと同様、[前提条件チェックの扱い](scenario-flow.md#前提条件チェックの扱い)に沿って**ハードロックにはせず**、GMが募集を出す際に明示する目安（ソフトガイド）とする。

## CP付与の構造

シナリオは「クリア時に必ずもらえる基本CP」を持ち、GMはそれに加えて、セッション中の活躍や次節の称号タグの内容などを踏まえて裁量で追加CPを上乗せできる（2階建て）。

## 称号タグとの関係

[称号タグ](comparison-and-titles.md#称号タグ)の獲得数を機械的にCPへ変換する仕組みは持たない。GMが前節の追加CPを裁定する際、称号タグの多さ・内容を参考材料の一つとして考慮してよい。

## この章の設計原則

1. 成長は「物語に密着した報酬カード」と「自由に選べるCP」の両方を組み合わせる。
2. CP予算はゲームバランス管理としてハードな制約とし、物語上の判断のソフトガイド方針とは別軸で扱う。
3. 解放済みカードプールは「選択肢の解放」であり無償配布ではない。CP予算という共通の土俵の上で選択肢だけが広がる。
4. シナリオ側のCPの目安（推奨CP）は、前提条件チェックと同じくソフトガイドとする。
5. 称号タグのような人間の評価に関わる情報は、機械的な計算式に組み込まず、GMの裁量による裁定の参考材料にとどめる。

基本CP量・カードごとのCPコストの数値の目安は[数値バランスの相場観](balance.md)を参照。厳密な数値表そのものは実装・プレイテストのフェーズで確定する。
