# 集約とドメインイベント

[境界づけられたコンテキスト](bounded-contexts.md)の中で、集約（1回の変更でいっしょに整合を保つ範囲）・値オブジェクト・ドメインイベントを決める。保存の単位と、集約をまたぐ整合の取り方をはっきりさせるため。ドメイン駆動設計の戦術的設計にあたる。決めた理由・採らなかった案は[デザイナーノート](../notes/architecture/aggregates.md)にある。

## 書き方の方針

- **集約は zod スキーマの型のまま** — クラスにしない。型の正は `packages/domain` の `model.ts`（[アーキテクチャルール](../process/rules/architecture.md)「packages/domain の中の置き場所」）
- **操作は純粋関数** — 集約と入力を受け取り、「新しい集約と、起きたイベント」か「断る理由」を返す。保存・イベントの配信・時刻・乱数は外側（MSW のハンドラ、将来のバックエンド）が受け持つ（同「副作用の分離」）
- **集約の外は id で指す** — ほかの集約を中に持たない。1回の変更で書き換えるのは1つの集約だけにし、集約をまたぐ整合はイベントで後から合わせる
- **集約の中だけを根から変える** — 集約の中の部分（シナリオデッキのノード、応募、提案など）は、根の集約の操作を通して変える

## 集約の一覧

| コンテキスト | 集約 | 中に持つもの | 守る不変条件 |
|---|---|---|---|
| シナリオ製作 | シナリオ | 下書き（シナリオデッキ・結末など）・シナリオ集に載っているか・最新の版番号 | 下書きを読み書きできるのは製作者だけ。参照されているノードは消せない。検査を通らなければ公開できない。版番号は公開のたびに1ずつ増える。一度も公開していなければシナリオ集に載らない |
| シナリオ製作 | 版 | 公開したときの下書きの中身（シナリオ id ＋版番号で指す） | 作ったら中身が変わらない |
| セッション運営 | 募集 | 公開版の指し先（シナリオ id ＋版番号）・応募・外したシーン・提案の扱い | 通常の募集からはセッションを1つだけ始める（始めたら開始済み）。GM 不在の募集は受付中のまま残る。シナリオ集に載っていないシナリオからは出せない |
| セッション運営 | セッション | 版の指し先・参加者（ドライバー・ナビゲーター・GM）・GM 不在か・状態（進行中・中断・終了）・中断の理由 | ドライバーは1人。裁定待ちの中断を解けるのは GM だけ。終了したら戻らない |
| プレイ | セッションスナップショット | 持ち出した PC のコピー・場・手札・いまのシーン・提案・語りの記録・自動戦闘の状態と記録 | カードをプレイできるのはドライバーだけ。シーンの遷移は版のシナリオデッキに沿う。提案の状態は決まった順にしか移らない（承認待ち → 採用・却下） |
| キャラクター | キャラクター | 能力値・HP・基本行動値・キャラクターデッキ・称号・CP | 変えられるのは所有者だけ。作成時の CP の予算はハードな制約 |
| キャラクター | 解放済みカードプール | プレイヤーが得たことのあるカード | プレイヤー単位。PC が引退・死亡しても減らない |

- **セッションとセッションスナップショットは同じ id の1対1** — セッションを始めると両方ができる。参加者の役割（誰がドライバーか）は、セッションを始めたときにスナップショットへコピーし、プレイの判断はスナップショットの中だけで済ませる
- **判定・戦闘は集約を持たない** — 値オブジェクトと純粋関数だけ。自動戦闘の状態は、セッションスナップショットが持つ
- **利用者は一般の業務領域** — アカウントとロールは外部サービスに任せる前提で、ここでは集約を決めない。既読のルール（[段階的な開示](../cartagraph/unlock.md)）は、着手するときに決める
- **将来のコンテキスト**（グラフ・ライブラリ、進化）の集約は、着手するときに決める

## 値オブジェクト

作ったら変わらず、中身で比べる値。

| 値オブジェクト | 使うコンテキスト |
|---|---|
| カードの定義（共有カーネル） | 利用者を除くすべて |
| シナリオ id ＋版番号の組 | セッション運営・プレイ |
| 能力値・HP・CP | キャラクター・判定・戦闘・プレイ |
| 判定・ダイス式・戦闘の効果 | 判定・戦闘・プレイ |
| 配る条件・使える条件・成長の効果 | プレイ |
| 結末タグの情報（どのシナリオのどの結末か・再挑戦不可か） | キャラクター・セッション運営（再挑戦不可の検査） |
| シナリオタイプ・提案の扱い | シナリオ製作・セッション運営・プレイ |

## ドメインイベント

集約やコンテキストの間で「起きたこと」を伝える。過去形で名づける。

| イベント | 起こす集約 | 受け取る側と、すること |
|---|---|---|
| シナリオを公開した | シナリオ | 版を作る。セッション運営は新しい公開版から募集・ソロ開始ができる |
| シナリオ集から外した | シナリオ | 新しい募集・ソロ開始を止める（既にある募集・セッションは残る） |
| セッションを始めた | 募集（ソロ開始はシナリオの公開版から） | セッションとセッションスナップショットを作る。PC のデータをコピーして持ち出す |
| 提案が出た | セッションスナップショット | GM 不在の募集から始めたセッションなら、セッションを中断（裁定待ち）にする |
| 提案を裁定した | セッションスナップショット | 裁定待ちの中断を、再開できる状態にする |
| 結末に達した | セッションスナップショット | GM 不在のセッションなら、セッションを終了にし、結末タグをキャラクターへ即時に付ける |
| 成長した | セッションスナップショット | GM 不在のセッションなら、能力値・カードの増減をキャラクターへ即時に反映する（[即時反映](../cartagraph/solo-village.md#即時反映例外)） |
| セッションが終わった | セッション | PC の所有者が、結果をキャラクターへ反映するかを選べるようにする（[PCの貸し借りとフィードバック](../cartagraph/party-and-session.md#pcの貸し借りとフィードバック)） |
| カードを得た | キャラクター | 解放済みカードプールに足す |

## いまのコードとの対応

いまのコードは、集約の操作の一部を純粋関数として持っている（`scenario/edit.ts` の下書きの編集、`session/transition.ts` のシーンの遷移、`session/start.ts` の開始の検査など）が、イベントは返していない。イベントの配信と集約をまたぐ反映は、MSW のハンドラ（`apps/web/src/mocks/handlers.ts`）がその場で書き換えている。

食い違いのうち、集約の境界に関わるものは[既知の問題](known-issues.md#ドメインモデル)にある（セッションが PC をコピーせず参照している件、GM 不在でないセッションで結末タグが PC に反映されない件も、上のイベントが無いことの表れ）。コードを組み替えるかは、バックエンドで保存の単位を作るときに別のプランで判断する。
