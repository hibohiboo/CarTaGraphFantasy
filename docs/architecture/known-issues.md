# 既知の問題

実装で見つかった不具合や、レビューで見送った課題（P2 など）を、直すまでの間ここに置く。

- **ここに置くもの** — アプリ・テスト・ドキュメントの実装上の問題。ゲームの仕様として決まっていない論点は[未解決論点トラッカー](../open-questions.md)に、開発プロセスの改善候補は[体制の進化ログ](../process/evolution.md)に置く
- **足すとき** — 1件ごとに「何が起きるか」「どこで見つかったか」「直すときの目安」を書く。[レビュールール](../process/rules/review.md)で「TODO 化」と決めた指摘も、ここに書く
- **直したとき** — その項目を消す（経緯は git の履歴とプランに残る）。直す作業のプランには、ここから項目を引用する

## 画面

### 自動戦闘の設定中に、プレイ画面のレイアウトが崩れる

- **起きること** — 自動戦闘のシーン（村スタートの冒険者試験）で、「戦い方を決める」パネルの上に、卓上の描写（GMの台詞カード）が重なって表示される。本来は台詞カードの下に出る案内文（「戦い方を決めて、戦闘を始めよう。」）も、台詞カードの横に出る
- **見つけた経緯** — 2026-09-27、PR #6（C2）の人間レビューで、ブラウザで確認して発見
- **原因の見立て（未調査）** — プレイ画面は HUD・卓・手札を1画面に収める縦並びのレイアウト（[試作の引き継ぎ](prototype-handover.md)「1画面完結レイアウト」）。自動戦闘のときだけ、手札の代わりに高さのある `AutoCombatPanel` が入り、1画面に収まらずに卓と重なっていると思われる
- **直すときの目安** — パネルを下からのシートに出す、またはこの状態の画面だけスクロールできるようにする。E2E か目視で崩れないことを確かめる

### 自動戦闘の全挑戦の記録を見る画面が無い

- **起きること** — 全挑戦の経過は `Session.combatHistory` に残るが、画面に出るのは直前の挑戦（`autoCombat.lastResult`）だけ。結末へ進むと、それも見えなくなる
- **見つけた経緯** — C2 の実装レビュー（`docs/plans/2026-09-23-自動戦闘エンジン.md`）
- **直すときの目安** — セッションのログ（feed）か、キャラクターシートから挑戦の一覧を開けるようにする

### 人間GMのセッションで、「GMの描写を待っている」が GM の台詞として出る

- **起きること** — 卓上の描写はすべて「GM」の台詞カードで出すため、人間GMのセッションで簡易スクリプトの無い選択肢を選ぶと、「『〇〇』を選んだ。GMの描写を待っている。」が GM の台詞になり、GM 自身が GM を待っている形になる。行動カードの「〇〇は『斬撃』を使った。」も同じ
- **見つけた経緯** — PR #6 の導入体験の修正のレビュー
- **直すときの目安** — 待ち状態の文言を、台詞カードではなく案内文（ヒント）に出す

## データ・API（MSW）

### 同じ自動戦闘のシーンに戻ると、敵カードが場に増える

- **起きること** — 自動戦闘のシーンに入るたびに、シナリオの定義から敵カードを新しくコピーして場に置く。一度出たシーンに戻ると、前回の敵（勝っていれば「戦闘不能」付き）が場に残ったまま2枚目が加わり、挑戦回数も0から数え直しになる
- **見つけた経緯** — C2 の実装レビュー
- **いまは起きない理由** — 検証用シナリオは導入→試験→結末の一本道で、試験に戻る選択肢が無い
- **直すときの目安** — シーンを移るときに場のカードをどう片付けるかは仕様に無い。行き来できるシーンを作る C3（村パート）で仕様を決めてから直す

### 手札に配る選択肢カードが、シナリオ定義のオブジェクトをそのまま参照している

- **起きること** — ソロ開始・シーン遷移・勝利時に配る選択肢カードは、`db.scenarios` 内のカードオブジェクトそのもの。いまは手札のカードを書き換える処理が無いので実害は無いが、将来カードのタグなどを書き換えると、シナリオ側にも波及する
- **見つけた経緯** — C2 の実装レビュー
- **直すときの目安** — 敵カードと同じく、配るときに複製する

### GM不在の選択肢の描写で、境界の扱いが甘い

- **起きること** — 選んだカードを手札から消すときに ID で絞り込むので、同じ ID のカードが手札に複数あると全部消える。カードの説明文が空文字だと、定型文に切り替わらず空の描写になる
- **いまは起きない理由** — 提案から生まれるカードの ID は一意で、説明文が空文字のカードも無い
- **見つけた経緯** — PR #6 の導入体験の修正のレビュー
- **直すときの目安** — 選んだ1枚だけを消す、空文字も定型文にする

### 「提案の扱い」がGM必須のシナリオを、GM不在で始められてしまう

- **起きること** — `POST /api/scenarios/:id/start-solo` はシナリオの提案の扱い（GM必須／提案不可／自動解決）を確かめない。GM必須のシナリオをソロで始めると、提案が裁定待ちのまま残る
- **いまは起きない理由** — ソロで始められる導線は、自動解決・提案不可のシナリオにしか無い
- **見つけた経緯** — PR #6 の導入体験の修正のレビュー
- **直すときの目安** — GM必須のシナリオは start-solo を 422 にする

### 「再挑戦の記憶」のタグの付け方が、ほかの特徴カードと揃っていない

- **起きること** — 敗北時に付ける特徴カード「再挑戦の記憶」は `tags: ['特徴']`。既存の特徴カードは内容を表すタグ（「感覚」「対人」など）を付けている
- **見つけた経緯** — C2 の仕様整合レビュー
- **直すときの目安** — C3 で依頼・お店のカードのタグを決めるときに合わせる

## テスト

### 自動戦闘のテストに、fixtures の値の書き写しがある

- **起きること** — `apps/web/src/test/AutoCombat.test.tsx` の `PREFIX`（シナリオIDとノードIDの接頭辞の対応）と、初期装備の HP20・行動値10 は、`mocks/fixtures.ts` の値をテストに書き写している。[テストルール](../process/rules/testing.md)の「fixtures.ts にない独自のマジック値を作らない」に反する
- **見つけた経緯** — C2 の異常系レビュー
- **直すときの目安** — fixtures から `soloStarter` と試験シナリオの接頭辞を export して参照する

### テスト専用のシナリオが、本番のシナリオ一覧のデータに入っている

- **起きること** — `sc-exam-always-win` などのテスト専用シナリオ（C1 の `sc-village-no-propose` も同じ）が、`fixtures.ts` の `scenarios` 配列に入っている。draft・システム作成なので一覧 API には出ないはずだが、GM・制作者のシナリオ一覧画面に出ないかは確かめていない
- **見つけた経緯** — C2 の異常系レビュー
- **直すときの目安** — 一覧画面で出ないことを確かめるテストを足すか、テスト専用のデータを分ける

## ドキュメント・用語

### 「GMレス」と「GM不在のソロ」の用語が揺れている

- **起きること** — 正式ページ・コード・プランで「GMレス（セッション）」「GM不在の1人プレイ」「人間GMのいないセッション」が混在している。「結末で自動終了する」はGM不在のセッション全般、「自動戦闘」はGM不在の1人プレイに限る、という範囲の違いも読み取りにくい
- **見つけた経緯** — C2 の仕様整合レビュー（「結末／エンディング」の揺れは 2026-09-27 に「結末」へ統一済み）
- **直すときの目安** — 用語集に1語を定義し、範囲の違いを書き分ける

### ダミーGM（`SYSTEM_GM_ID`）の扱いが正式ページに書かれていない

- **起きること** — GM不在のセッションに割り当てるダミーGMは、コード（`packages/domain`）のコメントが根拠をプランに置いている。プランは正式仕様（SSOT）ではない
- **見つけた経緯** — C2 の仕様整合レビュー
- **直すときの目安** — `party-and-session.md` か `play-and-field.md` に、GM不在のセッションの GM の扱いとして書く

### 共通部品 `NameProposal` が、ページ側の CSS を読んでいる

- **起きること** — `components/NameProposal.tsx` が、入力シートの見た目のために `pages/pages.module.css` のクラスを読んでいる。ほかの部品は自前の CSS を持っており、依存の向きが逆になっている
- **見つけた経緯** — PR #6 の導入体験の修正のレビュー
- **直すときの目安** — シート用のクラス（`sheetOverlay`・`sheetBackdrop`・`proposeSheet`）を共有の置き場所に移す。旅立ちの酒場のほかのシートも同じクラスを使っているので、あわせて直す

### シミュレーションのスクリプトが型検査の対象外

- **起きること** — `scripts/simulate-auto-combat.ts` は `tsx` で実行するだけで、`web:typecheck`・`domain:typecheck` の対象外（既存の `scripts/*.mjs` と同じ扱い）。リポジトリに `@types/node` が無いため
- **見つけた経緯** — シミュレーションの仕組み化（C2）
- **直すときの目安** — `@types/node` と scripts 用の tsconfig を足し、型検査のコマンドに加える
