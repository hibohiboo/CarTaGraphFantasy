# 業務領域の分類

カルタグラフのサービスを業務領域（サブドメイン）に分け、中核・補完・一般の3つに分類する。どこに設計と作り込みの手間をかけ、どこを簡素に・既製品で済ませるかを決めるため。ドメイン駆動設計の戦略的設計の最初の段階にあたる（2段階目は[境界づけられたコンテキスト](bounded-contexts.md)）。

「事業」は[ロードマップ](../roadmap.md)のゴール（遊ぶことでゲーム自体が進化していく TRPG を、複数人がブラウザで遊べるサービスとして公開する）と読み替える。決めた理由・将来の候補は[デザイナーノート](../notes/architecture/domain-map.md)にある。

## 分類の基準

| 分類 | 原語 | 基準 | 作り方 |
|---|---|---|---|
| 中核 | core subdomain | このゲームが他と違う理由になる。複雑で、遊ぶほど変わり続ける | 自前で作り込む。モデルと用語を最も丁寧に扱う |
| 補完 | supporting subdomain | 遊ぶのに要るが、違いは生まない。既製品が無い | 自前で作るが、簡素でよい |
| 一般 | generic subdomain | どのサービスでも同じ問題 | 外部サービス・既製品で済ませる |

分類は固定ではない。補完が中核に上がることも、中核が一般に下がることもある。分類を変えたら、このページを直す。

## 業務領域の一覧

シナリオから遊ぶまでは「シナリオ製作 → セッション運営 → プレイ」の3段階で、それぞれを別の業務領域にする。

| 業務領域 | 分類 | 何をするか | 仕様 | いまのコード（`packages/domain/src/`） |
|---|---|---|---|---|
| 進化ループ | 中核 | 遊んだ結果から進化候補を記録・評価・採用し、カードやルールを育てる | [コンセプト](../concept/index.md#進化ループ) | 未実装 |
| シナリオ製作 | 中核 | カードでシナリオを組み、行き止まりを見つけ、版を出して公開する | [シナリオの構造と開始までの流れ](../cartagraph/scenario-flow.md)・[シナリオタイプ](../cartagraph/scenario-type.md) | `scenario/` |
| プレイ | 中核 | デッキ・場・手札でカードを出し、プレイし、裏返し、移す | [場・手札・プレイ](../cartagraph/play-and-field.md)・[カード・デッキの考え方](../cartagraph/card-and-deck.md)・[カードの裏表](../cartagraph/card-face-back.md) | `session/`（遷移・語り・デッキ）・`card/` |
| グラフ | 中核 | 関係性を辿る正史グラフと PC 発見グラフ | [グラフの役割](../cartagraph/graph.md) | 未実装（共有設定だけ `library/`） |
| セッション運営 | 補完 | 募集・応募・確定から、セッションを立てて始めるまで | [シナリオの構造と開始までの流れ](../cartagraph/scenario-flow.md)・[パーティー編成と非同期セッション参加](../cartagraph/party-and-session.md) | `session/`（開始）・`scenario/replay.ts`（再挑戦不可） |
| キャラクター作成・成長 | 補完 | キャラメイクと CP による成長、称号 | [成長とキャラメイク](../cartagraph/character-growth.md)・[PC間の比較体験と称号タグ](../cartagraph/comparison-and-titles.md) | `character/` |
| 判定・自動戦闘 | 補完 | 能力値の判定と、自動戦闘の解決。数値のシミュレーションを回せる状態を保つ | [判定ルール](../cartagraph/check.md)・[戦闘ルール](../cartagraph/combat.md)・[自動戦闘](../cartagraph/auto-combat.md)・[数値バランスの相場観](../cartagraph/balance.md) | `check/`・`autoCombat/` |
| ソロの村 | 補完 | GM 不在のソロの進行（村はずれの一歩） | [GM不在のソロの進行](../cartagraph/solo-village.md) | `soloVillage/` |
| ライブラリの共有 | 補完 | 正史グラフの設定を共有する | [グラフの役割](../cartagraph/graph.md) | `library/` |
| 段階的な開示 | 補完 | 習熟に応じてカードやロールを解放する | [段階的な開示とアンロック](../cartagraph/unlock.md) | `user/` |
| ルールブックの閲覧 | 補完 | ルールの要約を読ませる | — | `apps/web/src/shared/content/` |
| 認証・ユーザー管理 | 一般 | ログイン・アカウント | — | 未実装（バックエンド着手時） |
| 画像の保存 | 一般 | PC の画像などを置く | — | 未実装 |
| API ドキュメント | 一般 | API の一覧を文書にする | [Webアプリの仕組み](web-app.md#api-ドキュメント) | OpenAPI・Redoc（既製品） |

コードのディレクトリは仕様のページに合わせて分けてあり（[アーキテクチャルール](../process/rules/architecture.md)「packages/domain の中の置き場所」）、業務領域とは1対1になっていない（`session/` がプレイとセッション運営の両方を持つ、など）。コードとの対応は[境界づけられたコンテキスト](bounded-contexts.md#いまのコードとの対応)にある。

## 見直しのきっかけ

分類と、[実装パターン](implementation-patterns.md)で選んだパターンは、次のことが起きたら見直す。起きるまでは変えない。見直したら、このページか実装パターンのページを直し、理由をデザイナーノートに足す。

| きっかけ | 見直すこと |
|---|---|
| キャラクターの成長が進化ループにつながる（成長の経緯を読む仕様ができる） | キャラクター作成・成長を補完から中核へ上げる。キャラクターの業務ロジックを、ドメインモデルからイベント履歴式ドメインモデルに変えるかを決める |
| GR-5（正常終了のときだけ発見をマージする）や破棄が入り、終わり方によって反映する先を選んだり取り消したりするようになる | 「セッションの終わり」を、プロセスマネージャーでまとめる形に変えるかを決める（[連携の実装](implementation-patterns.md#連携の実装)） |
| 長いセッションで、イベントの列を頭から畳むのが重くなる | 列の途中までを畳んだ状態を保存して、そこから畳む（途中の状態のキャッシュ） |
