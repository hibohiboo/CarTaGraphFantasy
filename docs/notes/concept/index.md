# デザイナーノート：コンセプト

対応する仕様：[コンセプト](../../concept/index.md)

## 人間の役割

- 将来的には、世界・設定の管理者など、役割を追加する可能性がある
- エージェントによる進化候補の自動発見・分析は、将来の支援機能として考える。まずは人間がセッションやログを見て発見する

## セッションログを自然言語で残す理由

最初から完全な構造化ログを要求すると、自然なプレイを阻害したり、ログ記録の負担が増える可能性がある。そのため、まず完全な自然言語ログを保存し、分析・構造化は後段で行う。

## 評価基準を機械的なスコアにしない理由

「面白さ」「汎用性」「プレイヤー評価」は観点として明文化するにとどめ、最終判断は採用判断者の自由裁定とした。[場・手札・プレイ](../../cartagraph/play-and-field.md)の発火条件や[段階的な開示・習熟によるアンロック](../../cartagraph/unlock.md)のソフトガイドと同様、「機械的な自動判定より人間の裁量を優先する」という一貫した方針に沿う。

## 将来の拡張候補・採らなかった案

- 複数セッションでの再発の検知に、自動類似度判定のような高度な仕組みを使う。現時点ではスコープ外とした（まずはカテゴリ・タグで同じ候補を一覧できるようにする）
- セッション中の想定外の行動への対応を、エージェントが支援する

  ```text
  PLの想定外行動
  ↓
  エージェントが可能性を提示
  ↓
  GMが選択・修正
  ↓
  GMが結果を返す
  ↓
  結果をセッションログに記録
  ↓
  将来的に進化候補として分析
  ```

  ただし、これは進化システムそのものではない。エージェントなしでも「セッション → ログ → 人間による分析 → 進化候補」という流れは成立することが重要
