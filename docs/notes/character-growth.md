# デザイナーノート：キャラクターの成長とキャラメイク（CP制）

対応する仕様：[キャラクターの成長とキャラメイク（CP制）](../cartagraph/character-growth.md)

## 経緯

成長の基本メカニズムから称号タグとの関係まで、grilling による深掘りで決めた。

## 報酬カードと CP の両方にした理由

両方を組み合わせることで、物語に根ざした成長と、プレイヤーが自由に選べる成長を両立させる。これは[進化ループ](../concept/index.md#進化ループ)における「セッション経験の蓄積」とも一貫する。

## CP予算だけハードな制約にした理由

これまでの「機械的な自動判定より人間の裁量を優先する」という一貫方針（[段階的な開示・習熟によるアンロック](../cartagraph/unlock.md#強制力)、[提案の裁定待ちの間の状態遷移](../cartagraph/play-and-field.md#提案の裁定待ちの間の状態遷移)など）は、主に GM 裁定・物語上の判断に関するものである。ポイント制キャラメイクによるゲームバランス管理は別軸の話として扱った。

推奨 CP をソフトガイドにしたのも同じ切り分けで、CP 予算は個々のキャラメイクの中ではハードだが、「どのシナリオに参加するか」の判断はソフトガイドを貫く。

## 解放済みカードプールを無償配布にしなかった理由

無償配布にすると2人目以降が1人目より一方的に強くなり、CP 予算によるバランス管理と矛盾する。プールが広がることで「1人目が見つけた特殊なカードを2人目も選べるようになる」という、選択肢の幅の広がりとして体験させる。

- **保存方法を決めなかった理由** — [既読状態の保存単位](../notes/unlock.md#制作側の学習的アンロックを決めた理由)と同じ切り分け方。アカウントシステムの有無自体が別の未決事項のため、「プレイヤー単位のプールという概念が存在する」ところまでを範囲にし、実装方法はアカウントシステムの設計時に持ち越した
- **PC の生死と切り離した理由** — PC が引退・死亡しても、プレイヤーの成長実績が失われないようにするため
- **共有ライブラリ全体を選べなくした理由** — プレイヤー自身が実際に積んできた経験に基づいて選択肢が広がるようにするため

## CP 付与を2階建てにした理由

固定の基本 CP で「シナリオを終えればこれだけ成長する」という予測可能性を担保しつつ、GM の裁量による追加分で人間的な評価を反映できる。

## 称号タグを CP に直結させなかった理由

称号タグは[所有者が合意すれば誰でも反映できる](../cartagraph/comparison-and-titles.md#称号タグ)仕組みのため、機械的に CP へ直結させると「身内で称号を贈り合って CP を稼ぐ」インフレの温床になりやすい。
