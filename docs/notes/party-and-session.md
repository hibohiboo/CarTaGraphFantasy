# デザイナーノート：パーティー編成と非同期セッション参加

対応する仕様：[パーティー編成と非同期セッション参加](../cartagraph/party-and-session.md)

## 経緯

ドライバーとナビゲーターをはじめ、このページの参加モデルは grilling による深掘りで決めた。

濃密モードの中身（戦闘の具体的な判定・ダイスなど）は、この論点では範囲外として保留し、後から[戦闘ルール](../cartagraph/combat.md)・[探索者向けの判定ルール](../cartagraph/exploration-check.md)として決めた。

## ドライバーを1人にした理由

手軽に非同期で遊びたい、という動機による。戦闘でカードを逐次選択する駆け引き（[戦闘ルールのノート](combat.md#カウント制の考え方)）も、この決め方の理由の一つ。

## 所有者がフィードバックを決める理由

他人に貸した PC が望まない方向に変化することを防ぐため。

## GM が描写のたびに選択肢を配れるようにした経緯

はじめは「新しい提案が出たときだけ GM が選択肢を追加する」としていた。GM があらかじめ選択肢カードを用意しておけば、ドライバーはそれを選ぶだけで進められる、という前提だった。2026-10-03、GM が PL を兼ねて結末まで遊ぶ機能（`docs/plans/2026-10-03-GMがPLを兼ねて遊ぶ.md`）で、[場・手札・プレイ](../cartagraph/play-and-field.md#gmレスセッションでの選択肢の描写)の「人間GMのセッションでは、選択肢を選ぶとGMの描写を待つ」（GM が結果を描写し、次の選択肢を配る）流れと食い違うことがわかった。選択肢を用意していないシナリオでは、GM が描写のたびに配らないと先へ進めない。そこで、GM は描写のたびに配ってよい、提案が出たときはそれに応えて追加する、に改めた。

## 将来の拡張候補
