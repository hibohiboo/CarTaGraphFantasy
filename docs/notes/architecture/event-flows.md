# デザイナーノート：イベントの流れ

対応する定義：[イベントの流れ](../../architecture/event-flows.md)

## 決めた経緯

2026-10-17、『ドメイン駆動設計をはじめよう』の手順を続けて当てはめる中で、イベントストーミングを行った。2026-10-16 に決めた[集約とドメインイベント](aggregates.md)は机上で並べたものだったので、実装の設計（業務ロジックのパターン選び）に進む前に、コマンドからイベント・ポリシーまでを時間の順に通して、抜けを探すのが目的。

人間と付箋を貼る形ではなく、AI が仕様（`party-and-session.md`・`play-and-field.md`・`solo-village.md`・`auto-combat.md`・`graph.md`）と、いまのコード（`packages/domain/src/session/`・MSW のハンドラ）を突き合わせて叩き台を出し、仕様の判断が要る2点を人間が決めた。範囲は、backend-1on1 で保存の単位を決めるときに要るセッション運営とプレイに絞った。

## 見つけた抜けと、どう扱ったか

- **GM 不在でないセッションで、反映する結末が決まっていなかった** — 人間が「最後に入った結末」と決めた（[パーティー編成のノート](../party-and-session.md#反映する結末を最後に入った結末にした経緯)）。「結末に達した」をどのセッションでも残すことにした
- **破棄を誰がいつ行うかが無かった** — 人間の判断で[未解決論点](../../open-questions.md#仕様の細部の未決)に置いた。なかったことにする要望と同じく、要るまで作らない
- **「自動戦闘に敗れた」が無かった** — 「再挑戦の記憶」をキャラクターへ即時に足すのは、集約をまたぐ反映なのにイベントが無かった。足した
- **中断と再開がイベントに無かった** — 仕様にある任意の中断・再開を、セッション運営のイベントとして足した。あわせて、コードの権限が仕様と食い違っている（再開がドライバーだけ）ことを既知の問題にした
- **終了で承認待ちの提案を閉じることが、集約をまたぐ** — コードは1つの `Session` の中で閉じているが、セッション（運営）とスナップショット（プレイ）に分けると、またぐ反映になる。「セッションが終わった」の受け取る側に書いた
- **ソロ開始が、1回の操作でキャラクターとセッションを作る** — 「1回の変更で1つの集約」の方針から外れる。イベントの届け方を決めるときに扱う

## 集約とドメインイベントのページとの分け方

イベントの意味と受け取る側の振る舞いは[集約とドメインイベント](../../architecture/aggregates.md#ドメインイベント)を正とし、このページは順番とつながりだけを持つ。集約の中で完結するイベント（応募した・描写した など）は、集約をまたがないので集約のページには足さず、このページにだけ並べた。
