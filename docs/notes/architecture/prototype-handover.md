# デザイナーノート：閲覧サイト・セッション画面の試作

対応する仕様：[Webアプリの仕組み「デザインシステム」](../../architecture/web-app.md#デザインシステム)

## 試作の経緯・位置づけ

[技術スタック](../../architecture/index.md)で決めた「まず閲覧サイト→後にセッション管理システム」という段階分けのうち、閲覧サイト（用語集・グラフの閲覧体験）の試作から着手した。その後、本来は後続フェーズのはずのセッション管理系UI（プレイ画面・GM承認・戦闘画面など）も、デザイン探索として先行して試作することになり、全15画面まで広がった。**フェーズ分けの方針自体は変更していない**。試作は見た目・UI構造の検証であり、実装の着手順は技術スタックの方針に従う。

試作は静的HTML・CSSのみで、`docs/public/preview/` に置き、GitHub Pagesで公開していた。VitePressの`public/`にそのまま置いた生のHTMLなので、サイドバーのリンクに`target: '_self'`が必要だった（VitePressのSPAルーターに干渉されるため）。Reactアプリとして独立させれば発生しない。React 化した画面の試作は削除した。

## カードの縦横比を5:7にした理由

5:7（≒白銀比 1:1.4）。法隆寺五重塔などに使われる「大和比」と呼ばれる日本の伝統的な比率で、ポーカー/MTG等の実物トレーディングカード規格ともほぼ一致する。

## ナビ・HUDを横スクロールにした理由

試作で、ナビ・HUDが折り返してスマホ幅で縦方向の予算を圧迫し、表示が崩れる不具合が実際に発生した。そのため折り返さず横スクロールに統一した。`100dvh`+`overflow-y:auto`のフォールバックも、固定高さ内での折り返しによる崩れを防ぐため、実装でも踏襲している。
