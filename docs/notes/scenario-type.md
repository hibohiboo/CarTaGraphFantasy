# デザイナーノート：シナリオタイプ

対応する仕様：[シナリオタイプ](../cartagraph/scenario-type.md)

## 旅人・探索者・冒険者の区切りをやめた経緯

2026-10-10、ティザー（`docs/public/teaser/movie-v1.html`）を見て、旅人・探索者・冒険者という典型ロールの区切りが、要らない複雑さを生んでいると判断した。このページはそれまで、PC のロールとシナリオタイプの対応を扱う題（ファイル名 `role-and-scenario.md`）で、PC の持つデータから典型ロールを導いていた。

- **冒険者の能力値・スキルはキャラクター像を支える** — 戦闘のないセッションでも、能力値やスキルは、プレイヤーがキャラクター像を固める役目を持つ。旅人として何も持たずに始めると、その手がかりがない
- **シナリオの側の目印は残した** — 区切りをやめても、「戦闘がない」「判定がない」シナリオを選びたい場面は残る。PC の側の属性ではなく、シナリオの側の目印にした
- **「なし」を宣言する形にした理由** — どの PC も冒険者なので、判定も戦闘もありうる「冒険」を既定にし、使わない仕組みだけを書く。以前の「参照するデータ種別のタグ」（能力値・HP・戦闘スキルを参照する）は、何も参照しないシナリオが既定で、PC の段階に合わせた向きだった
- **デッキを絞らなくした理由** — 以前は、シナリオが参照しないカードをセッションスナップショットに含めなかった。キャラクターシート全体がキャラクター像を支えるという判断から、全部持ち込むことにした
- **宣言と中身の食い違いを止める理由** — 目印が嘘になると、選ぶときの判断材料にならない
- 変える前の地点には git のタグ `before-adventurer-only` を付けた。検討の経緯は `docs/plans/2026-10-10-冒険者だけにする.md`

## 以前の設計：ロールを属性にしなかった経緯

以下は、典型ロールがあった頃の経緯である（いまの仕様ではない）。

- grilling による深掘りで、ロールは PC が選ぶ属性ではなく、PC が持つデータの結果として決まるものにした。[段階的な開示・習熟によるアンロック](../cartagraph/unlock.md#プレイ参加側のゲーム内アンロック)で決めた「PL のキャラクターが対応するスキルカードを持っているかどうかで判定する」の具体化だった
- 「冒険者は探索者・旅人を兼ねる」という固定階層は設けなかった。例外的な PC が出てきたときに機構が壊れるため
- 「旅人として始めたキャラクターが、冒険を重ねて探索者・冒険者になっていく」成長を、進化するTRPGのプレイ経験として表現しようとした。この成長は、能力値を伸ばし戦闘スキルを習う成長として残っている（[GM不在のソロの進行](../cartagraph/solo-village.md)）
- 固定ラベルではなくタグの集合で宣言したのは、「かっちり固定せず、タグベースで柔軟に組み合わせる」という設計思想に合わせたため
