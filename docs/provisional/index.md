# 仮ルール

実装やプレイを先へ進めるために、決着を待たずに仮に置いたルールを、1仮ルール1ファイルで置く。残っている仮ルールは、[トップページのダッシュボード](/)が、ここのファイルからビルド時に一覧にする。

仮ルールは減らしていくもの。決めて正式なルールにしたら、ファイルを消す（経緯は git とデザイナーノートに残る）。

## 1ファイルの書き方

ファイルの先頭（frontmatter）に次を書き、本文に、何が仮なのか・どこで使っているか・経緯を書く。

```yaml
---
title: 自動戦闘
spec:               # 仮ルールを書いている仕様ページ（docs/ からのパス）。無ければ書かない
  - cartagraph/auto-combat.md
decide: プレイテストを経て、優先順位リスト・ラウンド上限などを正式なルールにするか
updated: 2026-10-10
---
```

- **未解決論点との役割分担** — まだ決まっていないことのうち、仮ルールで動かしているものはここに置き、[未解決論点](../open-questions.md)には書かない（二重に持たない）。仮のルールも無く、決めるまで実装もしないものは未解決論点に置く
- **仕様ページとの役割分担** — 仮ルールの中身（いまのルール）は仕様ページに書き、ページの題名か見出しに「（仮ルール）」などの印を付ける。ここには、何を決めれば消せるか（`decide`）と、どこで使っているかを書く
- **決めたら** — 仕様ページから「仮」の印を外し、決めた理由をデザイナーノートに書き、このファイルを消す
- **機械で止めること**（`pnpm docs:build` の `scripts/check-provisional.mjs`）
  - 仕様ページ（`docs/cartagraph/`）の題名・見出しに「仮ルール」「仮マッピング」などの「仮」の印があるのに、どの仮ルールのファイルの `spec` にも載っていない
  - 仮ルールのファイルの `spec` のページが無い、またはそのページにもう「仮」の印が無い（決めたのにファイルを消し忘れている）
