## 役割

[グラフの利用者とロール](cartagraph/graph.md#グラフの利用者とロール別の見え方)の4ロールで考える。

- **システム製作者** — ルールと基本のカードプールを作る
- **シナリオ製作者** — シナリオを作って公開する
- **GM** — シナリオからセッションを立てて進行する。PL の権限を含む
- **PL** — キャラクターでセッションに参加する（ドライバー／ナビゲーター）

「GM が PL を兼ねる」とは、GM が自分のキャラクターでドライバーも務めることをいう。

## マイルストーン

### M1

**{{ $frontmatter.milestones[0].title }}** — {{ $frontmatter.milestones[0].summary }}

バックエンドを作る前に、4つの役割の流れをローカル（MSW）で一通り確かめられる状態にする。

**完成の条件**

1. **システム製作者** — ルールと基本のカードプールを、JSON としてリポジトリで管理する。M1 では専用の画面は作らず、JSON を直してコミットする
2. **シナリオ製作者** — シナリオを作って公開できる。シナリオは JSON としてリポジトリ（`scenarios/`）で管理し、MSW 経由で取得する。ローカルの開発サーバーで公開すると、そのシナリオが JSON として保存され、遊べるシナリオになる（GitHub Pages のデモは保存せず、メモリ上だけで動く）
3. **GM** — 公開されたシナリオから募集を出し、自分のキャラクターで応募して、セッションを始められる（[シナリオの構造とセッション開始までの流れ](cartagraph/scenario-flow.md)の募集→応募→開始）
4. **GM が PL を兼ねる** — GM の画面とプレイの画面を行き来して、描写・選択肢を配る・提案の裁定・シーンを進める、ができ、結末まで遊べる
5. **GM 不在** — GM が公開されたシナリオを GM 不在のセッションとして募集し、PL がセッション一覧で絞り込んで始め、結末まで遊べる。村はずれの一歩も、シナリオの JSON から結末まで遊べる

### M2

**{{ $frontmatter.milestones[1].title }}** — {{ $frontmatter.milestones[1].summary }}

バックエンドを作る前に、MSW のまま画面の体験を磨く。バックエンドに載せてから画面を作り直すと手戻りが大きいので、画面の形をここで固めておく。画面ごとの課題は[画面ごとの課題](screens/issues.md)、画面のつながりは[画面一覧と導線](screens/index.md)。

**完成の条件**

1. **PL のホーム** — PL として入ったホームには、PL として参加しているセッションと自分の PC だけが出て、GM・シナリオ製作者の導線に邪魔されない
2. **GM のホーム** — GM として入ると、自分の募集・進行中のセッション・裁定待ちの提案がまとめて見え、そこから進行管理へ進める。シナリオのテストプレイ（GM が自分の PC でドライバーも務めて、1人で通して確かめる）を始められる
3. **依頼の掲示板** — 募集が冒険者の店の依頼書として並び、依頼書を開いて PC（借りる PC を含む）を選んで応募できる。前提を満たす依頼に絞り込める
4. **キャラクター** — PC の容姿・設定を書き、画像を設定でき、キャラクターシートから CP で成長させられる
5. **プレイ画面の没入** — セッションが始まると、ヘッダ・フッタや他の画面へのリンクが消え（GM の操作への切り替えはテストプレイ中だけ出す）、場・手札・パーティのカード・プレイマットで遊べる。戦闘の結果や案内が重ならずに読める
6. **ルールブック** — 目次から少しずつ読め、どこまで読んだかが分かる
