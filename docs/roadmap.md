# ロードマップ

プロダクトのゴールと、そこへ向かうマイルストーンの**定義**だけを置く。各マイルストーンの進み具合（どの要望が済んだか）はここに書かず、[要望（バックログ）](backlog/index.md)の各ファイルに書いた「どのマイルストーンか」と状態から、[トップページのダッシュボード](/)が計算して見せる。

## ゴール

{{ $frontmatter.goal }}（[コンセプト](concept/index.md)）

ゴールの一文と、各マイルストーンの名前・一文の説明は、このファイルの先頭（frontmatter）が正。ダッシュボードもそこから読む。

## マイルストーンの id と順番

- **id** — 中身を表す英語の短い名前（`local-flow` など）。一度決めたら変えない。要望ファイルの `milestone` と、このページの見出しは id で書く
- **順番（優先順位）** — frontmatter の `milestones` の並び順だけで表す。順番を入れ替える・間に差し込むときは、並びを変えるだけでよく、id は変えない。ダッシュボードは、未完了の要望が残る最初のマイルストーンを「いま取り組んでいる」とする
- 前後関係は番号で書かず、「前のマイルストーン」のように並びで言う

## 役割

[グラフの利用者とロール](cartagraph/graph.md#グラフの利用者とロール別の見え方)の4ロールで考える。

- **システム製作者** — ルールと基本カードプールを作る
- **シナリオ製作者** — シナリオを作って公開する
- **GM** — シナリオからセッションを立てて進行する。PL の権限を含む
- **PL** — キャラクターでセッションに参加する（ドライバー／ナビゲーター）

「GM が PL を兼ねる」とは、GM が自分のキャラクターでドライバーも務めることをいう。

## マイルストーン

### local-flow

**{{ ms('local-flow').title }}** — {{ ms('local-flow').summary }}

バックエンドを作る前に、4つの役割の流れをローカル（MSW）で一通り確かめられる状態にする。

**完成の条件**

1. **システム製作者** — ルールと基本カードプールを、JSON としてリポジトリで管理する。このマイルストーンでは専用の画面は作らず、JSON を直してコミットする
2. **シナリオ製作者** — シナリオを作って公開できる。シナリオは JSON としてリポジトリ（`scenarios/`）で管理し、MSW 経由で取得する。ローカルの開発サーバーで公開すると、そのシナリオが JSON として保存され、遊べるシナリオになる（GitHub Pages のデモは保存せず、メモリ上だけで動く）
3. **GM** — 公開されたシナリオから募集を出し、自分のキャラクターで応募して、セッションを始められる（[シナリオの構造とセッション開始までの流れ](cartagraph/scenario-flow.md)の募集→応募→開始）
4. **GM が PL を兼ねる** — GM の画面とプレイの画面を行き来して、描写・選択肢を配る・提案の裁定・シーンを進める、ができ、結末まで遊べる
5. **GM 不在** — GM が公開されたシナリオを GM 不在のセッションとして募集し、PL がセッション一覧で絞り込んで始め、結末まで遊べる。村はずれの一歩も、シナリオの JSON から結末まで遊べる

### adventurer-only

**{{ ms('adventurer-only').title }}** — {{ ms('adventurer-only').summary }}

ティザーを見て、旅人・探索者・冒険者の区切りが要らない複雑さを生んでいると分かった。戦闘のないセッションでも、冒険者の能力値やスキルは、プレイヤーがキャラクター像を固める役目を持つ。画面を磨く前に設計を変えておく。変える前の地点には git のタグ `before-adventurer-only` を付けてある。

**完成の条件**

1. **仕様** — 正式仕様・用語集・デザイナーノート・仮ルールから、旅人・探索者・冒険者の区切り（典型ロール）がなくなる。PC は作成したときから能力値（体・技・心）・HP・基本＜行動値＞を持ち、戦闘スキルは習って増やす
2. **シナリオ** — シナリオは参照するデータ種別のタグを持たず、どのシナリオにも PC のキャラクターシート全体を持ち込む
3. **キャラクター作成** — 作成したときに能力値・HP・基本＜行動値＞を持つ（値の決め方は仮ルール）
4. **村はずれの一歩・旅立ちの酒場** — 冒険者として始め、依頼で能力値を伸ばし、お店で戦闘スキルを習う。途中で HP・＜行動値＞を与える仕組みはなくなる
5. **画面** — 典型ロール（旅人／探索者／冒険者）の表示がなくなる

### ui-polish

**{{ ms('ui-polish').title }}** — {{ ms('ui-polish').summary }}

バックエンドを作る前に、MSW のまま画面の体験を磨く。バックエンドに載せてから画面を作り直すと手戻りが大きいので、画面の形をここで固めておく。画面ごとの課題は[画面ごとの課題](screens/issues.md)、画面のつながりは[画面一覧と導線](screens/index.md)。

**完成の条件**

1. **PL のホーム** — PL として入ったホームには、PL として参加しているセッションと自分の PC だけが出て、GM・シナリオ製作者の導線に邪魔されない
2. **GM のホーム** — GM として入ると、自分の募集・進行中のセッション・裁定待ちの提案がまとめて見え、そこから進行管理へ進める。シナリオのテストプレイ（GM が自分の PC でドライバーも務めて、1人で通して確かめる）を始められる
3. **依頼の掲示板** — 募集が冒険者の店の依頼書として並び、依頼書を開いて PC（借りる PC を含む）を選んで応募できる。前提を満たす依頼に絞り込める
4. **キャラクター** — PC の容姿・設定を書き、画像を設定でき、キャラクターシートから CP で成長させられる
5. **プレイ画面の没入** — セッションが始まると、ヘッダ・フッタや他の画面へのリンクが消え（GM の操作への切り替えはテストプレイ中だけ出す）、場・手札・パーティのカード・プレイマットで遊べる。戦闘の結果や案内が重ならずに読める
6. **ルールブック** — 目次から少しずつ読め、どこまで読んだかが分かる
