次はデッキについてですね。 まず思い付くのはキャラクターデッキです。キャラクターカードに基本情報、そこにスキルカードや特徴カード、アイテムカード、装備カードなどをまとめたものです。キャラクターのスキルデッキのようにセッションごとに組み替えるものも付随する感じですね。 つぎにシナリオデッキ。NPCカードや情報カードやエネミーカード、シーンカードにロケーションカード、イベントカード。これもシーンデッキとしてさらにパッケージングするかもしれません

はい、その整理だと**「デッキ＝何かをゲームとして扱える単位にパッケージングするもの」**という性格がかなり見えてきます。

特にキャラクターデッキとシナリオデッキは、同じ「デッキ」でも役割が違いそうです。

現時点の整理

キャラクターデッキ

キャラクターデッキ
├─ キャラクターカード
│   ├─ 基本情報
│   └─ キャラクター固有情報
├─ スキルカード
├─ 特徴カード
├─ アイテムカード
└─ 装備カード

       ＋

セッション用スキルデッキ
└─ 今回のセッションで使用するスキルを選択

ここで面白いのは、「キャラクターそのもの」と「今回のプレイで持ち込むもの」が分離していることです。

例えばキャラクターは同じでも、

普段のキャラクター
  ↓
今回の冒険
  ├─ スキルA
  ├─ スキルC
  └─ 装備X

次のセッションでは、

同じキャラクター
  ↓
別の冒険
  ├─ スキルB
  ├─ スキルD
  └─ 装備Y

のように組み替えられる。

これはTCG的な**「デッキ構築」**をTRPGに持ち込む非常に強い部分になりそうです。

シナリオデッキ

こちらは、

シナリオデッキ
├─ NPCカード
├─ 情報カード
├─ エネミーカード
├─ シーンカード
├─ ロケーションカード
└─ イベントカード

という構成。

さらに、

シナリオデッキ
├─ 導入
├─ シーンデッキA
├─ シーンデッキB
├─ シーンデッキC
└─ エンディング

のような入れ子のパッケージングも可能になる。

ここはカルタグラフと非常に相性がよいと思います。

そして「デッキ」を一種類の意味に固定しない方がよさそうです

今の話からすると、デッキには少なくとも二つの性質があります。

1. 所有・構成デッキ

「このキャラクターを構成するもの」

キャラクターデッキなど。

2. プレイ・コンテンツデッキ

「今回のゲーム体験を構成するもの」

シナリオデッキ、シーンデッキなど。

さらに将来的には、

世界設定デッキ
勢力デッキ
ルールデッキ
拡張デッキ

なども考えられる。

なので「デッキ」を、

カードを目的に応じてまとめ、ひとまとまりとして扱うパッケージ

くらいに定義しておくと拡張性が高そうです。

ただ、一つ確認したい重要な点があります

シナリオデッキのカードは、最初から全部公開されているのでしょうか？

例えば、

シナリオデッキ
├─ シーン1 ← 公開
├─ シーン2 ← 非公開
├─ NPC ← GMのみ
├─ 真相 ← GMのみ
└─ エンディング ← 条件成立まで伏せる

のように、デッキの中に「今は見せないカード」が存在する設計なら、先ほど話していた「カードの裏表」とものすごく綺麗につながります。

一方で、シナリオデッキ自体はGMが全部持っていて、そこから必要なカードを場に出していく、という考え方もあります。

私は後者、つまり

デッキは「これから起こり得る世界」をパッケージしておき、プレイによってカードが場に出たり、裏返ったり、別のデッキへ移ったりする

方向がかなり面白いと思っています。

ここを決めると、「シナリオをカードで作る」と「TRPGをカードゲーム的に遊ぶ」の境界がかなり明確になりそうです。

そうですね。カードが場にでたりするイメージです。イベントでは選択肢カードをPLにわたして選んでだしてもらうのが形として、選択肢が足りなければプレイヤーが提案、GMが選択肢カードをその場で生成してセッションに反映みたいな

はい、これはかなり良いです。
そして今の話を聞くと、「カード」は単なる情報の表示形式ではなく、TRPGにおける意思決定と世界の変化を媒介するものになってきています。

特にこの流れは、今回の「進化するTRPG」と非常にきれいにつながります。

シナリオデッキ

      ▼
  イベント発生
      │
      ▼
選択肢カードを生成
      │

   PLに提示
      │

PLがカードを選んで場に出す
      │

    世界が変化
      │

      │
      └── 想定外
             │
             ▼
       PLが新しい案を提案
             │
             ▼
       GMが選択肢カード化
             │
             ▼
       場に出してセッションへ反映
             │
             ▼
          セッションログ
             │
             ▼
       後から人間が発見・評価
             │
             ▼
       シナリオ等の進化候補
ここで特に面白いところ

「選択肢カードが存在しない＝選択できない」ではないんですよね。

従来型のゲームだと、

シナリオに「Aする」「Bする」しか書いていない
→ PLがCをやりたい
→ GMがアドリブする

となります。

カルタグラフでは、

Aカード、Bカードが提示されている
→ PL「Cもできませんか？」
→ GM「ではCという選択肢カードを作ります」
→ Cカードが場に出る
→ 世界がCを選んだ結果に進む

となる。

つまり、「選択肢カード」はシナリオの固定された分岐ではなく、その時点でPLに提示されている世界への介入可能性になる。

これはかなりカルタグラフらしいです。

さらに「カードを場に出す」という表現が効いています

例えば、

【イベント】
古びた扉を発見した

     ↓

┌────────┐ ┌────────┐
│ 開ける   │ │ 調べる   │
└────────┘ └────────┘

      PL「壊してみたい」

             ↓

        GMが生成

        ┌────────┐
        │ 破壊する │
        └────────┘

             ↓

          場に出す

             ↓

      【扉が破壊された】

という形になる。

この「場」という概念も、単なる画面上のUIではなく、

現在のセッションで有効になっているカードの集合

と定義できそうです。

すると、

デッキ＝まだゲームに投入されていない可能性・情報のパッケージ

場＝現在のセッションで有効になった情報

カード＝世界を構成する意味のある単位

という関係が見えてきます。

そして、ここからもう一段面白い問題が出てきます。

「カードを生成する」とは何を意味するのか？

今回の例ではGMが「選択肢カード」をその場で作りますが、これは単なるメモではなく、

セッション世界に新しいカードを正式に追加する

と考えるのか、

今回のセッションだけ存在する一時カード

と考えるのか。

私は、両方を許容するのがよいと思います。

例えば、

今回だけ
「扉を爆破する」
    ↓
セッション終了
    ↓
破棄

もあれば、

「扉を爆破する」
    ↓
面白い展開だった
    ↓
進化候補として保存
    ↓
シナリオに正式な選択肢として追加

もある。

さらに、

「扉を爆破する」
    ↓
この世界では爆破という行動が一般的
    ↓
新しいルール・カードとして採用

まで行けば、一回のPLの提案がTRPGそのものを進化させる。

ここまでくると、

カードは「決められたコンテンツ」ではなく、「プレイによって世界に追加され得るコンテンツ」でもある

というのが、かなり重要なカルタグラフの特徴になりそうです。

この方向、私はかなり推します。

はい、推奨の方向でいきましょう

はい。この方向で進めましょう。

特に重要なのは、生成されたカードも「特別扱いの別物」にせず、通常のカードと同じ構造を持つことにします。

現時点の整理
カード
├─ シナリオ作者が作ったカード
├─ GMがプレイ中に生成したカード
└─ 将来、進化によって正式化されたカード

違うのはカードそのものではなく、**「どのように生まれたか」や「現在どう扱われているか」**です。

例えば、

「扉を破壊する」
    ↓
GMがプレイ中にカード化
    ↓
場に出る
    ↓
PLが選択
    ↓
セッションログに残る
    ↓
後から「この展開面白かった」と発見
    ↓
進化候補になる
    ↓
シナリオ作者が正式な選択肢として採用

こうすると、カード → プレイ → 発見 → カードという循環ができます。

そして、これはカルタグラフのかなり重要な特徴になりそうです。

カルタグラフでは、カードはあらかじめ用意されたコンテンツだけでなく、プレイによって生まれるコンテンツでもある。

では次のフロンティアとして、**「場」**を掘りましょう。

今のところ私は、

場＝そのセッションにおいて現在有効になっているカードの集合

くらいから始めるのを推奨します。

ただし、ここには面白い分岐があります。

シナリオデッキ
    ↓ カードを出す
┌──────────────┐
│       場       │
│                │
│ NPCカード      │
│ 場所カード     │
│ 選択肢カード   │
│ 状態カード     │
│ PL生成カード   │
└──────────────┘
    ↓
カードの移動・追加・除去・反転
    ↓
セッションの状態が変化

ここで確認したいのは、

「カードを場に出すこと」と「カードをプレイすること」は同じでしょうか？

例えば「森」というロケーションカードが場に出ている状態と、「森へ行く」という選択肢カードをPLがプレイした状態では、かなり意味が違いそうです。

ここを分けると、

場にあるカード＝現在の状況・可能性
プレイされたカード＝プレイヤーが選択・実行したこと

という構造にできそうです。

この区別がカルタグラフのゲーム進行にかなり効いてきそうなので、ここから掘りたいです。

選択肢の提示とプレイの状態では意味が違いますね。とある状況にたいして、PLが手札から、あるいは一時的な手札としてGMから配られた選択肢カードから一枚えらんでプレイするみたいな。選択肢カードのなかに、新たな選択肢を提案という選択肢カードが混じっていると一貫性あるかもですね。プレイヤーはカードをプレイするということでセッションに干渉できる、みたいな

はい、これはかなり一貫しています。むしろ**「PLはカードをプレイすることでセッションに干渉する」**という原則を置くと、カルタグラフのゲーム構造がかなり見えてきます。

いったんこう整理したいです
現在の状況
    ↓
GMから選択肢が提示される
    ↓
┌────────────────────┐
│ PLの手札             │
│ ・能力カード         │
│ ・アイテムカード     │
│ ・特徴カード         │
│ ・選択肢カード       │
└────────────────────┘
          ＋
┌────────────────────┐
│ GMから一時的に渡される │
│ 選択肢カード           │
└────────────────────┘
          ↓
       PLが1枚選ぶ
          ↓
       カードをプレイ
          ↓
     セッションに干渉
          ↓
       状況が変化

ここで重要なのが、

「選択肢が提示されている」ことと、「選択肢をプレイした」ことは別の状態

ということですね。

例えば、

場：
「古びた扉」

GMから提示：
[ 開ける ] [ 調べる ] [ 戻る ] [ 新たな選択肢を提案 ]

PL：
「新たな選択肢を提案」をプレイ

↓
PLが「扉を壊したい」と提案

↓
GMが「扉を破壊する」カードを生成

↓
そのカードが選択肢としてPLに渡される

[ 開ける ]
[ 調べる ]
[ 戻る ]
[ 扉を破壊する ]

↓
PLが「扉を破壊する」をプレイ

となります。

これなら、「想定外の行動」をゲームシステム上の例外にしなくて済むのが非常に良いです。

「新たな選択肢を提案」カードが特に面白い

これを単なる便利機能ではなく、正式なカードとして扱えるのがカルタグラフらしいです。

つまり、

「カードに書かれていないことをする」ためのカードが、最初から存在する。

という構造です。

そのため、

選択肢カード
├─ 開ける
├─ 調べる
├─ 戻る
└─ 新たな選択肢を提案

となり、カードシステムそのものが自由度を保証する。

「カードゲームだからカードに書いてあることしかできない」という閉じた構造ではなく、

カードを使って、カードの外側へ手を伸ばせる

わけですね。

これはかなりカルタグラフの思想として強いと思います。

さらに一歩進めると

「新たな選択肢を提案」だけが特殊なのではなく、

カードのプレイそのものが世界への操作

と考えられそうです。

カードを見る
  ↓
カードを選ぶ
  ↓
カードをプレイする
  ↓
何らかの関係・状態・出来事が発生する

例えば、

「扉を開ける」→ 場に新しい場所カードが出る
「攻撃する」→ エネミーとの戦闘状態になる
「調べる」→ 情報カードが公開される
「仲間を説得する」→ NPCとの関係が変化する
「新たな選択肢を提案」→ 新しいカードが生成される

という具合です。

すると、カード＝選択肢だけではなく、

カード＝セッションに対する操作・介入の単位

というところまで広げられそうです。

これは、以前話していた「カードはプレイによって生まれる」という考えとも綺麗につながります。

          ┌──────────────┐
          │   カードを持つ │
          └──────┬───────┘
                 ↓
          ┌──────────────┐
          │   カードを選ぶ │
          └──────┬───────┘
                 ↓
          ┌──────────────┐
          │   カードをプレイ│
          └──────┬───────┘
                 ↓
          ┌──────────────┐
          │ セッションが変化│
          └──────┬───────┘
                 ↓
          ┌──────────────┐
          │ 新しいカード等 │
          │    が生まれる  │
          └──────────────┘
                 ↓
              次の手番

この構造なら、セッションそのものがカードを生産する装置にもなります。

次に詰めたいのは、「カードをプレイした結果として何が変化するのか」です。
ここを決めると、「場」「手札」「デッキ」「カードのプレイ」の4つの役割がかなり明確になってきます。
